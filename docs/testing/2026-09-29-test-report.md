## Подтверждённые ошибки

Скриншоты и сырые результаты лежат локально в `data/qa-2026-09-29/` (в git не входят).

### 1. «Целевые задачи»: колонка «Идея» схлопывается — высокая

- **Шаги:** шапка — любая команда с задачами (например, «Команда 1С (Бухгалтерия)»), 2026, Q4; открыть «Целевые задачи» (`/backlog`), вкладка «Активные» или «Бэклог».
- **Ожидалось:** названия идей — обычный текст в строку.
- **Получилось:** заголовок «ИДЕЯ» и названия разбиты по одной букве в столбик, строки аномально высокие, список нечитаем. Воспроизводится на двух командах, в обеих темах, после ожидания и изменения размера окна. Ширина заголовка — 0 px: сумма ширин остальных колонок (1730 px) больше ширины таблицы (1290 px).
- **Причина (по коду):** у колонки «Идея» не задана ширина, у всех соседних — задана (`frontend/src/pages/BacklogPage.tsx`, колонка `title`).
- **Скриншоты:** `bugs/backlog-idea-column-full.png`, `bugs/backlog-idea-column-buh.png`.

### 2. Ресурсный план: нет пометки «работа на соседнюю группу» у задачи через дату перевода — средняя

- **Шаги:** Бухгалтерия, план Q4 2026 после «Распределить». Андрею Демидову (задача RFA-83 «Разработка», 02.10–13.11) записать перевод из «Команда Бухгалтерия» в «Команда РФМ» с даты внутри задачи (проверено с 01.11 и с 20.10) → «Распределить».
- **Ожидалось:** часть полоски после даты перевода — с пунктирной фиолетовой рамкой и подсказкой «работа на соседнюю группу»; новых конфликтов нет.
- **Получилось:** конфликтов нет (верно), но полоска целиком обычная, `other_subgroup = false`. Пометка появляется только у задач, которые целиком начинаются после даты перевода.
- **Причина (по коду):** признак считается на всё назначение сразу: группа работы сравнивается с объединением всех групп сотрудника за даты назначения (`_other_subgroup_ids` в `app/api/endpoints/resource_planning.py`, `groups_between` в `app/services/subgroup_shares.py`). Если назначение захватывает хоть день до перевода, старая группа попадает в объединение, и пометки нет нигде.
- **Независимо воспроизведено** в двух прогонах двумя тестировщиками; первый перепроверяющий подтвердил. Второй перепроверяющий вынес «ложную тревогу» ошибочно: к моменту его проверки в том же треке перевели главного исполнителя задачи (Епишину, T03-07), у задачи сменилась группа на «Команда Ломбарда», и пометка появилась по другой причине (проверено координатором через API стенда).
- **Скриншоты:** `bugs/other-subgroup-after-transfer.png`, `bugs/other-subgroup-row-crop.png`, `bugs/other-subgroup-gantt-after.json`.

### 3. Вовлечённость 0% молча сохраняется как 1% — средняя

- **Шаги:** ERP ТУ, Q4 2026, «Сценарии» → «Вовлечённость» → «Сотрудники» → «Добавить»; любой сотрудник, 2026, Q4, «Вовлечённость, %» = 0; увести фокус; «Добавить».
- **Ожидалось:** 0% не сохраняется — ошибка или подсказка (по замыслу 0% запрещён, иначе фазы не размещаются).
- **Получилось:** поле без предупреждения меняет 0 на 1, кнопка активна, запись сохраняется с 1% (в API `involvement = 0.01`). Пользователь получает почти недоступного сотрудника вместо отказа.
- **Скриншоты:** `bugs/involvement-0-typed.png`, `bugs/involvement-0-becomes-1.png`, `bugs/involvement-saved-1pct.png`.

### 4. «Справка» недоступна на двух страницах — низкая

- **Шаги:** открыть `/feedback`; открыть `/projects` без выбранного проекта.
- **Ожидалось:** «Справка» открывается на каждой странице (T12-02).
- **Получилось:** значок «?» неактивен, подсказка «Для этого раздела справки пока нет». На «Обратной связи» справка не заведена; на «Проектах» есть только в карточке проекта. На «Отчёте по видам работ» справка тоже неактивна, но только при выключенном ИИ — это настройка стенда, не ошибка.
- **Скриншоты:** `bugs/help-missing-feedback.png`, `bugs/help-missing-projects.png`.

## Наблюдения (не ошибки по плану — на обсуждение)

1. **Группы на диаграмме ресурсного плана** появляются только при включённом «Вид → Разбить по группам» (по умолчанию выключено, только в виде «Задачи»). «Загрузка по дням» делится на группы всегда. Первый тестировщик принял выключенный переключатель за отсутствие секций.
2. **Сотрудник в двух командах** на «Ресурсах» помечен тегами обеих команд (звёздочка у основной); слова «общий» нет — оно используется только для деления между группами внутри команды. По смыслу требование T08-06 выполнено.
3. **«Ресурсы», будущий квартал:** после перевода с будущей датой плашка «Без группы» за Q1 2027 сотрудника уже не учитывает, а в его строке колонка «Группа» по-прежнему показывает пустой список: строка показывает группу на сегодня. Может путать. Не перепроверялось.
4. **«Обновить только видимые» на стенде без доступа к Jira** показал «Данные обновлены из Jira» (случайное нажатие тестировщика T03). Запроса в Jira не было и быть не могло: пароля к Jira на стенде нет, и сервис без него к Jira не обращается. Сообщение об успехе в такой ситуации вводит в заблуждение. Не перепроверялось.
5. **«Свои проценты» нормированных работ** при включении заполняются процентами роли, а не пустыми. Чтобы снять сотрудника с нормированных работ, поля нужно стирать вручную. Из-за этого первый прогон T05-04 дал ложную тревогу.
6. **Неактивные сотрудники** не требуют группы (плашка, запрет утверждения, расчёты их не учитывают) — задумано. План тестирования исходил из обратного; данные плана для T01/T02/T03 стоит обновить.

## Серверные ошибки

- Ответов 500 и трейсбэков приложения в логах 18 стендов за всё время теста нет; раздел «Ошибки сервиса» пуст.
- Ожидаемые на стенде без Jira: `502` на `GET /api/v1/sync/jira-teams` (фоновый запрос шапки), `/sync/jira-fields` («Поля Jira»), `/sync/jira-issuetypes` («Правила иерархии») — интерфейс не ломается.
- `404` на `GET /api/v1/executive/dashboard` при первом входе на `/executive` — дайджест ещё не построен, показывается заглушка.
- `ConnectionResetError [WinError 10054]` в логах — обрыв соединения браузером при закрытии скрипта (Windows), без влияния на данные.
- Синхронизаций с Jira на стендах не было ни одной (проверено по истории запусков всех 18 копий базы).
