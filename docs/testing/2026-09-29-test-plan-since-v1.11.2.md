## 0. Правила для всех

- **Код не править.** Нашли ошибку — зафиксировать в отчёте (шаги, ожидалось, получилось, скриншот). Исправления — отдельно, после отчёта.
- **Не трогать** основной стенд (`http://localhost:8000`, `D:\ClaudeDev\JiraAnalysis\data\jira_analytics.db`) и рабочую копию `D:\ClaudeDev\JiraAnalysis`.
- **Не запускать синхронизацию с Jira** (кнопки на странице «Синхронизация» не нажимать). Стенды отвязаны от Jira, но всё равно.
- **Каждый трек — на своём стенде** (своя копия базы + свой порт). Треки меняют данные (утверждают сценарии, переводят людей, жмут «Распределить») — поэтому стенды не делятся.
- Вход: `kopyshkov_n_o@itgri.ru` / `admin123` (администратор).
- «Сегодня» в данных — 29.09.2026 (фактическая дата запуска может быть позже — учитывать при датах «с …»).
- Нет данных для проверки → статус `BLOCKED` с причиной. Ничего не выдумывать.
- Надписи в плане могут расходиться с экраном в мелочах (падеж, кавычки) — судить по смыслу; `FAIL` — только когда поведение не то.

## 2. Инструкция тестировщику (вставляется в промпт каждого субагента)

- Стенд: `http://127.0.0.1:81NN` (интерфейс и API на одном адресе, API — `/api/v1/...`). Рабочая папка артефактов своя.
- Инструмент: Python Playwright (sync), headless chromium, `viewport 1600×1000`, `locale ru-RU`. Скрипты — в свою папку, запуск `py -3.10 script.py`. Не использовать MCP-браузер (он один на всех).
- Шаблон:

```python
from playwright.sync_api import sync_playwright
BASE = "http://127.0.0.1:8101"
with sync_playwright() as p:
    b = p.chromium.launch()
    ctx = b.new_context(viewport={"width": 1600, "height": 1000}, locale="ru-RU")
    r = ctx.request.post(f"{BASE}/api/v1/auth/login",
                         data={"email": "kopyshkov_n_o@itgri.ru", "password": "admin123"})
    assert r.ok, r.status
    page = ctx.new_page()
    errors = []
    page.on("response", lambda resp: errors.append((resp.status, resp.url)) if resp.status >= 500 else None)
    page.on("console", lambda m: errors.append(("console", m.text)) if m.type == "error" else None)
    page.goto(f"{BASE}/capacity"); page.wait_for_timeout(2500)  # не networkidle — см. ниже
    page.screenshot(path=r"...\T01\01-capacity.png")
    data = ctx.request.get(f"{BASE}/api/v1/teams/ungrouped?year=2026&quarter=4").json()
    b.close()
```

- **Не ждать `networkidle`**: страницы держат живое соединение с сервером (обновления в реальном времени), «сеть без запросов» не наступает, и ожидание виснет до таймаута. Ждать нужный элемент (`locator.wait_for()`, `expect(...)`) или короткую паузу после перехода.
- При первом входе может всплыть окно «Что нового» — закрыть кнопкой «Понятно», иначе оно перекрывает кнопки.
- Команда/год/квартал выбираются в шапке (глобальный фильтр). Выбор хранится у пользователя в базе стенда — на другие стенды не влияет.
- Цифры сверять через API того же контекста (`ctx.request.get(...)`) — см. шпаргалку ниже.
- Каждый случай: выполнить шаги, сделать скриншот ключевого состояния, зафиксировать 5xx/ошибки консоли.
- Отчёт — **ровно JSON** (последним сообщением):

```json
{"track": "T01", "stand": "http://127.0.0.1:8101",
 "results": [
   {"id": "T01-03", "status": "PASS|FAIL|BLOCKED",
    "evidence": "что видно / какие цифры",
    "screenshot": "путь",
    "expected": "только для FAIL", "actual": "только для FAIL",
    "steps": "только для FAIL — как воспроизвести"}],
 "server_errors": ["5xx и ошибки консоли, если были"],
 "notes": "что осталось непроверенным и почему"}
```

## 4. Проверка находок и отчёт (координатор)

1. Каждый `FAIL` перепроверяет отдельный агент (**sonnet**) на том же стенде: воспроизводит по шагам из отчёта. Итог: «подтверждено» / «ложная тревога» (с причиной: ошибка теста, данные, ожидание неверно).

3. Пользователю — коротко, языком аналитика: сколько проверено, что сломано, что не удалось проверить.
