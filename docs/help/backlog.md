# Целевые задачи (бэклог инициатив)

Раздел «Целевые задачи» (меню «Планирование») — задачи квартального плана, реестр инициатив-кандидатов на следующий квартал и архив прошлых периодов. Это **единственный источник** задач для квартального планирования: всё, чего нет в этом разделе, в сценарий не попадёт.

---

## 1. Зачем раздел

Между разбором задач и планированием сценариев нужен «склад» инициатив. Раздел собирает кандидатов на квартал в одном месте: задачи из Jira попадают сюда сами — по категории, которую им дали в «Категориях задач»; идеи, которых в Jira ещё нет, PM заводит вручную кнопкой «Идея вручную». Здесь PM сравнивает инициативы между собой, проставляет приоритеты, оценки ручных идей, разработчика и параметры планирования, решает, что идёт в план, а что — в архив.

Дальше эти данные подхватывают сценарии и ресурсное планирование: оценки, приоритеты, исполнители и параметры (длительность, параллельность) уже посчитаны здесь. В сценарии PM решает только «брать / не брать».

## 2. Когда сюда заходить

- В начале квартального планирования — собрать список инициатив и проставить приоритеты.
- После синхронизации с Jira — посмотреть, какие новые инициативы пришли из категории «Инициативы (на потом)».
- После разбора задач в «Категориях задач» — убедиться, что они отразились здесь.
- Когда нужно сравнить объём инициатив (часы по ролям, доля от общего объёма).
- Когда оценки в полях Jira расходятся — выбрать верное значение (метка «спорно»).
- Когда нужно отправить инициативу в архив или вернуть её обратно.
- Когда в сценарии пропала инициатива — проверить, не ушла ли она в архив и не выключен ли у неё «В план».

## 3. Элементы интерфейса

В шапке — заголовок «Целевые задачи» с подписью «Активные задачи текущего квартала и бэклог инициатив» и кнопки:

- **«Обновить с Jira»** — перечитать из Jira все задачи раздела (кроме архивных): плановые часы, влияние и риск, цели, команду, исполнителя, заказчика, тип затрат — без полной синхронизации. Пока идёт обновление, вместо кнопок — кружок «Jira: N/M» и кнопка «Прервать».
- **«Обновить только видимые»** — то же, но только по задачам открытой вкладки (вместе с дочерними), чтобы не ждать обхода всего списка ради десятка строк.
- Если подключение к Jira не настроено, обе кнопки обновляют только данные самого сервиса и предупреждают: «Jira не подключена — обновлены только данные сервиса».
- **«Идея вручную»** — добавить идею-черновик без привязки к Jira (см. 3.5).

Три вкладки:

| Вкладка | Что лежит |
|---------|-----------|
| **Активные** | Задачи квартального плана — с категорией «Квартальные задачи». Инициатива переезжает сюда сама, когда её утверждают в сценарии; сюда же попадают задачи, отнесённые к этой категории при разборе. Выполненные остаются здесь, отменённые уходят в архив. Приоритет и часы здесь не редактируются. |
| **Бэклог** | Кандидаты: задачи категории «Инициативы (на потом)» и ручные идеи, ещё не взятые в утверждённый сценарий. Здесь идёт основная работа PM: приоритеты, оценки, параметры. Открывается по умолчанию вкладка «Активные». |
| **Архив** | Инициативы, отправленные в архив вручную, отменённые в Jira и выполненные. Можно вернуть, если задача в Jira не закрыта и не отменена. |

Цифра в скобках — число строк верхнего уровня на вкладке с учётом фильтра команды и группы в шапке.

Справа от вкладок (кроме «Архива») — **метки-фильтры**. Они появляются, только когда есть такие задачи:

- **«Только спорные · N»** — оставить задачи, у которых оценки в полях Jira расходятся.
- **«Не в плане · N»** — оставить задачи, выключенные из плана переключателем «В план».

Вместе метки оставляют задачи, подходящие под обе.

### 3.1. Вкладка «Бэклог» (основная)

Главная рабочая поверхность. Инициативы упорядочены по приоритету (число в первой колонке), задачи без приоритета — в конце. Перетаскивание строк отключено, приоритет меняется только вводом числа.

Дочерние эпики показываются прямо под строкой родителя с отступом и префиксом `└─`. По умолчанию все родители раскрыты; стрелка слева от строки сворачивает и разворачивает. Дочерний эпик показывает свой Jira-ключ и наследует проект от родителя.

| Колонка | Что показывает |
|---------|----------------|
| **Prio** | Приоритет. Целое число, чем меньше — тем выше. Сохраняется, когда уходите из поля. У задачи из Jira при первом появлении берётся из приоритета Jira, дальше меняется только здесь. |
| **Идея** | Название. Под ним — Jira-ключ (ссылка открывает задачу в Jira) и метки: «Дискавери» (служебный эпик внутри RFA), «мультикоманда» (над задачей работают несколько команд, в подсказке — какие), «спорно» (оценки в Jira расходятся). Если родитель задачи в список не попал (чужая команда, архив), под названием подписано «в составе КЛЮЧ · команда». |
| **Аналитик** | Для ручных идей — выпадающий список активных сотрудников. Для задач из Jira — исполнитель задачи в Jira (здесь только просмотр). |
| **Разработчик** | Выпадающий список активных сотрудников — в любой строке. То же значение, что в колонке «Разработчик» сценариев: этот человек ведёт фазу разработки. Один человек не может быть и аналитиком, и разработчиком одной задачи — такой вариант в списке неактивен с пометкой «— уже аналитик этой задачи» (и наоборот). |
| **Заказчик** | Для ручных идей — текстовое поле «Заказчик…». Для задач из Jira — значение из Jira, обновляется кнопками «Обновить с Jira» / «Обновить только видимые». |
| **Группа** | Только если выбранные в шапке команды (или, без выбора, любая команда) делятся на группы — см. раздел 9. |
| **Статус** | Статус задачи в Jira и «N д назад» — сколько дней назад он менялся (точная дата — в подсказке). От 180 дней — жёлтым, от 365 — красным: сигнал «зависшая инициатива». По колонке можно сортировать. |
| **АН / ПР / ТС / ОПЭ** | Оценка часов по ролям: Анализ / Разработка / Тестирование / Опытно-промышленная эксплуатация. В ячейке — часы и доля роли в оценке задачи. В подсказке — длительность фазы в днях и занятость, если заданы. У ручных идей клик по ячейке открывает поле ввода часов. У задач из Jira часы берутся из Jira, а поправить их можно в шестерёнке кнопкой «✎ Редактировать план». Ячейка с оранжевой пунктирной обводкой и знаком «?» — спорная оценка: клик открывает выбор (см. раздел 7). |
| **ОПЭ→АН** | Какая доля часов ОПЭ идёт на аналитика (остальное — на разработку). По умолчанию 0.5. |
| **Всего часов** | Сумма по ролям и подпись «X% ресурса» — доля задачи в сумме часов всех задач вкладки «Бэклог» (а не в ресурсе команды). Помогает оценить «вес» инициативы. |
| **Проект** | Ключ проекта Jira, в подсказке — название. |
| **В план** | Переключатель: идёт ли задача в сценарии (см. «Галочка «В план»»). Выключенная строка приглушена. |
| **Действия** | См. 3.4. |

**Отсечка ОПЭ.** Если в «Настройки → Планирование» задан квартал «ОПЭ не планируем начиная с квартала», а в шапке выбран этот квартал или более поздний, колонки ОПЭ и «ОПЭ→АН» пропадают, а часы ОПЭ показываются внутри АН и ПР по доле «ОПЭ→АН». Если в этом режиме поправить часы ручной идеи, её ОПЭ окончательно переносится в АН и ПР. Фаза ОПЭ пропадает и из окна «Новая идея», и из шестерёнки.

### 3.2. Вкладка «Активные»

Те же колонки, кроме «Проекта», но приоритет, часы и «ОПЭ→АН» не редактируются. Добавлены:

- **Цели** — цели задачи из Jira, тегами.
- **Сценарий** — утверждённые сценарии, в которые задача включена.

Редактировать можно разработчика, группу и «В план». В колонке «Действия» — только шестерёнка «Параметры планирования».

Кнопка **«Группировать по кварталам»** раскладывает задачи по вкладкам кварталов (квартал утверждённого сценария, где задача включена; «Без квартала» — если такого нет).

### 3.3. Вкладка «Архив»

Те же колонки + **Квартал** — квартал утверждённого сценария, в котором задача была в плане («3 кв. 2026»); «—», если она ни разу не планировалась. Сортировка по умолчанию — последний квартал сверху. Без группировки список листается страницами по 50 строк.

Кнопка **«Группировать по кварталам»** показывает архив отдельными секциями по кварталам. Выбор группировки на «Активных» и в «Архиве» запоминается в этом браузере.

### 3.4. Кнопки в строке (колонка «Действия»)

Вкладка «Бэклог» (название кнопки — во всплывающей подсказке):

- **Стрелка «Открыть страницу проекта»** — у задач из Jira: открывает карточку этой задачи в разделе «Проекты».
- **Скрепка «Связать с Jira»** — у ручных идей: привязать к существующей задаче (см. 3.6).
- **«Отвязать от Jira»** — у задач из Jira: «Отвязать от Jira? Идея останется в бэклоге, но потеряет связь с задачей.» Оценки остаются. Если задача в Jira по-прежнему относится к «Инициативам (на потом)», при ближайшей синхронизации для неё появится отдельная строка.
- **Карандаш «Редактировать»** — у ручных идей: окно «Редактирование идеи» (см. 3.5).
- **Шестерёнка «Параметры планирования»** — длительность, параллельность, часы и режим планирования. Подробнее в 3.7.
- **Ящик «Архивировать»** — «Убрать из активного бэклога? Инициатива попадёт в раздел «Архив». Связь с Jira сохраняется.» Задача сразу уходит из всех черновых сценариев.
- **Корзина** — удалить совсем: «Удалить идею? Элемент будет убран из всех черновиков сценариев.» После удаления уведомление перечислит сценарии, из которых задача убрана.

Вкладка «Архив»:

- **Стрелка-возврат «Восстановить»** — «Вернуть в активный бэклог?». Неактивна у задач, закрытых или отменённых в Jira (подсказка «Задача закрыта или отменена в Jira — вернуть её в бэклог нельзя»).
- **Карандаш** — у ручных идей.
- **Шестерёнка** — параметры планирования.
- **Корзина** — удалить совсем.

Вкладка «Активные» — только шестерёнка.

### 3.5. Окно «Новая идея» / «Редактирование идеи»

Открывается кнопкой «Идея вручную» или карандашом у ручной идеи:

- **«Название»** — обязательно.
- **«Проект»** — проект Jira, к которому относится идея.
- **«Команда»** — у кого в списке появится идея. По умолчанию — первая команда из фильтра в шапке. Без команды идея видна всем.
- **«Оценка по ролям (часы)»** — «АН ч», «ПР ч», «ТС ч», «ОПЭ ч».
- **«Доля ОПЭ на аналитика (0…1)»** — то же, что колонка «ОПЭ→АН».
- **«Параллельность (чел. по ролям)»** — АН / ПР / ТС, от 1 до 5: сколько человек работают на фазе одновременно — сокращает календарный срок. Пусто — берётся из настроек проекта (по умолчанию 1).
- **«Приоритизация»** — «Приоритет», «Impact» и «Risk» (Низкий / Средний / Высокий).

Заказчик и аналитик ручной идеи задаются прямо в таблице.

### 3.6. Окно «Связать идею с Jira-задачей»

Поле **«Jira key»** — ключ задачи в формате «RFA-123». Предупреждение в окне: «Локальные оценки часов, impact и risk будут заменены значениями из Jira». Название и проект тоже берутся из задачи; приоритет и «ОПЭ→АН» остаются.

- Задача должна уже быть загружена в сервис синхронизацией — иначе сервис откажет.
- Если у задачи уже есть своя строка в разделе (её уже отнесли к «Инициативам (на потом)» или «Квартальным задачам»), связать идею не получится — сервис ответит, что задача уже связана. Тогда удалите ручную идею и работайте со строкой задачи.
- После связки отнесите задачу к «Инициативам (на потом)» в «Категориях задач», если это ещё не сделано: иначе при ближайшем «Обновить с Jira» строка уйдёт в архив.

### 3.7. Параметры планирования (шестерёнка)

Окно «Параметры планирования — КЛЮЧ Название».

Сверху — переключатель **«В план»** с пояснением, что он значит для этой задачи (см. «Галочка «В план»»).

Дальше — фазы «Анализ», «Разработка», «Тестирование (QA)» и «ОПЭ». Для каждой задаётся:

- **«Длительность (дней)»** — сколько рабочих дней занимает фаза.
- **«Параллельность»** (кроме ОПЭ) — сколько человек работают на фазе одновременно, от 1 до 5. Больше людей — короче фаза.

Возле длительности — метка источника: бирюзовая **«Jira»** — значение совпадает с полем Jira; жёлтая **«вручную»** — значение задано здесь. Кнопка **«К Jira»** возвращает значение из Jira. Пустое поле показывает значение Jira серой подсказкой.

Как пишет само окно: ручное значение надёжно держится, только пока соответствующее поле в Jira пустое. Если в Jira поле заполнено, при ближайшем обновлении из Jira (кнопки «Обновить с Jira», синхронизация) значение Jira вернётся. Чтобы значение держалось, правьте его в Jira.

«Сохранить» — «Параметры сохранены». Для задач из Jira ниже есть блок **«Часы и иерархия»** — см. следующий раздел.

## 4. Откуда цифры

- **Задачи из Jira** — приходят сами, как только задача получила в «Категориях задач» категорию «Инициативы (на потом)» (вкладка «Бэклог») или «Квартальные задачи» (вкладка «Активные»). Сменили категорию на другую — задача уходит в архив.
- **Ручные идеи** — кнопка «Идея вручную» (черновик без привязки). Потом можно привязать к задаче Jira через «Связать с Jira».
- **Оценки часов** — из полей Jira, указанных в «Настройки → Поля Jira → Плановые трудозатраты»; поправить — «✎ Редактировать план» в шестерёнке.
- **Длительность фаз** — из полей Jira; можно задать вручную в шестерёнке (с оговоркой из 3.7). Вовлечённость из Jira не берётся — она фиксируется в карточке фазы ресурсного плана.
- **Фильтр команды** — общий, из шапки приложения. Задачи из Jira отбираются по команде задачи, ручные идеи — по полю «Команда» идеи; идеи без команды видны всегда.
- **Архивирование** — задача сразу уходит из всех черновых сценариев. Если она числится в утверждённом сценарии, архивировать её нельзя.
- **Возврат из архива** — задача снова в «Бэклоге» и снова появляется кандидатом (неотмеченной) в черновых сценариях своей команды. Отметить её в сценарии нужно самим.
- **Утверждение сценария** — отмеченные в нём инициативы получают категорию «Квартальные задачи» и переезжают на вкладку «Активные»; при возврате сценария в черновик — возвращаются в «Бэклог».

## 5. Типовые задачи

### Сценарий А: провести квартальный отбор

1. «Целевые задачи» → вкладка «Бэклог».
2. Убедиться, что в шапке стоит твоя команда и нужный квартал.
3. Если есть метка «Только спорные» — сначала разобрать спорные оценки.
4. Пройтись сверху вниз: проставить приоритеты вводом числа в колонке «Prio».
5. Проставить разработчика там, где он уже известен.
6. Для инициатив открыть шестерёнку и проверить длительность и параллельность по фазам.
7. Прикинуть «Всего часов» и долю в процентах — что укладывается в ресурс, что нет.
8. Заведомо непроходные — выключить «В план» или отправить в архив (ящик).
9. Перейти в «Сценарии» — там выбрать инициативы для сценария.

### Сценарий Б: отправить инициативу в архив

1. Найти инициативу на вкладке «Бэклог».
2. В колонке «Действия» — кнопка-ящик «Архивировать».
3. Подтвердить. Инициатива переезжает в «Архив» и убирается из всех черновых сценариев. Связь с Jira сохраняется.
4. У задачи из Jira, пока у неё стоит категория «Инициативы (на потом)», архив временный: при ближайшем обновлении из Jira или синхронизации она вернётся. Чтобы убрать надолго — смените ей категорию в «Категориях задач».

### Сценарий В: вернуть инициативу из архива

1. Открыть вкладку «Архив».
2. Найти инициативу (можно сгруппировать по кварталам).
3. Кнопка «Восстановить» — подтвердить.
4. Инициатива возвращается в «Бэклог» с прежним приоритетом и появляется кандидатом в черновых сценариях своей команды — отметить её в сценарии нужно в «Сценариях».

### Сценарий Г: завести идею до появления задачи в Jira

1. Кнопка «Идея вручную» в шапке.
2. Заполнить название, команду, оценки по ролям, при желании — параллельность и приоритет. Нажать «OK».
3. В строке идеи проставить аналитика, разработчика и заказчика.
4. Когда в Jira появится задача и пройдёт синхронизация — в строке идеи кнопка «Связать с Jira», ввести ключ задачи (до того, как задачу отнесут к «Инициативам (на потом)», — см. 3.6).
5. После связки название, исполнитель, статус и оценки часов берутся из Jira. Отнести задачу к «Инициативам (на потом)» в «Категориях задач».

### Сценарий Д: поправить плановые часы задачи из Jira

1. Шестерёнка у задачи → блок «Часы и иерархия» → «✎ Редактировать план».
2. В колонке «Правка» ввести часы по ролям, обязательно написать «Комментарий».
3. «Сохранить» — новые часы сразу видны в строке, в сценариях и ресурсном планировании.

### Сценарий Е: разобрать спорные оценки

1. Нажать метку «Только спорные · N» справа от вкладок.
2. У задачи нажать метку «спорно» (или ячейку роли с пунктирной обводкой).
3. Выбрать одно из полей Jira или «Ввести своё» — «Принять N ч».
4. Повторить для остальных задач; снять метку-фильтр.

## 6. Ограничения

- **Для задач из Jira категория решает всё.** Если в «Категориях задач» снять с задачи «Инициативы (на потом)» или «Квартальные задачи» — она уйдёт в архив. Вернуть такую из архива кнопкой нельзя — сначала верните категорию.
- **Задачи из Jira редактируются ограниченно** — название, статус, исполнитель, заказчик и цели берутся из Jira. Здесь меняются приоритет, разработчик, группа, «В план», параметры планирования и — через «✎ Редактировать план» — плановые часы.
- **Архивирование и удаление запрещены, пока задача числится в утверждённом сценарии.** Сервис откажет (текст отказа сейчас на английском). Сначала верните сценарий в черновик и уберите задачу из него.
- **Ручной архив задачи из Jira держится до ближайшей синхронизации**, если категория осталась прежней (см. сценарий Б).
- **Удаление через корзину — необратимо.** Задача из Jira после удаления снова появится при следующей синхронизации (пока у неё стоит категория «Инициативы (на потом)»). Ручная идея пропадёт навсегда.
- **Возврат из архива не отмечает задачу в сценариях** — только возвращает её кандидатом в черновые.
- **Ручная идея, взятая в утверждённый сценарий, пропадает из всех вкладок раздела** — в самом сценарии она остаётся.
- **Ручная правка длительности** при заполненном поле Jira держится только до следующего обновления из Jira.
- **Группировка по кварталам** запоминается в этом браузере, на другом компьютере она будет выключена.
- **Перетаскивание строк не используется.** Приоритет меняется только вводом числа в колонке «Prio».

## 7. Частые проблемы

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Инициатива пропала из «Бэклога» | Её взяли в утверждённый сценарий (она на вкладке «Активные»); в «Категориях задач» сменили категорию; она в архиве | Проверить «Активные» и «Архив»; в «Категориях задач» вернуть категорию «Инициативы (на потом)» |
| Инициатива есть в «Бэклоге», но не появляется в сценарии | Выключен «В план»; она эпик инициативы, которую планируют целиком; сценарий другой команды | Проверить переключатель «В план» и режим планирования у родителя; убедиться, что команда сценария совпадает с командой задачи |
| В разделе пусто, хотя в Jira инициативы есть | Фильтр команды или группы в шапке отсекает задачи; задачи ещё не разобраны | Проверить фильтр; в «Категориях задач» → «К разбору» отнести задачи к «Инициативам (на потом)» |
| Не могу поменять название / исполнителя | Задача из Jira — эти поля правятся в Jira | Поправить в Jira, нажать «Обновить с Jira» или «Обновить только видимые» |
| Не могу поправить часы задачи из Jira кликом по ячейке | У задач из Jira ячейка не редактируется | Шестерёнка → «✎ Редактировать план» |
| Ручная длительность «откатилась» | Поле в Jira заполнено, и обновление из Jira вернуло его значение | Поправить значение в Jira |
| Архивированная задача снова в «Бэклоге» | Категория осталась «Инициативы (на потом)», и синхронизация вернула задачу | Сменить категорию в «Категориях задач» |
| Не получается архивировать или удалить — ошибка на английском | Задача числится в утверждённом сценарии | Вернуть сценарий в черновик, убрать задачу, затем архивировать |
| «Связать с Jira» — ошибка, что задача не найдена или уже связана | Задача ещё не загружена синхронизацией; у задачи уже есть своя строка | Дождаться синхронизации; при наличии строки — удалить ручную идею |
| Ручная идея пропала после утверждения сценария | Ручные идеи, взятые в утверждённый сценарий, в разделе не показываются | Смотреть идею в самом сценарии |
| Задача в «Активных», но я её не утверждал | Она включена в утверждённый сценарий или ей дали категорию «Квартальные задачи» при разборе | Колонка «Сценарий» в строке; если сценария нет — проверить категорию в «Категориях задач» |
| У задачи метка «спорно», ячейка роли обведена пунктиром | В Jira у роли заполнено несколько полей оценки с разными значениями (какие поля читаются — «Настройки → Поля Jira → Плановые трудозатраты») | Пока выбора нет, действует верхнее поле из настроек. Кликнуть по ячейке или по метке и выбрать значение: одно из полей или своё. В выборе заранее отмечено значение, которое действует сейчас, — «Принять» без изменений его и закрепляет. Все такие задачи показывает метка «Только спорные · N» справа от вкладок; вместе с «Не в плане» останутся задачи, подходящие под обе. Если значение в Jira изменится, выбор сбросится и задача снова станет спорной |

## 8. Связанные разделы

**Откуда приходят данные:**

- **Категории задач** — единственный источник задач из Jira для раздела: «Инициативы (на потом)» — вкладка «Бэклог», «Квартальные задачи» — вкладка «Активные».
- **Синхронизация** — без свежей синхронизации новые задачи из Jira сюда не дойдут.
- **Фильтр команды и группы** в шапке — что отображается на каждой вкладке.
- **Настройки → Поля Jira** — из каких полей берутся плановые часы, длительность, заказчик и участвующие команды.
- **Настройки → Планирование** — правило для мультикомандных RFA и отсечка ОПЭ.
- **Ресурсы** — список сотрудников для колонок «Аналитик» и «Разработчик» (только активные).

**Куда уходит результат:**

- **Сценарии** — берут задачи с включённым «В план» как кандидатов в черновые сценарии своей команды: с приоритетом, оценками, аналитиком и разработчиком.
- **Ресурсное планирование** — длительность и параллельность фаз отсюда. Вовлечённость фазы берётся по порядку: зафиксированная в карточке фазы → личная настройка сотрудника → справочник команды по роли.
- **Дашборд** и **Аналитика** — задачи в работе попадают в общую картину по своим задачам Jira.
- **Проекты** — кнопка-стрелка в строке открывает карточку задачи.

Если что-то в разделе пошло не так — обычно проблема в «Категориях задач» (категория) или в фильтре команды. Раздел в первую очередь отражает результат разбора.

## Часы длинной RFA: таблица в шестерёнке

Для любой задачи из Jira в окне **«Параметры планирования»** (шестерёнка в колонке «Действия») есть блок **«Часы и иерархия»**. Особенно он полезен для RFA с дочерними эпиками. В блоке:

- **Полоса часов** сверху: Факт прошлых кварталов · Факт текущего квартала · Утверждено (остаток) · Запланировать (свободно). Под полосой — «Черновик: N ч (информационно)».
- **Таблица по ролям** (Аналитик / Разработка / Тестирование / ОПЭ и «Итого»): колонки «План», «Факт прошлых Q», «Факт текущий», «Утверждено», «Запланировать», «Черновик».
  - «План» — плановые часы самой задачи (с учётом ручной правки).
  - «Факт прошлых Q» — списания по задаче и всем её потомкам до начала квартала.
  - «Факт текущий» — списания в текущем квартале по задачам поддерева, утверждённым в сценарии этого квартала.
  - «Утверждено» — план задач поддерева, утверждённых в сценарии этого квартала.
  - «Запланировать» = План − Факт прошлых Q − Утверждено. Отрицательное значение — красным.
  - «Черновик» — план дочерних задач, ещё не утверждённых и без списаний. Отменённые (статусы «Отменено», «Rejected», «Won't Do» и т.п.) не учитываются.
- Период «текущего» квартала берётся из квартала, выбранного в шапке.
- **Метки под таблицей**: «Перерасход» (где-то «Запланировать» ушло в минус), «План не задан», «Черновики превышают остаток».
- **Переключатель режима планирования группы** — есть, только если у задачи в списке есть дочерние эпики (см. ниже).
- **Кнопка «✎ Редактировать план»** — ручная правка часов (см. ниже).
- **Предупреждение о конфликте с Jira** — над таблицей, если он есть (см. ниже).

В самой таблице раздела дочерние эпики показываются прямо под строкой RFA. Это нужно, чтобы видеть состав группы и заходить в шестерёнку каждой дочерней задачи отдельно.

## Режим планирования группы

В окне «Параметры планирования» — переключатель:

- **Инициатива целиком** (по умолчанию): в сценарий идёт сама RFA, дочерние эпики в кандидаты не попадают — их часы уже сидят в родителе.
- **По эпикам**: в сценарий идут дочерние эпики. Сама RFA при переключении выключается из плана; её включают переключателем «В план» для кварталов, не покрытых эпиками.

Если в режиме «По эпикам» одновременно включить RFA и её эпик, а их квартал совпадает, — появится оранжевый знак: часы будут посчитаны дважды. Это допустимо в редких случаях; решение остаётся за вами.

### Галочка «В план»

У каждой задачи в списке — и у RFA, и у её дочерних строк — есть переключатель **«В план»**. Подсказка на нём объясняет, что он значит для этой строки. Выключенная задача остаётся в списке (строка приглушена), но в сценарии не попадает: из черновых сценариев она сразу уходит, утверждённые не меняются. Включили обратно — задача появляется в черновых сценариях своей команды.

**Дискавери** (служебный эпик внутри RFA, отмечен меткой «Дискавери») по умолчанию выключен. Если его включить, его часы идут в сценарий **сверх** RFA — даже когда RFA планируется целиком.

Что значит переключатель у RFA и её эпиков:

- **Инициатива целиком** — у её обычных эпиков переключатель неактивен (подсказка «Инициатива планируется целиком — часы эпиков уже в ней»): их часы уже сидят в RFA, отдельно в сценарий они не идут. Так же и когда самой RFA в списке не видно: она другой команды, на другой вкладке или выполнена. Эпики RFA, уже утверждённой в сценарии, из «Бэклога» уходят вместе с ней — они в плане через родителя. А вот RFA, отправленная в архив или отменённая, эпики отпускает — у каждого работает свой переключатель; выполненная RFA их не отпускает. Исключение — Дискавери, у него переключатель работает всегда.
- **По эпикам** — переключатель RFA управляет только самой RFA (включают для кварталов, не покрытых эпиками). У каждого эпика — свой переключатель.
- **Мультикомандная RFA** — саму RFA включить нельзя: в план идут только её эпики. Пока эпиков нет, RFA в сценарий не попадает — сначала команды заводят свои эпики.

Метка **«Не в плане · N»** справа от вкладок показывает, сколько задач выключено так, что их часы не идут в план, — в том числе Дискавери, который выключен по умолчанию. Нажатие на метку оставляет в списке только такие задачи. Выключенная RFA «по эпикам» и неактивные эпики RFA «целиком» туда не попадают и не приглушаются — из плана они ничего не убирают. Тот же переключатель есть в «Параметрах планирования» (шестерёнка).

### Мультикомандные RFA

Если над задачей работает несколько команд, режим переключить нельзя — она планируется только по эпикам, каждая команда берёт свою часть. В шестерёнке переключатель режима неактивен, под ним — список команд-участников. Без эпиков такая RFA в сценарий не попадает. У такой RFA стоит жёлтая метка «мультикоманда», а в подсказке — список участников.

Мультикомандной считается задача, у которой участвующих команд больше одной либо единственная участвующая команда не совпадает с продуктовой. Список участников приходит из поля Jira, указанного в «Настройки → Поля Jira → Поле участвующих команд».

Правило можно отключить: «Настройки → Планирование → Мультикомандные RFA планировать только по Эпикам». Тогда режим снова выбирает PM вручную — со всеми рисками двойного счёта часов между планами двух команд.

Когда родительская RFA принадлежит другой команде, в вашем списке её не будет — вместо этого под названием эпика подписано «в составе RFA-…» с командой-владельцем. Так видно, откуда растёт задача. Планировать свой эпик вы продолжаете, если эта RFA мультикомандная (пока правило выше не отключено) или её планируют по эпикам. Если её планируют целиком, переключатель «В план» у эпика неактивен (кроме Дискавери): его часы уже учтены в RFA другой команды.

## Ручная правка плановых часов

Кнопка «✎ Редактировать план» в окне «Параметры планирования» открывает справа панель «Редактирование плана · КЛЮЧ». Правка доступна для любой задачи из Jira:

- Колонка «Jira» — текущее значение из Jira (только просмотр).
- Колонка «Правка» — ваше значение по каждой роли. Очистить поле — вернуть роли значение Jira.
- Обязательное поле «Комментарий» — зачем правка.
- «Сохранить» — сохраняется сразу, без перезагрузки страницы. Новые часы видны в строке раздела, в сценариях и в ресурсном планировании.
- «Сбросить к Jira» — вернуть все роли к значениям из Jira.
- «Показать историю» — журнал правок: дата, роль, было, стало, источник, комментарий.

Колонка «План» в таблице часов показывает вашу правку.

## Конфликт с Jira

Если в Jira план изменили *после* вашей правки, при следующей синхронизации в окне «Параметры планирования» над таблицей часов появится предупреждение:

> **В Jira план изменили на N ч (Роль). Сейчас активна ручная правка.**
> [Принять Jira]  [Игнорировать]

- **Принять Jira** — заменяет вашу правку значением из Jira.
- **Игнорировать** — оставляет вашу правку, предупреждение исчезает.

Ручная правка часов никогда не теряется сама — её можно потерять только через явное «Принять Jira» или «Сбросить к Jira».

## 9. Группы внутри команды

Если выбранные в шапке команды делятся на группы, в таблице появляется колонка **«Группа»** — выпадающий список групп. Он есть только у задач из Jira; у ручных идей — «—».

- Выбранная группа приписывает задачу группе, дочерние задачи без своей группы её наследуют.
- Бледное значение — группа не проставлена явно. Подсказка объясняет, откуда она: «Унаследовано от родителя» или «Предположение по исполнителю».

При выбранной в шапке группе в списке остаются инициативы, под которыми есть её работы. Инициатива, под которой группы ещё не проставили, и ручная идея без задачи Jira видны при любом выборе — прятать незаполненное нельзя.
