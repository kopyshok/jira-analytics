# KPI аналитиков

Раздел `/kpi` — ведомость коэффициента эффективности (КЭ) сотрудников по командам. Шесть метрик из справочника складываются во взвешенный итог, руководитель видит его по командам и по людям, с расшифровкой до конкретных задач Jira.

Раздел разрабатывается в отдельной ветке и по умолчанию скрыт из меню, пока не завершена проверка на реальных данных.

---

## 1. Зачем раздел

Раньше оценка аналитиков собиралась вручную — выгрузка задач из Jira, подсчёт долей в таблице. Раздел KPI делает то же самое автоматически: берёт те же правила, что раньше считались руками, и пересчитывает их на лету по текущим данным Jira.

Ключевая идея — метрики не зашиты в код. Шесть метрик первой версии (качество выпуска, соблюдение сроков, соблюдение регламентов, Cycle Time, оценка заказчика, своевременность трудозатрат) заведены как записи в справочнике. Новая похожая метрика или изменение существующей — правка в настройках, без участия разработчика.

«Соблюдение сроков» оценивает выполнение в срок квартальной цели, а квартальная цель — это эпик. ИТ-задачи в эту метрику не входят.

**Кого раздел оценивает.** Профиль оценки применяется к списку ролей сотрудников (первая версия: аналитик и руководитель проектов). Сотрудник, чья роль не привязана ни к одному профилю или не заполнена вовсе, в ведомость не попадает. Сколько таких людей в командах — видно в плитке «Покрытие профилями» и в таблице покрытия («Настройки → KPI → Профили оценки»).

**Кому засчитывается задача.** «Соблюдение сроков», Cycle Time и «Оценка заказчика» считаются по исполнителю задачи; «Качество выпуска» и «Соблюдение регламентов» — по автору (в «Качестве выпуска» баг на проде засчитывается автору той задачи, к которой баг привязан). Признак меняется в справочнике метрик, у каждой стороны формулы отдельно.

## 2. Когда сюда заходить

- В начале месяца — посмотреть итоги предыдущего.
- В середине месяца — держать руку на пульсе: у кого проседает метрика, пока месяц ещё не закрыт.
- По завершении квартала — переключить период на квартал, посмотреть итог целиком и, если утверждение включено, подписать его.
- Когда сотрудник просит объяснить свою оценку — открыть карточку сотрудника, разобрать по метрикам, провалиться в расшифровку до списка задач.
- Когда новый квартал требует новый норматив Cycle Time — «Настройки → KPI → Нормативы Cycle Time».
- Когда нужно завести новую метрику или скорректировать вес существующей — «Настройки → KPI».

## 3. Элементы интерфейса

| № | Блок | Что показывает |
|---|------|-----------------|
| 1 | Фильтры сверху | Выбор периода (месяц / квартал / последние месяцы / свой отрезок), продуктовое направление |
| 2 | Глобальный фильтр команды (в шапке) | Сужает ведомость и сводку до выбранных команд |
| 3 | Строка итогов | Средний КЭ с дельтой, сколько людей ниже цели, сколько клеток без данных, сколько человек оценивается. Две ссылки открывают разбор |
| 4 | Полоса метрик команд | Среднее по каждой метрике и дельта к прошлому периоду. Показана только когда команд в ведомости несколько |
| 5 | Ведомость | Таблица: строки-команды с итогом и дельтой, разворачиваются в людей; у человека — место в команде, метрики, полоска и итог |
| 6 | Распределение по итогу | Гистограмма: сколько человек в каком диапазоне |
| 7 | Панель расчёта снизу | Клик по значению метрики — дробь и таблица разбора задач под ведомостью |
| 8 | Вкладка сотрудника | Клик по имени — вкладка рядом с «Ведомостью»: кольцо, тренд, вклад метрик в итог, разбор |
| 9 | «Утвердить квартал» | Заморозить снимок результата команды за квартал. Кнопки нет, пока утверждение выключено в общих правилах |
| 10 | «Выгрузить в Excel» | xlsx-копия текущей ведомости |

### 3.0. Строка итогов и два разбора

Строка итогов занимает одну полосу и содержит четыре числа. Два из них кликабельны:

- **«разобрать»** рядом с числом клеток без данных — открывает таблицу: метрика, у скольких человек она пуста, вероятная причина (не задан норматив Cycle Time; поле не заполняется в Jira, раз пусто у всех; у части людей просто нет подходящих задач). Строка разворачивается в список фамилий.
- **«кто не попал»** рядом с покрытием — поимённый список сотрудников, которых раздел не оценивает, с их ролью. Отдельно помечены те, у кого роль не заполнена вовсе.

Оба разбора открываются панелью сбоку и не занимают места на странице, пока не нужны.

### 3.1. Фильтры периода и направления

Слева — переключатель периода и стрелки пролистывания. Четыре режима:

| Режим | Что показывает |
|---|---|
| Месяц | Один календарный месяц |
| Квартал | Целый квартал; рядом появляется выбор квартала |
| Последние месяцы | Отрезок, кончающийся текущим месяцем; длина задаётся числом |
| Свой период | Произвольный отрезок: конец пролистывается стрелками, длина задаётся числом |

Стрелки листают шагом в длину периода: на месяце — по месяцам, на квартале — по кварталам.

**Как считается период длиннее месяца.** Итог — одна дробь по задачам всех месяцев сразу, а не среднее месячных процентов. Месяц с одной закрытой задачей не весит столько же, сколько месяц с двадцатью. Разница видна на примере: 1 из 2 в июле, 1 из 1 в августе, 2 из 2 в сентябре дают за квартал 4 из 5 = 80%, тогда как среднее месячных было бы 83%.

**Разбивка по месяцам.** На периоде длиннее месяца в ведомости появляются приглушённые колонки помесячных значений — сразу видно, в каком месяце просело. Они справочные: решение принимается по колонке «Итог».

Справа — выпадающий список продуктового направления. Это фильтр отчёта, а не свойство метрики: один и тот же набор метрик можно посмотреть по разным направлениям, не заводя копии метрик под каждое.

### 3.2. Ведомость

Строки верхнего уровня — команды (из глобального фильтра; если фильтр пуст — все команды сервиса). У строки команды: итог, дельта к прошлому такому же периоду (квартал сравнивается с прошлым кварталом, месяц — с прошлым месяцем; стрелка вверх/вниз/без изменений), число людей. Клик по строке — развернуть/свернуть людей внутри.

Строки людей: место в команде по итогу, имя (клик открывает вкладку сотрудника), название профиля оценки, колонки метрик, колонка «Итог» — с полоской заполнения и дельтой к прошлому такому же периоду. Заливка ячейки — тонкая подсветка по попаданию в цель: зелёная (на цели и выше), жёлтая (в границах жёлтой зоны под целью), красная (ниже жёлтой зоны). Клик по значению метрики раскрывает панель расчёта под ведомостью и подсвечивает выбранную ячейку рамкой.

Если у метрики нет данных за период (ни одной подходящей задачи) — ячейка показывает «нет данных» вместо процента. Что при этом происходит с итогом, задаётся правилом «Если данных для расчёта нет»: метрика либо выбывает из расчёта, отдав свой вес остальным, либо засчитывается на 100%, либо на 0%. Правило можно задать отдельно каждой метрике (в конструкторе метрики), а метрики без своего правила берут общее из настроек раздела. Правила смешиваются: выбывшая метрика уходит из расчёта вместе с весом, метрики с «0%» и «100%» остаются в расчёте с подставленным значением. Карточка сотрудника под метрикой пишет, какое правило сработало.

Группа «Без команды» — сотрудники, для которых не удалось определить команду за отчётный период (обычно временная ситуация, пока не заведено участие в команде).

### 3.3. Вкладка сотрудника

Открывается кликом по имени в ведомости — вкладкой рядом с «Ведомостью», а не боковым окном. Вкладок может быть несколько: двух человек удобно держать рядом при сравнении, закрываются крестиком.

Что внутри:

- **Шапка** — кольцо итогового процента (цвет по принципу «цель / жёлтая зона / ниже»), дельта к прошлому месяцу (показана только на месячном периоде: график остаётся помесячным, а итог считается за весь период), место в команде, среднее по команде, сколько метрик без данных, плашка утверждения квартала.
- **Тренд за 12 месяцев** с пунктирной линией цели.
- **«Из чего сложился итог»** — вклад каждой метрики в итог в процентных пунктах. Видно не просто «качество выпуска 67%», а сколько это стоило в итоговом числе. Метрики без данных помечены «вес роздан».
- **Разбор по метрикам** — карточка на метрику: значение, полоска с засечкой цели, дробь, вес и среднее по команде для сравнения. Клик открывает расчёт.
- **«Что мешает считать»** — конкретные причины пустых метрик: не задан норматив Cycle Time на квартал, оценки заказчика не проставлены у всей команды и т. п.

### 3.4. Панель расчёта показателя

Клик по значению метрики раскрывает панель **под ведомостью** (не модальное окно) — таблица остаётся на экране, соседние ячейки можно перебирать подряд, не закрывая панель.

В панели:

- крупная дробь «числитель из знаменателя», значение, вес метрики и цель профиля;
- **таблица разбора** — строка на задачу, колонка на требование показателя. Строки с проблемой подсвечены и стоят первыми, переключатель «Все / С ошибкой» оставляет только их. Вид таблицы зависит от способа расчёта метрики:
  - доля задач — колонка на каждое требование, которым числитель строже списка сравнения («Цель задачи», «Описание текущего поведения», «Описание» и любое другое условие из справочника метрик), и итог «засчитана / не засчитана». У метрики качества выпуска числитель — это баги, поэтому проблемной считается попавшая в него задача, а итог называется «нарушение»;
  - норматив к факту (Cycle Time) — факт задачи, норматив квартала и отклонение в процентах; задача без факта показана как пробел в данных;
  - средний балл к максимуму — оценка задачи и её доля от максимума; задача без оценки в расчёт не входит и видна отдельно;
  - своевременность трудозатрат — строка на запись о часах: дата работы, дата внесения, часы и задержка;
- **«Отсеяно до сравнения»** (свёрнуто) — задачи, не дошедшие до показателя вообще: например, отменённые. Для метрики своевременности здесь же записи без даты внесения — самая частая причина пустого показателя;
- **воронка отбора** (свёрнуто) — сколько задач осталось после каждого условия и сколько оно отсекло. Шаг, отсёкший больше половины остатка, подсвечен: именно он и есть ответ на вопрос «почему так мало».

### 3.5. Утверждение квартала

Подписывается целый квартал, а не месяц. Кнопка появляется, только когда утверждение включено в «Настройки → KPI → Общие правила» (по умолчанию выключено), и активна при двух условиях: период на экране — ровно календарный квартал, а глобальный фильтр команды сужен ровно до одной команды (утверждение это понятие «на одну команду», а не на произвольный набор).

Утверждение замораживает снимок: результат, веса профиля, нормативы и общие правила, действовавшие в этот момент. После утверждения правка настроек задним числом на этот квартал не влияет — снимок не пересчитывается. Повторное нажатие на уже утверждённый квартал недоступно, это состояние показано плашкой с датой и именем утвердившего.

Отдельный месяц внутри подписанного квартала по-прежнему считается вживую: снимок хранит квартальный итог, помесячных чисел в нём нет.

### 3.6. Выгрузка в Excel

Кнопка в шапке страницы отдаёт xlsx-копию текущей ведомости (с учётом выбранных фильтров периода, команды и направления). На периоде длиннее месяца перед итогом добавляются колонки помесячных значений. Для утверждённых кварталов выгружается тот же замороженный снимок, что показан в ведомости.

## 4. Откуда цифры

- **Источник** — те же задачи и записи о трудозатратах Jira, что и в остальном сервисе, плюс несколько дополнительных полей (резолюция, окружение, подтип, тип затрат, фактический Cycle Time, продуктовое направление, связи задач, дата внесения записи о трудозатратах) — все сопоставляются в «Настройки → Подключение → Поля Jira» и «Настройки → Справочники».
- **Период сотрудника** обрезается по фактическим дням его участия в команде: вступил в середине месяца — считаются только дни после вступления.
- **Cycle Time не штрафует за паузу.** Если задача стояла в статусе «Приостановлено», эти дни вычитаются из фактического цикла: ожидание — это не срок работы исполнителя. В расшифровке метрики есть колонка «На паузе» с числом вычтенных дней, а в столбце «Факт» стоит уже уменьшенное значение. Дни считаются по истории статусов Jira и обновляются вместе с задачами при синхронизации.
- **Значение всегда живое** — считается по текущим данным при каждом открытии страницы, кроме утверждённых кварталов (снимок).
- **Итог** — взвешенная сумма шести метрик профиля; сумма весов профиля равна 100%.
- **Своевременность трудозатрат** считается одним из двух способов, выбранным в общих правилах: «часов от времени работы» (по умолчанию, как в ТЗ — запись просрочена, если создана позже чем через 18 часов после времени начала работы; выходные не прощаются) или «рабочие дни и время отсечки» (не позже указанного времени N-го рабочего дня, выходные и праздники пропускаются по производственному календарю). Запись без даты внесения не участвует в расчёте вообще.
- **Своевременность трудозатрат требует даты внесения записи** — это отдельное поле, которое обычная синхронизация ворклогов не дозаполняет у уже загруженных записей. Если раньше эта дата не выгружалась, метрика честно покажет «нет данных» до тех пор, пока не будет сделана «Полная перезагрузка (удалить и перечитать)» ворклогов (`/sync`, вкладка «Дополнительно»).

## 5. Типовые задачи

### Сценарий А: закрыть квартал по своей команде

1. Открыть `/kpi`, в глобальном фильтре шапки выбрать ровно одну команду.
2. Переключить период на «Квартал» и выбрать нужный квартал.
3. Проверить полосу итогов и ведомость — нет ли явных провалов.
4. Нажать «Утвердить квартал» (кнопка есть, только если утверждение включено в общих правилах).
5. Плашка в шапке страницы и во вкладках сотрудников покажет «утверждено», числа заморожены снимком.

### Сценарий Б: разобраться, почему у сотрудника низкий итог

1. Найти сотрудника в ведомости, кликнуть по имени — откроется его вкладка.
2. Посмотреть «Из чего сложился итог» — какая метрика стоила больше всего процентных пунктов.
3. Кликнуть по проблемной метрике — раскроется панель расчёта.
4. В таблице разбора нажать «С ошибкой» — останутся только незачтённые задачи, колонки назовут причину.
5. Открыть задачу по ссылке в Jira и дозаполнить то, чего не хватает.
6. Если незачтённых задач нет, а показатель всё равно низкий — раскрыть «Отсеяно до сравнения» и воронку отбора: там видно, что задачи не дошли до сравнения.

### Сценарий В: завести новую метрику

См. раздел KPI в справке по настройкам (`/settings#kpi`) — там же способы расчёта, обязательные поля и предпросмотр на реальных данных.

### Сценарий Г: сотрудника нет в ведомости

1. Открыть «Настройки → KPI → Профили оценки», прокрутить до таблицы покрытия.
2. Найти строку с его ролью. Если профиль не привязан — добавить роль в нужный профиль.
3. Если сотрудник попал в строку «Роль не заполнена» — заполнить роль в его карточке сотрудника.

## 6. Ограничения

- **Норматив Cycle Time задаётся на квартал.** Если период растянут на несколько кварталов, берётся среднее по тем кварталам, где норматив заведён.
- **Оцениваются только роли, привязанные к профилям.** Остальные сотрудники в ведомость не попадают вовсе — это осознанное решение, а не потеря данных.
- **Утверждение — на одну команду.** Нельзя утвердить сразу несколько команд одним нажатием.
- **Доступ по ролям пока не разграничен внутри раздела** — раздел закрыт целиком скрытием пункта меню (см. «Настройки → Доступ → Видимость разделов»), не отдельными правами по людям.
- **Направление — фильтр отчёта**, а не свойство метрики: смена направления не требует пересчёта справочника метрик.

## 7. Частые проблемы

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Метрика показывает «нет данных» | За период не нашлось ни одной подходящей задачи/записи | Кликнуть по ячейке и прочитать воронку отбора в панели снизу — она называет условие, отсёкшее всё |
| Сотрудника нет в ведомости | Его роль не привязана ни к одному профилю оценки, либо роль не заполнена | «Настройки → KPI → Профили оценки», таблица покрытия внизу вкладки |
| Cycle Time пуст у всей команды | Не задан норматив на квартал | «Настройки → KPI → Нормативы Cycle Time» |
| «Своевременность трудозатрат» — «нет данных» у всех сотрудников | У записей о трудозатратах не заполнена дата внесения (обычная синхронизация её не дозаполняет) | `/sync` → вкладка «Дополнительно» → «Полная перезагрузка (удалить и перечитать)» ворклогов |
| Кнопки «Утвердить квартал» нет | Утверждение выключено в «Настройки → KPI → Общие правила» | Включить выключатель, когда пора подписывать результаты |
| Кнопка «Утвердить квартал» неактивна | Период на экране не квартал, в фильтре не ровно одна команда, либо квартал уже утверждён | Переключить период на квартал и сузить фильтр до одной команды; если утверждён — посмотреть плашку с датой |
| Числа в ведомости не меняются после правки норматива/веса | Квартал уже утверждён — снимок заморожен | Это ожидаемо; правка подействует на неутверждённые кварталы |
| Строка «Без команды» с людьми | Для сотрудника нет действующего участия в команде за отчётный период | Проверить участие сотрудника в команде в разделе сотрудников |
| Раздел не виден в меню | Скрыт по умолчанию | Включить в «Настройки → Доступ → Видимость разделов» |

## 8. Связанные разделы

**Откуда приходят данные:**
- **Синхронизация** (`/sync`) — без свежих задач и трудозатрат ведомость не обновится. Если у задач, выгруженных давно, не хватает полей для KPI (резолюция, окружение, подтип и т.п.) — на вкладке «Дополнительно» есть «Перечитать задачи с даты», чтобы дозаполнить их без полной пересинхронизации.
- **Настройки → Поля Jira** — сопоставление полей, от которых зависят метрики (резолюция, окружение, подтип, тип затрат, Cycle Time, направление).
- **Настройки → KPI** — справочники метрик, профилей оценки, нормативов Cycle Time и общих правил раздела.
- **Глобальный фильтр команды** в шапке — общий для ведомости, сводки по командам и утверждения.
- **Итог квартала не равен среднему трёх месяцев** — это одна дробь по всем задачам квартала (см. 3.1).

**Куда уходит результат:**
- Экспорт в Excel — для отчётности вне сервиса.
- Утверждённый снимок — источник истины для этой команды и квартала впредь, независимо от последующих правок настроек.
