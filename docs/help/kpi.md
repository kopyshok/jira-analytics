# KPI аналитиков

Раздел «KPI» (заголовок «KPI аналитиков») — ведомость коэффициента эффективности (КЭ) сотрудников по командам. Метрики профиля оценки (в первой версии — шесть) складываются во взвешенный итог, руководитель видит его по командам и по людям, с расшифровкой до конкретных задач Jira.

Администратор может скрыть раздел из меню для всех («Настройки → Видимость разделов»); по умолчанию раздел виден.

---

## 1. Зачем раздел

Раньше оценка аналитиков собиралась вручную — выгрузка задач из Jira, подсчёт долей в таблице. Раздел KPI делает то же самое автоматически: берёт те же правила, что раньше считались руками, и пересчитывает их на лету по текущим данным Jira.

Ключевая идея — метрики не зашиты в код. Шесть метрик первой версии (качество выпуска, соблюдение сроков, соблюдение регламентов, Cycle Time, оценка заказчика, своевременность трудозатрат) заведены как записи в справочнике. Новая похожая метрика или изменение существующей — правка в настройках, без участия разработчика.

«Соблюдение сроков» оценивает выполнение в срок квартальной цели, а квартальная цель — это эпик. ИТ-задачи в эту метрику не входят.

**Кого раздел оценивает.** Профиль оценки применяется к списку ролей сотрудников (первая версия: аналитик и руководитель проектов). Одна роль принадлежит не больше чем одному профилю. Сотрудник, чья роль не привязана ни к одному профилю, привязана к выключенному профилю или не заполнена вовсе, в ведомость не попадает. Сколько таких людей в командах — видно в строке итогов («Оценивается N из M», ссылка «кто не попал») и в таблице «Покрытие ролей профилями» («Настройки → KPI → Профили оценки», внизу вкладки).

**Кому засчитывается задача.** «Соблюдение сроков», Cycle Time и «Оценка заказчика» считаются по исполнителю задачи; «Качество выпуска» и «Соблюдение регламентов» — по автору (в «Качестве выпуска» баг на проде засчитывается автору той задачи, к которой баг привязан). Признак меняется в справочнике метрик, у каждой стороны формулы отдельно.

## 2. Когда сюда заходить

- В начале месяца — посмотреть итоги предыдущего.
- В середине месяца — держать руку на пульсе: у кого проседает метрика, пока месяц ещё не закрыт.
- По завершении квартала — переключить период на квартал, посмотреть итог целиком и, если утверждение включено, подписать его.
- Когда сотрудник просит объяснить свою оценку — открыть карточку сотрудника, разобрать по метрикам, провалиться в расшифровку до списка задач.
- Когда новый квартал требует новый норматив Cycle Time — «Настройки → KPI → Нормативы Cycle Time».
- Когда нужно завести новую метрику или скорректировать вес существующей — «Настройки → KPI».

## 3. Элементы интерфейса

| № | Блок | Что показывает |
|---|------|-----------------|
| 1 | Фильтры сверху | Переключатель периода «Месяц / Квартал / Последние месяцы / Свой период» со стрелками, выпадающий список «Продуктовое направление». Пока данные пересчитываются, рядом видна надпись «обновляется…» |
| 2 | Глобальный фильтр команды (в шапке) | Сужает ведомость и сводку до выбранных команд, второй уровень — до групп внутри команды |
| 3 | Строка итогов | «Средний КЭ» с дельтой, «Ниже цели», «Без данных», «Оценивается». Две ссылки — «разобрать» и «кто не попал» — открывают разбор |
| 4 | Полоса «Метрики по выбранным командам» | Среднее по каждой метрике и дельта к прошлому такому же периоду. Показана только когда команд в ведомости несколько |
| 5 | Ведомость | Таблица с легендой цветов: строки-команды с итогом и дельтой, разворачиваются в людей; у человека — место в команде, профиль, метрики, итог с дельтой и полоской |
| 6 | Панель расчёта снизу | Клик по значению метрики — дробь и таблица разбора задач под ведомостью |
| 7 | Вкладка сотрудника | Клик по имени — вкладка рядом с «Ведомостью»: кольцо, тренд, вклад метрик в итог, разбор |
| 8 | «Утвердить квартал» | Заморозить снимок результата команды за квартал. Кнопки нет, пока утверждение выключено в общих правилах |
| 9 | «Выгрузить в Excel» | xlsx-копия текущей ведомости |

Период и направление хранятся в адресе страницы: ссылку на квартальную ведомость по направлению можно переслать коллеге, и у него откроется тот же срез (команды он выбирает в своей шапке сам).

### 3.0. Строка итогов и два разбора

Строка итогов занимает одну полосу и содержит четыре числа:

| Подпись | Что значит |
|---|---|
| **СРЕДНИЙ КЭ** | Средний итог оценённых людей; рядом стрелка и изменение в п.п. к прошлому такому же периоду |
| **НИЖЕ ЦЕЛИ** | «N из M» — сколько человек не дотянули до цели профиля (красное, если таких больше нуля) |
| **БЕЗ ДАННЫХ** | «N из M клеток» — сколько клеток ведомости показывают «нет данных» |
| **ОЦЕНИВАЕТСЯ** | «N из M» — сколько людей команд попали в ведомость из всех участников команд за период |

Две ссылки открывают разбор:

- **«разобрать»** рядом с «Без данных» — панель «Почему не хватает данных»: колонки «Метрика», «Пусто у» (сколько человек), «Почему» — вероятная причина (не задан норматив Cycle Time; пусто у всех оценённых — похоже, поле не заполняется в Jira или условия метрики никого не находят; у части людей просто нет подходящих задач или записей). Строка разворачивается в список фамилий.
- **«кто не попал»** рядом с «Оценивается» — панель «Кто не попал в ведомость»: поимённый список сотрудников, которых раздел не оценивает, с их ролью. У кого роль не заполнена вовсе, стоит жёлтая метка «Роль не заполнена».

Обе панели открываются сбоку и не занимают места на странице, пока не нужны. Ссылки видны, только когда есть что разбирать.

### 3.1. Фильтры периода и направления

Слева — переключатель периода, стрелки пролистывания и подпись выбранного периода («Сентябрь 2026», «III квартал (июл–сен) 2026», «Июль — Сентябрь 2026»). Четыре режима:

| Режим | Что показывает |
|---|---|
| Месяц | Один календарный месяц |
| Квартал | Целый календарный квартал; рядом появляется выбор «I квартал (янв–мар)» … «IV квартал (окт–дек)» |
| Последние месяцы | Отрезок, кончающийся текущим месяцем; при включении — три месяца, длина задаётся полем «Месяцев:» (от 2 до 24) |
| Свой период | Произвольный отрезок: конец пролистывается стрелками, длина задаётся полем «Месяцев:» |

Стрелки листают шагом в длину периода: на месяце — по месяцам, на квартале — по кварталам.

Отрезок ровно в три месяца, кончающийся последним месяцем квартала, сервис всегда считает кварталом: переключатель при этом подсвечивает «Квартал», а поле «Месяцев:» пропадает. Так бывает, например, если нажать «Последние месяцы» в марте, июне, сентябре или декабре.

**Как считается период длиннее месяца.** Итог — одна дробь по задачам всех месяцев сразу, а не среднее месячных процентов. Месяц с одной закрытой задачей не весит столько же, сколько месяц с двадцатью. Разница видна на примере: 1 из 2 в июле, 1 из 1 в августе, 2 из 2 в сентябре дают за квартал 4 из 5 = 80%, тогда как среднее месячных было бы 83%.

**Разбивка по месяцам.** На периоде длиннее месяца в ведомости появляются приглушённые колонки помесячных значений — сразу видно, в каком месяце просело. Они справочные: решение принимается по колонке «Итог».

Справа — выпадающий список продуктового направления. Это фильтр отчёта, а не свойство метрики: один и тот же набор метрик можно посмотреть по разным направлениям, не заводя копии метрик под каждое.

### 3.2. Ведомость

Над таблицей — легенда: «На цели», «Жёлтая зона», «Ниже цели» и «нет данных — метрика не участвует в расчёте».

Строки верхнего уровня — команды (из глобального фильтра; если фильтр пуст — все команды сервиса). У строки команды: название и «· N чел.», средние по метрикам, итог и дельта в п.п. к прошлому такому же периоду (квартал сравнивается с прошлым кварталом, месяц — с прошлым месяцем; стрелка вверх/вниз/без изменений). Команды развёрнуты сразу; клик по строке команды — свернуть/развернуть людей внутри.

Строки людей: колонка «#» — место в команде по итогу (1 — лучший), «Сотрудник» — имя (клик открывает вкладку сотрудника) и метка с названием профиля оценки, колонки метрик (полное название — в подсказке к заголовку), колонка «Итог» — с полоской заполнения и дельтой к прошлому такому же периоду (подсказка «Сравнение с периодом «…»»). Внутри команды люди идут от меньшего итога к большему. Заливка ячейки — тонкая подсветка по попаданию в цель: зелёная (на цели и выше), жёлтая (в границах жёлтой зоны под целью), красная (ниже жёлтой зоны); рядом с числом — значок того же смысла, чтобы не полагаться только на цвет. Клик по значению метрики раскрывает панель расчёта под ведомостью и подсвечивает выбранную ячейку рамкой. Клетка «нет данных» в ведомости не кликается — расчёт такой метрики открывается из вкладки сотрудника (см. 3.3).

Если ведомость не загрузилась, вместо таблицы — сообщение «Не удалось загрузить ведомость» и кнопка «Повторить»; если за период никого нет — «Нет данных за выбранный период».

Если у метрики нет данных за период (ни одной подходящей задачи) — ячейка показывает «нет данных» вместо процента. Что при этом происходит с итогом, задаётся правилом «Если данных для расчёта нет»: метрика либо выбывает из расчёта, отдав свой вес остальным, либо засчитывается на 100%, либо на 0%. Правило можно задать отдельно каждой метрике (в конструкторе метрики), а метрики без своего правила берут общее из настроек раздела. Правила смешиваются: выбывшая метрика уходит из расчёта вместе с весом, метрики с «0%» и «100%» остаются в расчёте с подставленным значением. Карточка сотрудника под метрикой пишет, какое правило сработало.

Группа «Без команды» — сотрудники, для которых не удалось определить команду за отчётный период (обычно временная ситуация, пока не заведено участие в команде).

### 3.3. Вкладка сотрудника

Открывается кликом по имени в ведомости — вкладкой рядом с «Ведомостью», а не боковым окном. Вкладок может быть несколько: двух человек удобно держать рядом при сравнении, закрываются крестиком.

Что внутри:

- **Шапка** — кольцо итогового процента (цвет по принципу «цель / жёлтая зона / ниже»), имя, команда, профиль и период; «К прошлому месяцу» (только на месячном периоде: график остаётся помесячным, а итог считается за весь период), «В команде N-й из M», «Среднее команды», «Метрик без данных N из M». Справа плашка утверждения: «Утвердил … · дата», «Квартал не утверждён» или «Утверждение доступно только для сотрудника с командой». Квартал для плашки берётся по последнему месяцу периода.
- **«Тренд за 12 месяцев»** — итог по месяцам за год, кончающийся последним месяцем периода, с пунктирной линией «цель N%».
- **«Из чего сложился итог N%»** — вклад каждой метрики в итог в процентных пунктах. Видно не просто «качество выпуска 67%», а сколько это стоило в итоговом числе. Метрики без данных помечены «вес роздан».
- **«Разбор по метрикам · клик открывает расчёт»** — карточка на метрику: значение, полоска с засечкой цели, дробь, вес и «в команде N%» для сравнения. У метрики без данных вместо полоски — какое правило сработало («Вес N% перераспределён между остальными метриками», «Нет данных — метрика считается выполненной на 100%» или «… невыполненной, 0%»). Клик по любой карточке, в том числе пустой, переключает на «Ведомость» и раскрывает под ней панель расчёта.
- **«Что мешает считать»** — конкретные причины пустых метрик: не задан норматив Cycle Time на квартал, метрика пуста у всей команды, а не только у этого сотрудника.

### 3.4. Панель расчёта показателя

Клик по значению метрики раскрывает панель **под ведомостью** (не модальное окно) — таблица остаётся на экране, соседние ячейки можно перебирать подряд, не закрывая панель.

В панели:

- шапка: крупная дробь «N из M», название метрики и сотрудника, период, команда, вес метрики, цель профиля и значение; справа кнопка «Свернуть»;
- **таблица разбора** — строка на задачу, колонка на требование показателя; ключ задачи — ссылка в Jira. Строки с проблемой подсвечены красным. Переключатель «Все · N / С ошибкой · N» (у качества выпуска и своевременности — «Нарушения · N») оставляет только проблемные строки; рядом — «N засчитано · M требуют внимания». Больше 25 строк — таблица листается страницами. Вид таблицы зависит от способа расчёта метрики:
  - доля задач — «Закрыта», у соблюдения сроков ещё «План» (плановая дата и «+N дн» просрочки), колонка на каждое требование, которым числитель строже списка сравнения («Цель задачи», «Описание текущего поведения», «Описание» и любое другое условие из справочника метрик) со значками «✓ есть / ✕ нет», и итог «засчитана / не засчитана». У метрики качества выпуска числитель — это баги, поэтому проблемной считается попавшая в него задача, а итог называется «нарушение» / «без нарушений». Метка «сверх списка» — задача учтена показателем, хотя её нет в списке сравнения;
  - норматив к факту (Cycle Time) — «Закрыта», «Факт», «На паузе», «Норматив», «Отклонение» и итог «в норме» / «превышение N%»; задача без факта помечена «нет данных»;
  - средний балл к максимуму — «Закрыта», «Оценка» («N из 5») и итог «максимум» / «N% от максимума»; задача без оценки помечена «нет оценки» и в расчёт не входит;
  - своевременность трудозатрат — строка на запись о часах: «Дата работы», «Внесено», «Часы» и итог «вовремя» / «просрочено · N ч (дн)»;
- **«Отсеяно до сравнения · N»** (свёрнуто; у своевременности — «Не судим · N») — задачи, не дошедшие до показателя вообще, с колонкой «Почему не вошла»: например, отменённые. Для метрики своевременности здесь же записи без даты внесения — самая частая причина пустого показателя;
- **«Как получилось это число — отбор по шагам»** (свёрнуто) — воронка «Что считаем» и «С чем сравниваем»: колонки «Условие», «Осталось», «Отсеяно». Шаг, отсёкший больше половины остатка, подсвечен: именно он и есть ответ на вопрос «почему так мало».

Если за период строк нет вовсе, панель пишет «За этот месяц у сотрудника нет строк для разбора».

### 3.5. Утверждение квартала

Подписывается целый квартал, а не месяц. Кнопка появляется, только когда утверждение включено в «Настройки → KPI → Общие правила», карточка «Утверждение квартала» (по умолчанию выключено), и активна при двух условиях: период на экране — ровно календарный квартал, а глобальный фильтр команды сужен ровно до одной команды (утверждение это понятие «на одну команду», а не на произвольный набор).

Рядом с кнопкой — метка состояния:

| Метка | Когда |
|---|---|
| «Утверждается только квартал» | Период на экране — не квартал (подсказка: переключите период на квартал) |
| «Утверждение — по одной команде» | Квартал выбран, но в фильтре не ровно одна команда |
| «Черновик, не утверждён» | Можно утверждать |
| «Утвердил … · дата» | Квартал уже утверждён — кнопка неактивна |

Утверждение замораживает снимок: результат, веса профиля, нормативы и общие правила, действовавшие в этот момент. После утверждения правка настроек задним числом на этот квартал не влияет — снимок не пересчитывается. Над ведомостью появляется зелёная плашка «Квартал утверждён по команде «…» — числа заморожены снимком…».

Отдельный месяц внутри подписанного квартала по-прежнему считается вживую: снимок хранит квартальный итог, помесячных чисел в нём нет.

### 3.6. Выгрузка в Excel

Кнопка в шапке страницы отдаёт xlsx-копию текущей ведомости (с учётом выбранных фильтров периода, команды и направления). На периоде длиннее месяца перед итогом добавляются колонки помесячных значений. Для утверждённых кварталов выгружается тот же замороженный снимок, что показан в ведомости.

## 4. Откуда цифры

- **Источник** — те же задачи и записи о трудозатратах Jira, что и в остальном сервисе, плюс несколько дополнительных полей (резолюция, окружение, подтип, тип затрат, фактический Cycle Time, продуктовое направление, связи задач, дата внесения записи о трудозатратах) — все сопоставляются в «Настройки → Подключение → Поля Jira» и «Настройки → Справочники».
- **Период сотрудника** обрезается по фактическим дням его участия в команде: вступил в середине месяца — считаются только дни после вступления.
- **Cycle Time не штрафует за паузу.** Если задача стояла в статусе «Приостановлено», эти дни вычитаются из фактического цикла: ожидание — это не срок работы исполнителя. В расшифровке метрики есть колонка «На паузе» с числом вычтенных дней, а в столбце «Факт» стоит уже уменьшенное значение. Дни считаются по истории статусов Jira и обновляются вместе с задачами при синхронизации.
- **Значение всегда живое** — считается по текущим данным при каждом открытии страницы, кроме утверждённых кварталов (снимок).
- **Итог** — взвешенная сумма метрик профиля; сумма весов профиля равна 100%. Метрика без данных участвует по правилу «Если данных для расчёта нет» (см. 3.2).
- **Своевременность трудозатрат** считается одним из двух способов, выбранным в общих правилах: «часов от времени работы» (по умолчанию, как в ТЗ — запись просрочена, если создана позже чем через 18 часов после времени начала работы; выходные не прощаются) или «рабочие дни и время отсечки» (не позже указанного времени N-го рабочего дня, выходные и праздники пропускаются по производственному календарю). Запись без даты внесения не участвует в расчёте вообще.
- **Своевременность трудозатрат требует даты внесения записи** — это отдельное поле, которое обычная синхронизация ворклогов не дозаполняет у уже загруженных записей. Если раньше эта дата не выгружалась, метрика честно покажет «нет данных» до тех пор, пока не будет сделана «Полная перезагрузка (удалить и перечитать)» ворклогов (раздел «Синхронизация», вкладка «Дополнительно»).

## 5. Типовые задачи

### Сценарий А: закрыть квартал по своей команде

1. Открыть раздел «KPI», в глобальном фильтре шапки выбрать ровно одну команду.
2. Переключить период на «Квартал» и выбрать нужный квартал.
3. Проверить полосу итогов и ведомость — нет ли явных провалов.
4. Убедиться, что рядом с кнопкой стоит «Черновик, не утверждён», и нажать «Утвердить квартал» (кнопка есть, только если утверждение включено в общих правилах).
5. Метка у кнопки сменится на «Утвердил … · дата», над ведомостью появится зелёная плашка «Квартал утверждён…», во вкладках сотрудников — «Утвердил …». Числа заморожены снимком.

### Сценарий Б: разобраться, почему у сотрудника низкий итог

1. Найти сотрудника в ведомости, кликнуть по имени — откроется его вкладка.
2. Посмотреть «Из чего сложился итог» — какая метрика стоила больше всего процентных пунктов.
3. Кликнуть по карточке проблемной метрики в «Разборе по метрикам» — откроется «Ведомость» с панелью расчёта под ней.
4. В таблице разбора нажать «С ошибкой» (у качества выпуска и своевременности — «Нарушения») — останутся только проблемные задачи, колонки со значком «✕ нет» назовут причину.
5. Открыть задачу по ссылке в Jira и дозаполнить то, чего не хватает.
6. Если проблемных задач нет, а показатель всё равно низкий — раскрыть «Отсеяно до сравнения» и «Как получилось это число — отбор по шагам»: там видно, что задачи не дошли до сравнения.

### Сценарий В: завести новую метрику

См. раздел KPI в справке по настройкам — там же способы расчёта, обязательные поля и предпросмотр на реальных данных.

### Сценарий Г: сотрудника нет в ведомости

1. В строке итогов нажать «кто не попал» — найти сотрудника и его роль.
2. Открыть «Настройки → KPI → Профили оценки» (раздел настроек доступен администратору), прокрутить до таблицы «Покрытие ролей профилями».
3. Найти строку с его ролью. Если в колонке «Профиль оценки» стоит «не привязана» — добавить роль в поле «Роли сотрудников» нужного профиля и нажать «Сохранить профиль». Проверить, что у профиля включён выключатель «Включён».
4. Если у сотрудника метка «Роль не заполнена» (в таблице покрытия — «проверить карточки») — заполнить роль в его карточке сотрудника.

## 6. Ограничения

- **Норматив Cycle Time задаётся на квартал.** Если период растянут на несколько кварталов, берётся среднее по тем кварталам, где норматив заведён.
- **Оцениваются только роли, привязанные к профилям.** Остальные сотрудники в ведомость не попадают вовсе — это осознанное решение, а не потеря данных.
- **Утверждение — на одну команду.** Нельзя утвердить сразу несколько команд одним нажатием.
- **Доступ по ролям пока не разграничен внутри раздела** — раздел можно только скрыть из меню целиком и сразу для всех (см. «Настройки → Доступ → Видимость разделов»), не отдельными правами по людям. Настройки KPI (метрики, профили, нормативы, правила) доступны только администратору.
- **Направление — фильтр отчёта**, а не свойство метрики: смена направления не требует пересчёта справочника метрик.

## 7. Частые проблемы

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Метрика показывает «нет данных» | За период не нашлось ни одной подходящей задачи/записи | Клетка «нет данных» в ведомости не кликается: открыть вкладку сотрудника, кликнуть карточку этой метрики и в панели снизу раскрыть «Как получилось это число — отбор по шагам» — воронка называет условие, отсёкшее всё. Общая картина по всем людям — ссылка «разобрать» в строке итогов |
| Сотрудника нет в ведомости | Его роль не привязана ни к одному профилю оценки, профиль выключен, либо роль не заполнена | «кто не попал» в строке итогов, затем «Настройки → KPI → Профили оценки», таблица «Покрытие ролей профилями» внизу вкладки |
| Cycle Time пуст у всей команды | Не задан норматив на квартал | «Настройки → KPI → Нормативы Cycle Time» |
| «Своевременность трудозатрат» — «нет данных» у всех сотрудников | У записей о трудозатратах не заполнена дата внесения (обычная синхронизация её не дозаполняет) | «Синхронизация» → вкладка «Дополнительно» → «Полная перезагрузка (удалить и перечитать)» ворклогов |
| Кнопки «Утвердить квартал» нет | Утверждение выключено в «Настройки → KPI → Общие правила» | Включить выключатель, когда пора подписывать результаты |
| Кнопка «Утвердить квартал» неактивна | Период на экране не квартал, в фильтре не ровно одна команда, либо квартал уже утверждён | Переключить период на квартал и сузить фильтр до одной команды; если утверждён — посмотреть плашку с датой |
| Числа в ведомости не меняются после правки норматива/веса | Квартал уже утверждён — снимок заморожен | Это ожидаемо; правка подействует на неутверждённые кварталы |
| Строка «Без команды» с людьми | Для сотрудника нет действующего участия в команде за отчётный период | Проверить участие сотрудника в команде в разделе «Ресурсы» |
| Раздел не виден в меню | Администратор скрыл его для всех | Включить в «Настройки → Доступ → Видимость разделов» |
| Выбрал «Последние месяцы», а подсветился «Квартал» | Три месяца, кончающиеся последним месяцем квартала, — это ровно квартал | Ожидаемо; чтобы взять другую длину, поменяйте «Свой период» → «Месяцев:» |

## 8. Связанные разделы

**Откуда приходят данные:**
- **Синхронизация** — без свежих задач и трудозатрат ведомость не обновится. Если у задач, выгруженных давно, не хватает полей для KPI (резолюция, окружение, подтип и т.п.) — на вкладке «Дополнительно» есть «Перечитать задачи с даты», чтобы дозаполнить их без полной пересинхронизации.
- **Настройки → Поля Jira** — сопоставление полей, от которых зависят метрики (резолюция, окружение, подтип, тип затрат, Cycle Time, направление).
- **Настройки → KPI** — справочники метрик, профилей оценки, нормативов Cycle Time и общих правил раздела.
- **Глобальный фильтр команды** в шапке — общий для ведомости, сводки по командам и утверждения.
- **Итог квартала не равен среднему трёх месяцев** — это одна дробь по всем задачам квартала (см. 3.1).

**Куда уходит результат:**
- Экспорт в Excel — для отчётности вне сервиса.
- Утверждённый снимок — источник истины для этой команды и квартала впредь, независимо от последующих правок настроек.

## 9. Группы внутри команды

У команды, разделённой на группы, второй уровень фильтра в шапке сужает
ведомость до людей выбранной группы. КЭ — показатель человека, поэтому группа
берётся по его приписке (раздел «Ресурсы»), а не по задачам, над которыми он
работал. Пункт «Без группы» показывает тех, кого ещё не приписали.

Утверждённый квартал сужается так же: снимок не пересчитывается, из него просто
показываются строки выбранной группы.
