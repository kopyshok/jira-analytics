# Проекты

Раздел «Проекты» — проекты квартала команды: слева список, справа — сводка портфеля (пока проект не выбран) или карточка выбранного проекта в одном из трёх видов: «Анализ», «Презентация», «План и сроки». Здесь PM смотрит, что сделано по проекту, укладывается ли он в план по этапам, читает короткое ИИ-резюме и при необходимости готовит одностраничник для встречи или отчёта.

---

## 1. Зачем раздел

Дашборд и Аналитика показывают цифры по всей команде, по сотрудникам и по периодам. Но руководству и заказчику нужна не «средняя температура», а ответ по конкретному проекту: что мы делали, к какому результату пришли, кто вложился, укладываемся ли в план и сроки, как заказчик оценил. Эта страница собирает по каждому проекту единый паспорт — цели, ход работы, часы, план и сроки по этапам, оценки заказчика и короткое резюме от ИИ. А сводка портфеля показывает то же самое по всем проектам квартала сразу.

В список попадают задачи, включённые в утверждённый сценарий выбранного квартала для команд, выбранных в шапке приложения. Обычно это инициативы и квартальные задачи. Категория сама по себе проект в список не добавляет — только утверждённый сценарий. Остальная работа (сопровождение, техдолг, встречи) сюда не попадает — она живёт в Дашборде, Аналитике и других разделах.

## 2. Когда сюда заходить

- Перед встречей с руководством по проекту — посмотреть статус, резюме и топ-задачи.
- Перед планёркой по кварталу — открыть «Сводку»: какие проекты перерасходуют план, какой этап отстаёт, кто молчит.
- Чтобы проверить план по этапам и сроки фаз конкретного проекта — вид «План и сроки».
- Перед встречей с заказчиком — открыть «Презентацию», распечатать или сохранить картинкой.
- Когда нужно понять, как загружены сотрудники именно по этому проекту (а не вообще по кварталу).
- Когда заказчик прислал оценку — проверить, что она подтянулась из Jira.
- Когда хочется быстро вспомнить, чем закончился проект прошлого квартала (выбрать тот квартал, фильтр «Архив»).
- Когда из Дашборда, Аналитики или Целевых задач кликнули на проект — попадаем сюда.

## 3. Элементы интерфейса

Раздел построен по схеме «список слева — сводка или карточка справа». Список фильтруется по году, кварталу, статусу и категории; карточка переключается между тремя видами.

### 3.1. Список проектов слева

| Элемент | Что делает |
|---------|-----------|
| Проекты N | Заголовок списка и число проектов в нём. |
| Сводка | Открывает справа сводку портфеля по проектам из списка. Подсвечена, пока открыта сводка. |
| Год | Меняет год. По умолчанию — текущий. Не связан с периодом в шапке приложения. |
| Q1 / Q2 / Q3 / Q4 | Бирюзовая плашка — выбранный квартал. По умолчанию — текущий. |
| Поиск | «Поиск по названию или ключу». Срабатывает через 0,3 сек после ввода, чтобы не дёргать сервер на каждом нажатии. |
| Статус | «Все» / «В работе» / «Готов». Срез по статусу проекта в Jira. |
| Категория | «Все» / «Квартальные» / «Архив». Срез по категории задачи в системе. |

Каждая карточка проекта в списке показывает: ключ Jira, название, период «месяц–месяц» (от первого до последнего списания), часы, количество задач под проектом, количество участников, плашку статуса («Новый», «В работе», «Готов»), плашку категории и среднюю оценку заказчика (звёздочки, если заказчик что-то заполнил). Левая полоска карточки окрашена в цвет статуса (серый — новый, бирюзовый — в работе, зелёный — готов). Выбранная карточка подсвечена бирюзовой рамкой.

Клик по карточке открывает карточку проекта справа и обновляет адрес страницы — ссылку можно скопировать и переслать. Повторный клик по уже выбранной карточке возвращает к сводке портфеля.

### 3.2. Сводка портфеля

Открывается справа, пока проект не выбран (или по кнопке «Сводка»). Считается по тем же проектам, что видны в списке слева, — с учётом года, квартала, поиска, статуса, категории и фильтра команды.

- **Верхняя полоса** — число проектов, «факт / план ч» по всему портфелю («всего факт / план», или «план не заведён»), общая «загрузка» в процентах и три кольца по этапам: «Анализ», «Разработка», «Тестирование» — процент выполнения плана и «факт / план ч». Кольцо красное, если этап перерасходовал план больше чем на 10%. Справа — плитка «Внешние» с часами сотрудников не из команды проекта (если такие часы есть).
- **Проекты портфеля** — таблица по проектам. Колонки:
  - «Проект» — название, приоритет из Целевых задач («P5»), ключ, плановые даты работ и статус.
  - «Факт / План» — часы.
  - «Загрузка» — факт к плану: >110% красный, от 70% — зелёный. По умолчанию таблица отсортирована по этой колонке, от большего к меньшему.
  - «Анализ», «Разработка», «Тестирование» — «факт / план ч», процент и полоска по каждому этапу.
  - «Внешние» — появляется, если у кого-то из проектов есть часы сотрудников не из команды проекта.

  Сортировка — кликом по заголовку любой колонки. Стрелка слева раскрывает задачи первого уровня под проектом: ключ (ссылка в Jira), название, статус, часы. Клик по строке открывает карточку проекта. Внизу — строка «Итого · N».
- **Таймлайн портфеля** — по строке на проект: цветные полосы фаз из ресурсного плана (при наведении — фаза и даты), вертикальная линия «сегодня», затенены границы квартала. Клик по названию проекта открывает его карточку. Если плановых дат нет — «Нет плановых дат».
- **Подсказки** внизу — короткие сигналы «куда смотреть»: «N проектов > 100% плана», «N проектов без списаний 14+ дней» (проекты, по которым ещё не начинали списывать, не считаются), «Этап отстаёт: X% при Y% общей» (когда этап отстаёт от общей загрузки больше чем на 15 процентных пунктов).

### 3.3. Шапка карточки проекта

Сверху карточки — закреплённая шапка с названием проекта, ключом-ссылкой на Jira, периодом (от первого до последнего списания), статусом и подписью «AI-резюме обновлено …». Здесь же кнопки:

| Кнопка | Что делает |
|--------|-----------|
| Анализ / Презентация / План и сроки | Переключает вид карточки (см. 3.4–3.6). |
| Обновить AI | Перегенерирует ИИ-резюме именно по этому проекту прямо сейчас. Если ИИ выключен администратором — кнопка серая, при наведении подсказка «ИИ выключен администратором». |
| PNG | Сохраняет вид «Презентация» картинкой. Если открыт другой вид, страница сама переключится на «Презентацию», подождёт прорисовку и сохранит файл «КЛЮЧ_ГГГГММДД.png» в загрузки. |
| ⋯ | Меню с пунктом «Копировать ссылку». Надёжный способ поделиться проектом — скопировать адрес из адресной строки браузера: в нём уже записаны проект и открытый вид. |

### 3.4. Вид «Анализ» (по умолчанию)

Аналитический вид — две колонки карточек. Считается по проекту целиком: все задачи под ним, все участники, за всё время.

Левая колонка:
- **Цели проекта** — короткие пункты из ИИ-резюме. Если резюме ещё нет, показывается фрагмент описания из Jira.
- **Структура трудозатрат** — диаграмма-«бублик». Если у проекта есть ИИ-резюме — по группам работ (анализ, разработка, тестирование, ОПЭ), иначе — по категориям задач внутри проекта. В центре — общая сумма часов и «~N нед» — сколько недель прошло от первого до последнего списания. Справа — легенда: название группы, часы и доля. В режиме категорий клик по категории (на диаграмме или в легенде) открывает Аналитику с фильтром по этой категории.
- **Участники** — список сотрудников с часами, долей и полоской. Клик по сотруднику открывает Аналитику с фильтром по этому человеку.

Правая колонка:
- **Основной результат** — чек-лист от ИИ: что считается сделанным (зелёная галочка), что ещё нет, и под ним — короткий вывод ИИ.
- **Статус проекта** — тот же вывод ИИ и четыре плитки: «Задач», «Часов», «Участников», «Недель».
- **Оценка заказчика** — звёздочки и число из 5 по трём измерениям: Качество, Скорость, Результат (показываются заполненные), под ними — комментарий ИИ о трудозатратах. Если в Jira ничего не заполнено — подпись «Оценка заказчика появится после заполнения полей в Jira».
- **Топ-3 задачи по трудозатратам** — три задачи с наибольшими часами: ключ, название, часы. Клик по задаче открывает Аналитику.

### 3.5. Вид «Презентация»

Тот же проект, но одной длинной страницей в виде сторителлинга — для печати или для встречи. Сверху — заголовок: «Проект КЛЮЧ», название, период, статус и три крупные плитки «Часов» (с «~N нед»), «Задач», «Участников». Дальше строго по разделам:

1. **Что мы делали** — пронумерованные цели + фрагмент описания из Jira.
2. **Какой результат** — чек-лист ✓/○ + вывод ИИ.
3. **Кто работал** — горизонтальные полоски с часами и процентами по сотрудникам.
4. **На что ушло время** — крупный «бублик» с легендой и список «Топ-3 задачи».
5. **Как оценили** — три блока со звёздочками: Качество, Скорость, Результат, и комментарий ИИ.

Пока ИИ-резюме нет, вместо целей и результата стоят заглушки «AI-цели генерируются...» и «AI генерирует основной результат...».

Этот вид специально свёрстан в одну колонку шириной до 960 пикселей — подходит и для печати, и для PNG.

### 3.6. Вид «План и сроки»

План и факт проекта по этапам и сроки фаз. Считается для квартала, выбранного в списке слева.

- **Верхняя полоса** — «факт / план ч» по проекту («всего факт / план», или «план не заведён»), «загрузка» в процентах, кольца «Анализ», «Разработка», «Тестирование» (красное — перерасход больше 10%) и плитка «Внешние» — часы сотрудников не из команды проекта, они не входят ни в план, ни в факт.
- **Таймлайн проекта** — по строке на каждую фазу ресурсного плана (Анализ, Консультация, Разработка, Тестирование, ОПЭ). При наведении на полосу — даты фазы. Затенены границы выбранного квартала, вертикальная линия — сегодня. Если фаз с датами нет — «Нет плановых дат».
- **Задачи проекта · N** — задачи первого уровня под проектом: «Ключ» (ссылка в Jira), «Название», «Статус», «Часы» (вместе со всеми подзадачами, до конца квартала; колонку можно сортировать).

### 3.7. Справка

Справка открывается кнопкой «?» в шапке приложения. Эта страница справки подключается, когда открыта карточка проекта.

## 4. Откуда цифры

- **Список проектов** — задачи, включённые в утверждённые сценарии выбранного года и квартала. Сценарии берутся для команд из шапки приложения; если команда не выбрана — все утверждённые сценарии квартала. Нет утверждённого сценария — список пуст.
- **Год и квартал** — выбираются в шапке списка, отдельно от периода в шапке приложения.
- **Цифры в карточках списка** — все списания по проекту и всем задачам под ним, за всё время, всеми сотрудниками. Фильтр команды на них не влияет (кроме деления на группы, см. раздел 9).
- **Виды «Анализ» и «Презентация»** — тоже проект целиком: все задачи под ним, все участники, за всё время. Ни фильтр команды, ни квартал здесь цифры не режут.
- **План и сроки, сводка портфеля.** План — плановые часы фаз проекта из действующего ресурсного плана каждого квартала, в котором проект планировался; если у фазы часы не распределены — берётся оценка роли из Целевых задач. План ОПЭ раскладывается между Анализом и Разработкой по коэффициенту, заданному у целевой задачи (по умолчанию пополам). Факт — все списания по проекту до конца выбранного квартала, разложенные по роли автора (часы руководителя проекта идут в Анализ). В факт идут только аналитики, разработчики и руководители проектов из команды проекта — за дни участия в ней, — и тестировщики (общий ресурс); остальные часы уходят во «Внешние». Команда проекта — из поля «Команда» задачи, а если оно пустое — команда ресурсного плана.
- **Цели проекта, основной результат, статус, группы работ** — это ИИ-резюме. Оно обновляется автоматически каждую ночь (около 3:00) — только у задач с категорией квартальных задач или их архива и только если резюме ещё нет или по проекту появились новые списания. Кнопка «Перегенерировать все саммари» в Настройки → AI запускает это же обновление сразу. Для одного проекта — кнопка «Обновить AI» в шапке проекта (работает для любого проекта, без условий). Если ИИ выключен — новых резюме не будет, показывается последнее сохранённое.
- **Какой провайдер ИИ работает** — выбирается админом в Настройки → AI. Резюме обновляются тем провайдером и моделью, которые там стоят на момент запуска.
- **Оценка заказчика** — три отдельных поля Jira (качество, скорость, результат), заполняются заказчиком в его задаче. Раздел показывает их «как есть», ничего не пересчитывая.
- **Описание проекта** — берётся из поля «Описание» в Jira (в «Анализе» — первые ~600 символов, в «Презентации» — ~800).
- **Топ-3 задачи** — три задачи проекта с самой большой суммой списаний за всё время.

Все цифры обновляются только после синхронизации с Jira. Если в Jira что-то поменялось, а синхронизации не было — здесь это пока не увидим.

## 5. Типовые задачи

### Сценарий А: проверить статус по проекту перед встречей

1. Открыть «Проекты», выбрать год и квартал.
2. В поиске или в списке найти нужный проект, кликнуть на карточку.
3. В виде «Анализ» прочитать «Основной результат» и «Статус проекта» справа.
4. Посмотреть «Цели проекта» и «Структуру трудозатрат» слева — понять, на что реально тратилось время.
5. Если ИИ-резюме старое (по подписи «AI-резюме обновлено …») — нажать «Обновить AI» и дождаться сообщения «AI-резюме обновлено».

### Сценарий Б: распечатать одностраничник для заказчика

1. Открыть карточку проекта.
2. В шапке справа переключиться на «Презентацию» (или сразу нажать «PNG» — она это сделает за вас).
3. «PNG» — сохранится файл с именем «КЛЮЧ_ГГГГММДД.png». Готово, можно вставлять в письмо или отчёт.
4. Если нужна распечатка — открыть «Презентацию» и распечатать страницу средствами браузера (Ctrl + P). Презентация специально свёрстана узкой колонкой, чтобы помещалась на лист.

### Сценарий В: понять, почему ИИ дал такой вывод

1. В виде «Анализ» сравнить ИИ-цели с описанием проекта в Jira.
2. Сравнить чек-лист «Основной результат» с реальными статусами задач (вид «План и сроки» → «Задачи проекта»).
3. Если резюме явно расходится с фактами — нажать «Обновить AI» в шапке проекта. Свежий запуск возьмёт текущее состояние задач и описаний.
4. Если и после этого ИИ говорит ерунду — проверить в Настройки → AI, какой провайдер и модель работают, и нет ли в описании проекта/задач устаревшего текста, который сбивает ИИ.

### Сценарий Г: отметить новые риски

1. Открыть проект → «Анализ» → «Статус проекта» — здесь ИИ может прямо сказать, что проект «под риском».
2. Переключиться на «План и сроки»: красное кольцо этапа — перерасход, полосы фаз за линией «сегодня» — где проект должен быть сейчас.
3. Если в Топ-3 или в задачах проекта висят открытые задачи без движения — это сигнал.
4. Договориться с заказчиком о решении. После того как ситуация изменится в Jira, нажать «Обновить AI» — резюме перегенерируется уже с новыми вводными.

### Сценарий Д: обзор портфеля квартала

1. Открыть «Проекты», выбрать квартал; справа сразу открыта «Сводка» (если нет — кнопка «Сводка»).
2. Посмотреть кольца этапов и подсказки внизу: сколько проектов больше 100% плана, какой этап отстаёт, кто молчит.
3. В таблице «Проекты портфеля» сверху — самые загруженные проекты; стрелкой раскрыть задачи, кликом по строке — открыть карточку.
4. В «Таймлайне портфеля» проверить, чьи фазы вылезают за границы квартала.

## 6. Ограничения

- В списке видны **только** задачи из утверждённых сценариев выбранного квартала. Если проекта нет в списке — почти всегда дело в том, что сценарий не утверждён или задача в нём не включена.
- Год и квартал списка **не связаны** с периодом в шапке приложения, а фильтры по году/кварталу/статусу/категории и поиск **не сохраняются** между сессиями — при каждом входе стоит текущий квартал.
- Выбранный вид (Анализ / Презентация / План и сроки) **сохраняется в адресе страницы** — ссылка на «Презентацию» приведёт нового пользователя сразу в режим презентации. При выборе другого проекта вид сбрасывается на «Анализ».
- Карточки списка, «Анализ» и «Презентация» показывают проект **целиком** — за всё время, всеми сотрудниками. План и факт по кварталу — только в «Плане и сроках» и в сводке.
- ИИ-резюме показывает то, что было сгенерировано последний раз. Если ИИ выключен или провайдер не отвечает, новые резюме не появятся — будет видно старое. Ночное обновление не трогает проекты без категории квартальных задач — их резюме обновляется только вручную.
- «PNG» рендерит только вид «Презентация». Из другого вида кнопка сначала автоматически переключит на «Презентацию», подождёт прорисовку и потом сохранит файл.
- «Оценка заказчика» — это **показ как есть** из трёх полей Jira. Если заказчик не заполнил — показывается подпись о незаполненных полях. Раздел сам ничего не считает и не усредняет (кроме звёздочек в списке слева — там среднее по заполненным, округлённое до целой звезды).
- Фильтр команды в шапке приложения определяет **набор проектов** (сценарии каких команд брать), но не режет часы внутри карточки проекта.
- При переходе в Аналитику из карточки проекта фильтр по самому проекту не переносится — переносится только сотрудник или категория, а клик по задаче из Топ-3 открывает Аналитику без фильтра. Период берётся из шапки приложения.

## 7. Частые проблемы

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Нет ИИ-резюме (Цели / Результат / Статус пустые) | ИИ выключен в Настройках, провайдер не отвечает, или резюме по проекту ещё ни разу не создавалось | Настройки → AI → включить, проверить ключ и провайдера; нажать «Обновить AI» в шапке проекта |
| Резюме явно устарело (упоминает задачи, которые уже закрыты) | Резюме обновляется ночью и только если появились новые списания. Смена статусов без списаний его не обновит | Нажать «Обновить AI» в шапке проекта |
| Проекта нет в списке | Проект не включён в утверждённый сценарий этого квартала, или выбран другой квартал, или фильтр команды указывает на другую команду | Проверить год, квартал и команду в шапке; в разделе «Сценарии» — что сценарий утверждён и проект в нём включён |
| Списка проектов вообще нет («Нет проектов») | Для выбранных команд нет утверждённого сценария квартала | Утвердить сценарий в разделе «Сценарии» или выбрать другой квартал |
| «Оценка заказчика» не заполнена | Заказчик ещё не заполнил поля «Качество / Скорость / Результат» в Jira | Подождать заполнения; либо проверить в Настройки → Поля Jira, что три «оценочных» поля указаны правильно |
| Часы в карточке больше, чем в «Плане и сроках» | Карточки и «Анализ» считают проект целиком и все часы, а «План и сроки» — факт до конца квартала без «Внешних» | Норма; для сравнения с планом смотреть «План и сроки» |
| В «Плане и сроках» — «план не заведён» и «Нет плановых дат» | Проект не распределён в ресурсном плане ни одного квартала | Раздел «Ресурсное планирование» → распределить утверждённый сценарий |
| Много часов во «Внешних» | Списывали сотрудники не из команды проекта, или у проекта не указана команда в Jira | Проверить поле «Команда» у задачи в Jira и состав команды в «Ресурсах» |
| «PNG» сохранил пустую или обрезанную картинку | Страница не успела прорисоваться | Открыть «Презентацию» вручную, подождать пару секунд, ещё раз нажать «PNG» |
| Кнопка «Обновить AI» серая | ИИ выключен администратором в Настройках | Настройки → AI → включить |
| После «Обновить AI» появилось сообщение «Регенерация не удалась: …» | Провайдер ИИ не ответил, исчерпан лимит или модель недоступна — причина написана в сообщении | Подождать минуту и повторить; при повторе — сменить модель в Настройки → AI |

## 8. Связанные разделы

**Откуда приходят данные:**
- **Синхронизация** — без свежей синхронизации задачи, ворклоги и оценки заказчика не обновятся.
- **Сценарии** — утверждённый сценарий квартала определяет, какие проекты вообще попадают в раздел.
- **Ресурсное планирование** — плановые часы и даты фаз для «Плана и сроков» и сводки портфеля.
- **Целевые задачи** — приоритет проекта, оценки ролей (если в плане часы не распределены) и деление ОПЭ.
- **Категории задач** — категория проекта для фильтра «Квартальные / Архив» и для ночного обновления ИИ-резюме.
- **Настройки → Проекты в scope** — какие проекты Jira синхронизируются.
- **Настройки → Поля Jira** — какие поля Jira считаются «оценками заказчика».
- **Настройки → AI** — провайдер и модель ИИ, общий «выключатель» резюме, перегенерация всех резюме.
- **Глобальный фильтр команды** (в шапке приложения) — чьи утверждённые сценарии брать.

**Куда уходит результат:**
- **Дашборд** — виджет «Проекты квартала» показывает те же проекты утверждённого сценария; клик по строке ведёт сюда.
- **Аналитика** — клик по сотруднику, категории или задаче из карточки проекта открывает Аналитику; в Аналитике у строк проектов есть кнопка «Открыть страницу проекта».
- **Целевые задачи** — кнопка «Открыть страницу проекта» у задач с ключом Jira.
- **Сводка для руководителя** — показатели верхнего уровня по квартальным проектам.
- **Презентация / печать** — PNG-картинка или печать страницы — для встреч и отчётов руководству / заказчику.

## 9. Группы внутри команды

Если команда разделена на группы, второй уровень фильтра в шапке оставляет в
списке только те проекты, под которыми есть работы выбранной группы. Часы,
задачи и участники в карточках списка при этом считаются тоже по её работам.
Сводка портфеля и карточка проекта справа показывают проекты целиком.

Инициатива заводится одна на всю команду, деление проходит ниже — по задачам.
Поэтому инициатива, под которой группы ещё никому не проставили, при выборе
конкретной группы из списка уходит. Чтобы увидеть такие проекты, отметьте в
фильтре пункт «Без группы» или снимите выбор групп.
