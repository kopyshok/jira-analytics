# Дашборд руководителя

Раздел «Сводка для руководителя» (меню «Обзор», заголовок страницы «Executive dashboard сопровождения 1С») — обзор квартала на одной странице: четыре показателя верхнего уровня, ИИ-сводка из трёх блоков, недельные тренды, риски и загрузка ролей. Не подменяет Аналитику или Ресурсы, а собирает короткую выжимку «на что смотреть в первую очередь».

---

## 1. Зачем раздел

Руководителю не нужно каждый раз заходить в Аналитику, Ресурсы и Сценарии по отдельности. Дашборд руководителя отвечает на четыре вопроса:

1. **Как мы себя чувствуем в целом?** — индекс здоровья.
2. **Хватает ли людей?** — загрузка по ролям.
3. **Что горит?** — критичные задачи и риски.
4. **Идём ли по плану?** — выполнение сценария квартала.

Сверху четыре числа, ниже — ИИ-сводка «что улучшилось / где риск / что делать», ещё ниже — графики и список рисков. Заходишь на пять минут, понимаешь картину, решаешь, куда углубиться.

---

## 2. Когда сюда заходить

- Утром понедельника — обзор квартала на текущий момент.
- Перед встречей с руководством — быстрая выжимка по кварталу.
- Когда в Аналитике или Ресурсах всплыла подозрительная цифра — посмотреть, видна ли она на верхнем уровне.
- Когда нужно показать кому-то «как у нас дела», а времени на пересказ нет.

Раздел не для ежечасного мониторинга. Это снимок, который собирается по кнопке.

---

## 3. Элементы интерфейса

| № | Блок | Что показывает |
|---|------|----------------|
| 1 | Шапка | Заголовок, строка «AI-сводка обновлена …» с датой и временем сборки и кнопка «Построить» / «Пересчитать» |
| 2 | Фильтр команд (в шапке приложения) | По каким командам собирается дашборд |
| 3 | Период (в шапке приложения) | Год и квартал; выбранный месяц дашборд не учитывает |
| 4 | Четыре карточки | «Индекс здоровья», «Загрузка ресурса», «Критичные риски», «Выполнение сценария» |
| 5 | «AI-сводка» | Три плашки: «Что улучшилось», «Где риск», «Что делать» |
| 6 | «Тренд здоровья (8 недель)» | Индекс по неделям за последние 8 недель квартала |
| 7 | «Здоровье модулей» | Разрез по командам задач: маркер здоровья, риск, условная нагрузка |
| 8 | «Очередь по типам» | Открытые задачи по типам и приоритетам |
| 9 | «План / факт по ролям» | План сценария и факт по ролям за квартал |
| 10 | «Часы по типам (8 недель)» | Недельные часы по типам задач |
| 11 | «Топ рисков» | До пяти задач-рисков с уровнем, эффектом, ответственным и действием |
| 12 | «Загрузка по ролям» | Полоски загрузки по каждой роли |

### 3.1. Кнопка «Построить» / «Пересчитать»

Дашборд не строится сам. Для каждой пары «квартал + набор команд» его нужно один раз собрать: пока сборки нет, на странице написано «Нажмите «Построить» для генерации сводки за 2026Q3» и кнопка «Построить». Дальше при заходе показывается сохранённая сборка, а за свежими цифрами — «Пересчитать».

Сборка — одно действие: цифры и ИИ-сводка считаются вместе, обычно за несколько секунд (дольше, если модель ИИ отвечает медленно). По окончании — уведомление «Дашборд обновлён», дата в шапке меняется. При ошибке — «Не удалось построить: …».

Сборка общая: её видят все пользователи с тем же кварталом и тем же набором команд в шапке.

Если ИИ выключен администратором, кнопка неактивна (подсказка «ИИ выключен администратором»): пересобрать нельзя ни сводку, ни цифры. Над сводкой появляется синяя плашка «ИИ выключен администратором — AI-сводка не обновляется» — показаны последние собранные данные.

### 3.2. Четыре карточки

| Карточка | Что считаем | Зелёная | Жёлтая | Красная |
|----------|-------------|---------|--------|---------|
| **«Индекс здоровья»** (N/100) | Сводный балл из критичности, возраста задач, выполнения плана и перегруза (см. раздел 4) | 80 и выше | 60–79 | ниже 60 |
| **«Загрузка ресурса»** | Средняя загрузка по пяти ролям за квартал | 70–100% | ниже 70% | выше 100% |
| **«Критичные риски»** | Открытые задачи с приоритетом Critical, Highest или Blocker | 0 | 1–3 | 4 и больше |
| **«Выполнение сценария»** | Факт / план сценария квартала по ролям | 90% и выше | 70–89% | ниже 70% |

Под числом на каждой карточке — короткое пояснение: «Сводный показатель по критичности, возрасту, плану и нагрузке», «Средняя по ролям за квартал», «Открытые задачи Critical / Highest / Blocker», «Факт / план по утверждённому сценарию».

Загрузка каждой роли ограничена 100%, поэтому карточка «Загрузка ресурса» красной не бывает (см. раздел 6).

### 3.3. ИИ-сводка

Под карточками — подпись «AI-сводка» и три плашки:
- **«Что улучшилось»** (зелёная);
- **«Где риск»** (жёлтая);
- **«Что делать»** (серая).

Текст пишет языковая модель по цифрам со всей страницы. Если модель не ответила, рядом с подписью появляется метка «fallback», а в плашках — шаблонный текст: «Индекс здоровья: N/100. AI-сводка недоступна.», «Критичных рисков: N.», «Просмотрите блоки дашборда вручную.». Если в настройках не выбран провайдер ИИ — «Провайдер LLM не настроен.», «AI-сводка недоступна.», «Настройте провайдер в /settings.».

### 3.4. Тренд здоровья (8 недель)

График-заливка из восьми точек «W1» … «W8» — недели, отсчитанные назад от последнего дня квартала. В каждой точке — упрощённый индекс: доля некритичных задач среди задач, на которые списывали часы в эту неделю (100 — критичных нет). План и загрузка в тренд не входят.

Для текущего квартала последние недели ещё в будущем: задач в них нет, и точки стоят на 100.

### 3.5. Здоровье модулей

Не функциональные модули, а **команды задач** (команда из карточки задачи в Jira), до восьми штук с наибольшей нагрузкой. По каждой:
- цветная точка — здоровье: красная, если критичных открытых задач 5% и больше, жёлтая — от 2%, иначе зелёная;
- название и заметка «N задач, M критичных»;
- риск текстом — «Высокий», «Средний» или «Низкий»;
- полоска «нагрузки» — условная величина: часы сотрудников команды за квартал в расчёте на одну задачу команды; 20 часов на задачу и больше — это 100%.

### 3.6. Очередь по типам

Горизонтальные столбики по открытым задачам квартала, разложенным по типам:
- «Инциденты» — типы Bug, Incident;
- «Доработки» — Story, Improvement, Task;
- «Консультации» — Question, Consultation;
- «Регламент» — Sub-task, Regulatory.

Каждый столбик делится на «Критичные» (приоритеты Critical, Highest, Blocker), «Высокие» (High, Major) и «Обычные» (остальные). Типы и приоритеты узнаются только по этим английским названиям Jira (см. раздел 6).

### 3.7. План / факт по ролям

Парные столбики «План» (светлый) и «Факт» (тёмный) по строкам «Аналитики», «Консультанты», «Разработка», «QA», «Архитектор/тимлид» и «ОПЭ (фаза)».

- **План** — оценки задач, включённых в сценарий квартала, по этапам (анализ, разработка, тестирование, ОПЭ) с учётом коэффициента вовлечённости. У консультантов и архитекторов плана нет.
- **Факт** — часы, списанные в квартале прямо на задачи сценария, разложенные по роли сотрудника. Часы на подзадачах этих задач сюда не входят.
- **«ОПЭ (фаза)»** — это этап, а не роль: у него только план, факт всегда 0 (эти часы списывают аналитики и разработчики). Если в «Настройки → Планирование» ОПЭ отключён с этого квартала, строки нет, а часы ОПЭ уже влиты в план аналитиков и разработки.

### 3.8. Часы по типам (8 недель)

Стек-диаграмма недельных часов по типам задач за те же 8 недель, подписи — даты начала недель. Слои: «Инциденты», «Доработки», «Консультации», «Регламент». В «Регламент» попадают все часы, чей тип задачи не распознан как инцидент, доработка или консультация.

### 3.9. Топ рисков

До пяти плашек с цветной полоской слева:
- заголовок — ключ задачи и служебное обозначение признака: «high_hours» — много часов, «many_workers» — много исполнителей, «stale» — долго в работе;
- эффект — например «N сотрудников · M ворклогов · D дней», «N разных сотрудников», «в работе D дней»;
- «Ответственный: Руководитель сопровождения» и предлагаемое действие;
- тег уровня — «Высокий» (много часов, долго в работе, критичная задача) или «Средний» (много исполнителей).

Риски выбираются автоматически из задач квартала: много часов (не меньше 16 и в верхних 15% по часам), больше пяти разных исполнителей, списания растянуты больше чем на 14 дней, а задача не закрыта. Если таких меньше трёх, добавляются открытые задачи с приоритетом Critical или Blocker — «критичная задача без закрытия». Если рисков нет — «Рисков не выявлено». Плашки не кликабельны.

### 3.10. Загрузка по ролям

Для пяти ролей («Аналитики», «Консультанты», «Разработка», «QA», «Архитектор/тимлид») — полоска загрузки в процентах. Цвет: бирюзовый — ниже 90%, жёлтый — 90% и выше, красный — больше 100%.

Среднее этих пяти значений — карточка «Загрузка ресурса».

## 4. Откуда цифры

- **Задачи квартала** — задачи, на которые есть списания в квартале. Если в шапке выбраны команды — задачи этих команд (основной или участвующей) и задачи, на которые списывали люди, состоявшие в этих командах в день списания. Группы внутри команды не учитываются.
- **Индекс здоровья** — сумма четырёх частей: до 35 баллов за низкую долю критичных открытых задач, до 25 — за «свежесть» (средний возраст открытых задач на конец квартала: 0 дней — полный балл, 30 дней и старше — ноль), до 20 — за выполнение сценария, до 20 — за отсутствие перегруженных ролей.
- **Загрузка роли** — средние часы на одного сотрудника роли за квартал, делённые на 520 часов (условная квартальная норма), не больше 100%. Считаются только сотрудники, списавшие часы, и только часы, списанные в дни участия в выбранных командах. Роль берётся из карточки сотрудника. Роль без сотрудников даёт 0% и тянет среднее вниз.
- **Сценарий квартала** — один сценарий на квартал из раздела «Сценарии»: последний изменённый черновик, а если черновиков нет — утверждённый. Фильтр команд на выбор сценария и на его факт не влияет.
- **Выполнение сценария** — весь факт / весь план по строкам «План / факт по ролям», не больше 100%. Нет сценария — 0%.
- **Критичные риски** — открытые задачи квартала с приоритетом Critical, Highest или Blocker.
- **ИИ-сводка** — пишется при каждой сборке по всем цифрам страницы.
- **Период** — квартал из шапки; тренды — 8 недель, заканчивающихся последним днём квартала.

## 5. Типовые задачи

### Сценарий А: понедельничный обзор

1. Открыть «Сводку для руководителя».
2. Проверить в шапке квартал и команды.
3. Если дата «AI-сводка обновлена» старая — «Пересчитать».
4. Посмотреть четыре карточки: что-то в красном или жёлтом?
5. Прочитать ИИ-сводку: «Что улучшилось» — отметить команде; «Где риск» — на повестку.
6. По тренду здоровья — растём, падаем, плато?
7. «Топ рисков» — внести 1–2 пункта в обзор недели.

### Сценарий Б: подготовка к встрече с руководством

1. Выбрать в шапке отчётный квартал.
2. Нажать «Пересчитать», дождаться «Дашборд обновлён».
3. Сделать скриншоты: ряд карточек — слайд «Состояние»; «План / факт по ролям» — слайд «Загрузка»; «Топ рисков» — слайд «Что мешает».
4. Скопировать текст плашки «Что делать» — готовая выжимка решений.
5. Детали по конкретной цифре — в Аналитике с тем же периодом и командами.

### Сценарий В: разобраться с загрузкой

1. Карточка «Загрузка ресурса» жёлтая (ниже 70%).
2. Спуститься к «Загрузке по ролям» — какая роль тянет вниз. Роль без сотрудников в команде показывает 0%.
3. Перейти в «Ресурсы» с тем же кварталом и командой — посмотреть план и факт по людям.
4. При необходимости — в «Ресурс. планир.» перераспределить нагрузку.

### Сценарий Г: разобраться с рисками

1. Спуститься к «Топ рисков» — прочитать ключи задач, эффект и уровень.
2. Скопировать ключ задачи и найти её в Аналитике фильтром «Поиск задачи» — видно, кто и сколько списал.
3. По итогам — назначить действия в Jira; на следующей сборке список должен измениться.

## 6. Ограничения

- **Дашборд не строится сам.** Каждый заход — чтение сохранённой сборки. Свежие цифры — только после «Пересчитать». Автоматической сборки по расписанию нет.
- **Без ИИ дашборд не пересобрать** — при выключенном ИИ недоступны и цифры, и сводка.
- **Месяц и группы из шапки не учитываются** — дашборд всегда по кварталу и командам целиком.
- **Названия из Jira узнаются только английские.** Закрытой считается только задача в статусе с названием «Done»: статусы «Готово», «Отменено» и другие русские названия дашборд считает открытыми. Приоритеты — Critical, Highest, Blocker, High, Major; русский «Блокер» критичным не считается. Типы задач — Bug, Incident, Story, Improvement, Task, Question, Consultation, Sub-task, Regulatory; задачи с русскими типами («Задача», «Баг», «Подзадача») в очередь не попадают, а их часы уходят в слой «Регламент». Из-за этого «Критичные риски» и «Очередь по типам» могут показывать нули, а «Топ рисков» — давно закрытые задачи.
- **Загрузка ограничена 100%** на каждую роль — перегруз на дашборде не виден, красного цвета у «Загрузки ресурса» не бывает. Норма — фиксированные 520 часов на квартал без учёта отпусков и календаря; в незавершённом квартале загрузка заведомо ниже.
- **Сценарий один на квартал** и выбирается без учёта команды; черновик приоритетнее утверждённого.
- **Факт по сценарию** — только часы прямо на задачах сценария, без подзадач.
- **Тренды — 8 недель** от конца квартала, окно не настраивается.
- **Пороги** здоровья модулей и уровней риска зашиты в сервис и из интерфейса не меняются.
- **Роли «Архитектор/тимлид»** в справочнике ролей может не быть — тогда строка всегда пустая.

## 7. Частые проблемы

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Кнопка «Построить» / «Пересчитать» неактивна, синяя плашка «ИИ выключен администратором» | ИИ выключен в «Настройки → AI» | Попросить администратора включить ИИ, затем «Пересчитать» |
| Вместо дашборда «Нажмите «Построить» для генерации сводки за …» | Для этого квартала и набора команд сборки ещё нет | Нажать «Построить» |
| Сменил команды в шапке — дашборд пропал | Сборка хранится отдельно для каждого набора команд | «Построить» для нового набора |
| Метка «fallback» в ИИ-сводке | Модель ИИ не ответила или провайдер не настроен | «Пересчитать»; если повторяется — проверить провайдера в «Настройки → AI» |
| «Выполнение сценария» = 0% | В квартале нет сценария или у задач сценария нет оценок | Проверить сценарий квартала в «Сценариях» |
| Цифры не сходятся с Аналитикой | Другой способ подсчёта: условная норма 520 часов, факт сценария только по задачам сценария, свой набор задач | Для точных часов пользоваться Аналитикой и Ресурсами |
| «Критичные риски» = 0 и пустая «Очередь по типам», хотя критичные задачи есть | Приоритеты и типы задач в Jira названы по-русски | Ограничение дашборда (раздел 6); критичные задачи смотреть в Аналитике |
| В «Топе рисков» закрытые задачи | Статус закрытия назван не «Done» | Ограничение дашборда (раздел 6) |
| «Загрузка ресурса» низкая в середине квартала | Норма считается на полный квартал | Сравнивать в конце квартала или смотреть загрузку в «Ресурсах» |
| Тренд здоровья прыгает | В разные недели на задачи списывали очень по-разному; большая перезагрузка ворклогов изменила историю | Проверить, не было ли полной перезагрузки ворклогов |
| Долго висит «Пересчитать» | Модель ИИ отвечает медленно | Подождать; если падает с ошибкой — проверить настройки провайдера в «Настройки → AI» |

## 8. Связанные разделы

**Откуда приходят данные:**
- **Синхронизация** — без свежих ворклогов и задач дашборд показывает старое.
- **Сценарии** и **Целевые задачи** — сценарий квартала и оценки задач по этапам для «План / факт по ролям».
- **Ресурсы** — роли сотрудников.
- **Настройки → Команды и группы** — состав команд и периоды участия.
- **Настройки → Планирование** — отключение ОПЭ с квартала.
- **Настройки → AI** — включает и выключает ИИ, выбирает провайдера и модель.
- **Фильтр команд и период** в шапке приложения.

**Куда уходит результат:**
- Дальше дашборд данные не отдаёт — это конечная точка для руководителя.
- ИИ-сводку можно скопировать в отчёт или письмо.

Дашборд — вершина пирамиды: всё, что показано тут, рождается в других разделах. Если цифра «не та» — сначала проверьте ограничения из раздела 6, затем источник данных.
