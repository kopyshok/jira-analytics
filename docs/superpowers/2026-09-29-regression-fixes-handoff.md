## Что исправить

### 1. «Целевые задачи»: колонка «Идея» схлопывается — важность высокая

- **Симптом:** `/backlog`, вкладки «Активные»/«Бэклог», любая команда и тема: заголовок «ИДЕЯ» и названия идей — по одной букве в столбик, строки аномально высокие. Скриншоты: `bugs/backlog-idea-column-full.png`, `bugs/backlog-idea-column-buh.png`.
- **Причина:** в `frontend/src/pages/BacklogPage.tsx` у колонки `title` («Идея», ~стр. 349) нет `width`, у всех соседних есть. Сумма ширин остальных колонок (~1730 px) больше `scroll={{ x: 1400 }}` (~стр. 1026, 1042, 1116), и Ant Design отдаёт «Идее» 0 px. Вероятно, регрессия от `4319b08e` (добавлены колонки «Аналитик» и «Разработчик» — ширина таблицы выросла, а `scroll.x` остался 1400).
- **Исправление:** задать «Идее» ширину (ориентир 320–380 px, как было до регрессии по ощущению — сверь с историей файла) и привести `scroll.x` в соответствие с суммой колонок (или `'max-content'`) во всех таблицах страницы, включая группировку по кварталам (`scroll={{ x: true }}`, ~стр. 984, 1011, 1104) и «Архив».
- **Готово, когда:** на 1600×1000 и 1280×800, во вкладках «Активные», «Бэклог», «Архив» и с «Группировать по кварталам» названия читаются в строку; закреплённые слева/справа колонки не наезжают. Сверь, что таблица идей в «Сценариях» (там тоже есть «Аналитик»/«Разработчик») не страдает.

### 2. Нет пометки «работа на соседнюю группу» у задачи через дату перевода — важность средняя

- **Симптом:** Бухгалтерия, план Q4. Сотруднику с назначением 02.10–13.11 записать перевод в другую группу с 20.10 (или 01.11) → «Распределить». Полоска после даты перевода обычная, подсказки нет, в ответе диаграммы `other_subgroup = false`. Пометка появляется только у назначений, целиком начинающихся после перевода. Скриншоты: `bugs/other-subgroup-*.png`, `bugs/other-subgroup-gantt-after.json`.
- **Ожидание (план тестирования, T03-03):** «полоски этих задач после X с пунктирной фиолетовой рамкой, в подсказке „работа на соседнюю группу“; нового конфликта нет».
- **Причина:** `_other_subgroup_ids` (`app/api/endpoints/resource_planning.py`, ~стр. 406) сравнивает группу работы с объединением всех групп сотрудника за весь период назначения (`groups_between`, `app/services/subgroup_shares.py`). Если назначение захватывает хоть день до перевода, старая группа попадает в объединение — пометки нет нигде.
- **Исправление (рекомендуемый вариант — пометка только на части полоски):**
  - бэкенд: для каждого назначения отдавать отрезки дат, где группа работы не входит в группы сотрудника (по `segments(...)` — по отрезку на запись распределения); поле, например, `other_subgroup_ranges: [{start, end}]`. Решить и явно задокументировать, что тогда означает старый `other_subgroup` (удобно: «назначение целиком вне групп» — чтобы старая логика рамки на всю полоску не поменялась);
  - интерфейс (`frontend/src/components/resource-planning/GanttRows.tsx`, ~стр. 517–535 и ~1443): поверх полоски — наложение с пунктирной фиолетовой рамкой только на эти даты; подсказка «работа на соседнюю группу с ДД.ММ» (или «… ДД.ММ–ДД.ММ»);
  - конфликты не трогать — нового конфликта быть не должно (проверено, сейчас его нет);
  - учти деление на доли: день, когда человек в двух группах, и группа работы — одна из них, — не «соседняя».
- **Тесты:** расширить `tests/test_rp_subgroup_assignment.py` (там уже есть проверки `other_subgroup`): перевод внутри назначения → отрезок только после даты; перевод до назначения → всё назначение; деление 60/40 → пометки нет.
- **Готово, когда:** сценарий из «Симптома» даёт пунктир только после даты перевода, до неё — обычная полоска; справка раздела «Ресурсное планирование» (`docs/help/resource-planning.md`, фраза про «пунктирный фиолетовый контур») описывает поведение верно — поправить текст, если нужно.

### 3. Вовлечённость 0% молча превращается в 1% — важность средняя

- **Симптом:** «Сценарии» → «Вовлечённость» → «Сотрудники» → «Добавить», ввести 0 → поле без предупреждения меняется на 1, запись сохраняется с 1%. Скриншоты: `bugs/involvement-*.png`.
- **Причина:** `frontend/src/components/planning/InvolvementDefaultsDrawer.tsx`, поле «Вовлечённость, %» (~стр. 197): `InputNumber min={1}` — Ant Design молча подтягивает значение к минимуму при потере фокуса. Бэкенд 0 уже отклоняет (`app/api/endpoints/personal_settings.py`, проверка `0 < involvement <= 1`), до него просто не доходит.
- **Исправление:** не подменять ввод молча — при 0 (и вне 1–100) показывать под полем ошибку «Вовлечённость — от 1 до 100%» и блокировать «Добавить»/«Сохранить»; пустое поле по-прежнему значит «как обычно». Проверь то же в окне редактирования записи и в блоке «По ролям команды» (~стр. 461–470) — там тот же приём.
- **Готово, когда:** ввод 0 даёт видимую ошибку и не сохраняется; 1–100 и пусто работают как раньше; тест на форму (если в проекте есть фронтовые тесты этого компонента) или e2e-сценарий.

### 4. «Справка» недоступна на «Обратной связи» и списке «Проектов» — важность низкая

- **Симптом:** значок «?» неактивен («Для этого раздела справки пока нет») на `/feedback` и на `/projects` без выбранного проекта. Скриншоты: `bugs/help-missing-*.png`.
- **Причина:** справка регистрируется хуком `useRegisterHelp(title, md)` (`frontend/src/contexts/HelpContext.tsx`), тексты — `docs/help/*.md`. `FeedbackPage` хук не вызывает, файла `docs/help/feedback.md` нет. На «Проектах» хук стоит только в `components/projects/ProjectHeader.tsx` (карточка проекта), не на самой странице списка.
- **Исправление:** написать `docs/help/feedback.md` в стиле соседних файлов (что это за раздел, «Мои обращения», «Лента идей», как отправить, что видит администратор) и зарегистрировать; для «Проектов» — регистрировать `projects.md` на уровне страницы. Попутно: «Отчёт по видам работ» (`WorkTypeReportPage.tsx`) теряет справку при выключенном ИИ — ранний `return` заглушки до `useRegisterHelp`; справка должна быть и в этом состоянии.
- **Готово, когда:** «?» активен на всех страницах из списка T12-01 плана тестирования.

### 5. «Данные обновлены из Jira», когда Jira не подключена — важность низкая (найдено при разборе)

- **Симптом:** на «Целевых задачах» «Обновить с Jira» / «Обновить только видимые» при отсутствующих данных доступа к Jira показывает «Данные обновлены из Jira», хотя в Jira не ходили.
- **Причина:** `_perform_refresh` (`app/api/endpoints/backlog.py`) при `JiraClientError` в `JiraClient.from_db` молча ставит `jira_client = None` и обновляет только локальные данные; интерфейс (`BacklogPage.tsx`, ~стр. 310) показывает успех безусловно.
- **Исправление:** вернуть в итоге признак «Jira недоступна / не настроена» и показывать предупреждение вида «Jira не подключена — обновлены только данные сервиса» вместо успеха. Проверь оба пути: обычный запрос и поток с прогрессом (`/refresh-from-jira/stream`).
- **Готово, когда:** тест на эндпоинт без кредов возвращает признак; на стенде без токена — предупреждение, с токеном — прежнее поведение.
