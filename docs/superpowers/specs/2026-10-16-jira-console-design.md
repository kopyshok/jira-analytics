# Консоль Jira и Confluence — дизайн

Дата: 2026-10-16. Ветка: `feature/jira-console`.

## Зачем

Машина разработки не видит Jira и Confluence (только из внутренней сети), а
сервер сервиса видит. Сейчас каждый вопрос к Jira — это скрипт, который
админ запускает у себя и присылает файлом. Консоль в админке даёт серверу
задать вопрос своим токеном и отдать ответ текстом: администратор вставляет
присланный пакет запросов, жмёт «Выполнить», копирует результат.

## Решения пользователя

- Вариант — консоль запросов, а не выполнение скриптов (скрипт на сервере =
  полный доступ к серверу через интерфейс).
- Системы — Jira и Confluence.
- Имена и почта — галочка «Скрыть имена и почту», по умолчанию включена.
- Доступ — только администраторы.

## Поведение

### Ввод

- Переключатель системы: Jira / Confluence.
- Текстовое поле, одна строка — один запрос. Пустые строки пропускаются.
  Строка, начинающаяся с `#`, — пояснение: не выполняется, но выводится в
  результат заголовком следующего блока.
- Строка запроса — либо полная ссылка (`https://<адрес>/rest/...`), либо путь
  от адреса системы (`/rest/...` или `rest/...`).
- Не больше 50 запросов в одном запуске (пояснения не считаются).
- Готовые кнопки дописывают строки в конец поля (не затирают введённое):

| Система | Кнопка | Строки |
|---|---|---|
| Jira | Сведения о сервере | `/rest/api/2/serverInfo` |
| Jira | Все поля | `/rest/api/2/field` |
| Jira | Задача по ключу | `/rest/api/2/issue/КЛЮЧ` |
| Jira | Списания задачи | `/rest/api/2/issue/КЛЮЧ/worklog` |
| Jira | Поиск по условию | `/rest/api/2/search?jql=project = КЛЮЧ_ПРОЕКТА&maxResults=5` |
| Jira | Диагностический пакет | `# Диагностический пакет` + serverInfo, myself, field, issuetype, status, priority, resolution, issueLinkType, project |
| Confluence | Текущий пользователь | `/rest/api/user/current` |
| Confluence | Пространства | `/rest/api/space?limit=50` |
| Confluence | Страница по номеру | `/rest/api/content/НОМЕР?expand=version,space` |

### Безопасность запроса

Проверяется до отправки, каждая строка отдельно. Отклонённая строка не
отправляется и в результате помечена «отклонено: <причина>».

- Метод — только чтение (GET). Других методов в консоли нет.
- Полная ссылка принимается, только если схема, хост и порт совпадают с
  адресом системы из настроек и путь начинается с пути адреса (у Jira может
  быть подпапка). Иначе — «ссылка ведёт не на <система>».
- Строки, начинающиеся с `//`, и строки со схемой, отличной от адреса
  системы, — отклоняются (иначе токен уйдёт на чужой сервер).
- Путь после адреса системы обязан начинаться с `rest/`; `..` в пути
  запрещено.
- Перенаправления не выполняются (ответ 3xx показывается как есть).
- Токен никогда не попадает ни в результат, ни в историю.

### Выполнение

- Запросы идут по очереди, адрес и токен — из настроек «Подключение к Jira»
  (с запасным вариантом из файла окружения, как у синхронизации) или
  «Подключение к Confluence».
- Если адрес или токен не заданы — запуск целиком отклоняется с подсказкой,
  какой раздел настроек заполнить.
- Ожидание одного ответа — до 60 с. Общий бюджет запуска — 100 с (запас до
  120 с прокси на сервере): когда бюджет вышел, оставшиеся строки помечаются
  «не выполнено — вышло общее время, запустите их отдельно».
- Ошибка одного запроса (код Jira 4xx/5xx, нет связи, тайм-аут) не
  останавливает пакет.
- Синк заблокирован переездом — консоль работает всё равно: она только читает.

### Результат

Один текст:

```
=== Jira · 2026-10-16 14:05 · имена и почта скрыты ===
Запросов: 9, с ошибкой: 1, отклонено: 0, время: 3,4 с

### 1. /rest/api/2/serverInfo
→ 200 · 0,12 с
{ ...ответ с отступами... }

# Поля
### 2. /rest/api/2/field
→ 200 · 0,40 с
[ ... ]

### 3. /rest/api/2/issue/OS-1
→ 404 · 0,05 с
{"errorMessages": ["Issue Does Not Exist"], ...}
```

- JSON-ответ выводится с отступами, не-JSON (HTML и пр.) — как текст.
- Один ответ длиннее 5 МБ (после форматирования) обрезается с пометкой
  «… обрезано, показано 5 МБ из N МБ».
- Весь результат не длиннее 10 МБ: когда предел достигнут, оставшиеся строки
  помечаются «не выполнено — результат слишком большой».
- Кнопки: «Скопировать всё» и «Скачать файлом» (`.txt`, имя
  `jira-console-ГГГГ-ММ-ДД-ЧЧММ.txt` / `confluence-console-…`).

### Скрытие имён и почты

При включённой галочке, в рамках одного запуска:

- значения полей `displayName`, `emailAddress`, `email` в любом месте ответа
  заменяются метками «Человек-1», «почта-1»; одно и то же значение получает
  одну и ту же метку во всех ответах запуска;
- собранные исходные имена и почты дополнительно заменяются в любых строках
  ответа (описания, комментарии);
- любой текст вида адреса почты (`x@y.z`) в строках заменяется меткой почты;
- логины, `key`, номера учёток и прочие поля не трогаются (нужны для сверки;
  логин может содержать фамилию — это осознанно).

Скрытие применяется до сохранения: в историю попадает уже обработанный текст.

### История

- Хранится на сервере, последние 30 запусков (старые удаляются при записи
  нового).
- Запись: кто запустил, когда, система, была ли галочка, введённый текст,
  результат, число запросов / ошибок / отклонённых, длительность.
- Список показывает: когда, кто, система, «запросов / ошибок», первую строку
  запроса. Действия: «Открыть» (поле ввода и результат заполняются из записи),
  «Удалить».
- Любой администратор видит все запуски (сервис общий).

## Где в интерфейсе

Настройки → группа служебных разделов, рядом с «Ошибки сервиса»: раздел
«Консоль Jira и Confluence», только для администраторов.

## Устройство (для разработки)

- Сервис `app/services/console_service.py`: разбор строк, проверка
  безопасности, выполнение (httpx без `base_url`, `follow_redirects=False`),
  форматирование, скрытие, бюджеты. Транспорт httpx внедряется параметром —
  для тестов.
- Модель `ConsoleRun` (`console_runs`) + миграция `dc05_console_runs`
  (самодостаточная, пропускает уже созданную таблицу).
- Эндпоинты `/admin/console`, только администратор:
  `POST /run`, `GET /runs`, `GET /runs/{id}`, `DELETE /runs/{id}`.
- Фронтенд: `frontend/src/api/console.ts`,
  `frontend/src/components/settings/JiraConsoleTab.tsx`, пункт в
  `SettingsPage.tsx`.

## Проверка

- Разбор строк: полная ссылка своего хоста — да; чужой хост, `//`, другая
  схема, `..`, путь не на `rest/` — отклонено; пояснения не считаются;
  51-й запрос — отказ всего запуска.
- Скрытие: имя и почта заменены, одинаковые значения — одна метка, вхождения
  в тексте заменены, логин и `key` не тронуты.
- Выполнение (подменённый транспорт): JSON с отступами, 404 с текстом Jira,
  не-JSON, обрезка 5 МБ, бюджет времени, нет связи, нет настроек.
- API: не-админ — 403; запуск пишет историю; хранится 30; открыть и удалить.
- Фронтенд: линтер и сборка.

## Вне объёма

- Изменяющие запросы (POST/PUT/DELETE), включая POST-поиск.
- Запуск в фоне с прогрессом — пока хватает бюджета 100 с.
- Справка раздела и видео — раздел служебный, для администратора.
