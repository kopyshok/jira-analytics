# Движение ресурсов между командами — дизайн

Дата: 2026-07-28

## Проблема

Разработчик с конкретной даты ушёл в другую команду. Ресурс команды на квартал должен уменьшиться ровно на недостающие дни.

Сейчас состав команды хранится «как есть на сегодня»: есть дата входа (учитывается только в виджете баланса часов) и нет даты выбытия. Убрать человека можно лишь удалением участия — и тогда он исчезает задним числом из всех прошлых кварталов, отчётов и утверждённых сценариев.

Вторая боль — общий сотрудник: человек, состоящий в двух командах одновременно, даёт полные часы в обе, ресурс задваивается. Утверждённого норматива деления нет: одну задачу делает в одной команде, другую в другой, по потребности.

## Решения (утверждены заказчиком)

1. Часы считаются **пропорционально дням в команде**: ушёл 15 февраля — с 15 февраля его часы в ресурс не идут. Симметрично для входа в середине квартала.
2. Даты участия влияют на **ресурсы квартала, факт и аналитику, график работ, списки сотрудников и фильтры**.
3. Утверждённый сценарий **не пересчитывается**: показываем плашку расхождения и предлагаем создать новую версию.
4. У участия может быть **несколько периодов** (ушёл — вернулся).
5. Признак «основная команда» — **на дату**, а не глобальный флаг.
6. Ввод — **в карточке сотрудника** плюс действие «Перевести в другую команду с даты».
7. Общий сотрудник: **не делим ресурс, показываем** (вариант B). Проценты заранее не выдумываем.

## Модель

### Периодизация участия

Участие сотрудника в команде получает дату окончания. Одна пара «сотрудник + команда» может иметь несколько записей — разные периоды.

- `employee_teams.left_at` (Date, nullable) — день, **начиная с которого** человек уже не в команде (граница исключающая: `joined_at <= day < left_at`).
- `joined_at = NULL` — «был всегда» (открыт слева), `left_at = NULL` — «состоит сейчас» (открыт справа).
- Уникальность `(employee_id, team)` снимается. Вместо неё сервисная проверка: периоды по одной паре «сотрудник + команда» не пересекаются.
- `is_primary` остаётся на записи. Инвариант меняется: **не более одной активной основной записи на любую дату** (проверка в сервисе; в БД по-прежнему нельзя — partial unique недоступен в SQLite).
- `Employee.team` (legacy denormalized) = основная команда **на сегодня**; пересчёт через существующий `_recompute_legacy_team` с фильтром «активно сегодня».

Отдельная таблица истории не заводится: периодизованные строки — то же самое, дешевле.

### Общий сотрудник (вариант B)

Новых полей не требуется. «Общий» = у сотрудника более одного активного участия, пересекающегося с рассматриваемым периодом. Вычисляется на лету из тех же записей.

## Единая точка расчёта состава

Новый модуль `app/services/team_membership.py` — единственный источник ответа на вопрос «кто в команде». Заменяет ~30 мест, где сейчас идёт прямой запрос по названию команды.

```
members_on(db, teams, day) -> set[employee_id]
    состав на конкретную дату

members_overlapping(db, teams, start, end) -> set[employee_id]
    все, кто хоть день пересёкся с периодом (для фактов и аналитики)

member_intervals(db, teams, start, end) -> dict[employee_id, list[(from, to)]]
    отрезки участия внутри периода — для посуточных расчётов

members_ever(db, teams) -> set[employee_id]
    все, кто когда-либо состоял (для загрузки ворклогов из Jira)

primary_team_on(db, employee_id, day) -> str | None
    основная команда на дату

shared_members(db, teams, start, end) -> dict[employee_id, list[team]]
    кто пересекается с другими командами в этом периоде
```

Все функции работают с полуинтервалом `[joined_at, left_at)`; `NULL` — открытая граница.

## Что меняется по разделам

### Ресурсы квартала и сценарии

`ResourceBaseService` уже идёт по дням квартала — добавляется проверка «день внутри периода участия», иначе день пропускается (так же, как пропускается день отсутствия). Затрагивает `compute` (посуточная матрица) и `compute_summary` (сводка по ролям, включая брутто по производственному календарю и дни отсутствий — их тоже считаем только за дни участия).

`SnapshotWriter` при утверждении сценария фиксирует состав с учётом периодов: в слепок команды попадают все, кто пересекался с кварталом, а помесячные часы считаются по дням участия.

### Факт и аналитика

Фильтр по команде для списаний становится позонным: списание попадает в команду, если сотрудник состоял в ней **в день списания**. Затрагивает `AnalyticsService`, `ExecutiveDashboardService`, `WorkTypeReportService`, `HoursBalanceService`, `work_desk_widgets`, `plan_common`, `project_plan_service`, `scenario_xlsx_export`, эндпоинты аналитики.

Списания человека после выбытия по задачам старой команды попадают в существующий разрез «помощь извне» — отдельной логики не требуется.

Списки сотрудников команды (карточки, справочники, capacity) показывают активных на сегодня; выбывшие доступны через переключатель «показывать выбывших».

### График работ (планирование ресурсов)

- Пул исполнителей плана — состав, пересекающийся с окном плана.
- Назначение на дни вне периода участия — конфликт (через существующий механизм конфликтов, новый тип: «сотрудник вне команды на эту дату»).
- Дневной кап по вовлечённости считается только за дни участия.

### Загрузка ворклогов из Jira

Employee-centric проход (bucket B) берёт `members_ever` — иначе история перестанет догружаться после выбытия.

### Утверждённые сценарии — плашка расхождения

При открытии утверждённого сценария сравниваем текущий расчёт ресурса с зафиксированным в снапшоте. Расхождение → плашка «Состав команды изменился после утверждения: −N часов» + кнопка создать новую версию (существующий flow ревизий, ничего нового).

Порог: расхождение больше 1 часа.

### Общий сотрудник — видимость

В базе ресурса и в сводке по ролям у общего сотрудника:
- пометка «делит время с командой X» (список пересекающихся команд за квартал);
- сколько часов на него уже заложено всеми командами суммарно за этот квартал (сумма по базам ресурса всех его команд);
- подсветка, если суммарно заложено больше его календарной нормы.

Дополнительно — подсказка по факту: как реально разошлись его списания по командам за **предыдущий** квартал (в процентах). Не норматив, ориентир для разговора.

Ресурс при этом **не режется**. Деление долями (вариант A) не делается; если появится утверждённое деление — доли лягут поверх этой видимости.

## Интерфейс

**Карточка сотрудника в Ресурсах.** У каждой строки команды — даты «с» и «по». История периодов раскрывается. Валидация: дата выбытия не раньше даты входа; периоды по одной команде не пересекаются.

**Действие «Перевести в другую команду».** Диалог: новая команда + дата перевода. Одним шагом закрывает текущее участие датой перевода, открывает новое с той же даты, переносит признак основной. Без дыр и нахлёстов.

**Списки и фильтры.** Выбывшие скрыты по умолчанию, переключатель «показывать выбывших» на странице Ресурсов и в справочнике сотрудников.

**Сценарий.** Плашка расхождения (см. выше). В базе ресурса — колонка/значок общего сотрудника с раскрытием деталей.

## Миграция данных

Существующие участия становятся открытыми справа периодами (дата выбытия пустая) — до ввода первой даты выбытия все цифры совпадают с текущими. Снятие уникального ограничения — batch-миграция (SQLite).

## Проверки (тесты)

- Выбытие в середине квартала → ресурс уменьшается ровно на рабочие дни после даты, с учётом производственного календаря.
- Вход в середине квартала → симметрично.
- Два периода с разрывом → считаются оба, разрыв не считается.
- Пересечение периодов по одной команде → отклоняется.
- Две активные основные на одну дату → отклоняется; перевод переносит основную корректно.
- Факт: списание до выбытия — в команде; после — нет.
- Плашка расхождения: утверждённый сценарий + выбытие → расхождение видно, слепок не изменился.
- Общий сотрудник: суммарно заложенные часы по двум командам считаются и подсвечиваются при перерасходе.
- Загрузка ворклогов: выбывший остаётся в выборке employee-centric прохода.

## Вне объёма

- Отдельный экран журнала переводов по компании.
- Деление ресурса долями/процентом ставки (вариант A).
- Автоматический пересчёт утверждённых сценариев.
- Перенос уже назначенных задач графика на других исполнителей при выбытии (только подсветка конфликта).
