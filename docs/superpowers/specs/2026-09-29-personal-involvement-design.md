# Личная вовлечённость и личные нормированные работы — дизайн

**Дата:** 2026-09-29
**Ветка:** `feature/personal-involvement` (worktree `D:\ClaudeDev\JiraAnalysis-personal`)
**Связано:** [2026-09-28-normed-works-reserve-design.md](2026-09-28-normed-works-reserve-design.md)

## 1. Зачем

Иногда сотрудника нужно полностью погрузить в разработку или анализ (вовлечённость 100%) и снять с него нормированные работы — целиком или частично. Сейчас вовлечённость задаётся справочником по роли команды и в задаче, а нормированные работы — только процентами роли в сценарии.

## 2. Решения пользователя (29.09)

| Вопрос | Решение |
|---|---|
| Что главнее | Сотрудник главнее всего: сотрудник → задача → справочник роли |
| Срок | С квартала, до следующей записи по этому сотруднику (как справочник) |
| Нормированные работы | Свои проценты по видам работ у сотрудника (или «по правилам роли») |
| Где задавать | В панели «Вовлечённость» сценариев — раздел «Сотрудники», одна строка на сотрудника и квартал |
| Сценарий | «Базовые ресурсы» и «На бэклог» учитывают личные проценты сразу |

## 3. Поведение

### 3.1 Запись сотрудника

Сотрудник, с какого квартала (год + квартал), **вовлечённость** (0–100%, необязательно; пусто — как обычно), **нормированные работы**: «по правилам роли» или «свои» — проценты по видам работ, уменьшающим запас на проекты (сумма ≤ 100%; пустой список «своих» = нормированных работ нет). Действует с указанного квартала до следующей записи этого сотрудника. Запись без вовлечённости и с «по правилам роли» возвращает общее правило. Настройка — про человека: действует в планах и сценариях любой команды.

При переключении на «свои» форма подставляет проценты правил его роли из текущего сценария — пользователь только правит.

### 3.2 Вовлечённость

Порядок: личная вовлечённость сотрудника на квартал → значение задачи → справочник команды по роли. Применяется везде, где считается вовлечённость фазы с известным исполнителем:
- раскладка фаз своего плана (дневной потолок фазы);
- брони в планах других команд (вовлечённость брони, остаток дня);
- доля дня, которую другая команда оставляет домашней в дни без её задач (сейчас — из справочника домашней команды; с личной вовлечённостью — из неё);
- «Загрузка по дням»: остаток дня после вовлечённости;
- расшифровка фазы: «Вовлечённость … · источник: сотрудник / задача / справочник команды».

Фаза без исполнителя (тестирование) — как раньше.

### 3.3 Нормированные работы

- **Запас роли** = Σ по людям роли (норма × их проценты): у кого «свои» — по ним, у остальных — по правилам роли.
- **Остаток вида** делится между людьми роли пропорционально тому, сколько у каждого заложено по этому виду (при одинаковых правилах — как раньше, по норме). Человек с 0% по виду доли не получает.
- **Сценарий:** «Базовые ресурсы» (посуточная база) и сводка «На бэклог» считают долю проектных часов человека по его процентам; строки видов работ по ролям — сумма по людям.

### 3.4 Не входит

Виджет «Нормированные работы» на дашборде, факт по работе в других командах — третий этап. Снимки утверждённого сценария личные настройки не фиксируют (как и справочник вовлечённости).

## 4. Реализация (для исполнителей)

### 4.1 Данные (Alembic, batch, идемпотентно — см. память про create_all в тестах)

- `employee_personal_settings`: `id`, `employee_id` FK `employees.id` CASCADE, `effective_year`, `effective_quarter`, `involvement` Float nullable, `normed_custom` Boolean not null default false, timestamps; unique (`employee_id`, `effective_year`, `effective_quarter`).
- `employee_personal_normed`: `id`, `setting_id` FK CASCADE, `work_type_id` FK `mandatory_work_types.id`, `percent_of_norm` Float; unique (`setting_id`, `work_type_id`).

### 4.2 Сервис `app/services/personal_settings.py` (чтение)

`PersonalSetting(involvement: Optional[float], normed: Optional[Dict[str, float]])` — `normed=None` «по правилам роли», `{}` — нет нормированных работ. `personal_for(db, employee_ids, year, quarter) -> Dict[str, PersonalSetting]`: последняя запись с (год, квартал) ≤ заданного; константа запросов. Сотрудники без записи в ответ не попадают.

### 4.3 API `/planning/personal-settings`

GET `?team=` — записи сотрудников, состоявших в команде (любые периоды), с именем и ролью; POST, PUT `/{id}`, DELETE `/{id}`. Валидация: вовлечённость 0–1; виды — только уменьшающие запас; проценты 0–100, сумма ≤ 100; дубль (сотрудник, год, квартал) → 409. Удаление вида работ, используемого в личных процентах, — 409 (как для периодов). После записи — событие обновления (`planning`, `resource_planning`).

### 4.4 Места учёта

- `involvement_default_service.effective_for_phase(item, phase, defaults, personal=None)` — личное значение первым.
- `ResourcePlanningService`: вовлечённость фазы с исполнителем — с личной настройкой исполнителя на квартал плана.
- `cross_team_occupancy`: вовлечённость брони (`external_bookings`), `base_other_share` — личная вовлечённость вместо справочника.
- `resource_planning.py`: остаток дня в «Загрузке по дням», `_effective_involvement` + источник `employee` в расшифровке.
- `normed_reserve.team_reserve`: заложено по личным процентам; остаток — пропорционально заложенному по виду.
- `ResourceBaseService.compute` / `compute_summary`: доля проектных часов и часы видов работ по людям.

### 4.5 Фронтенд

Панель `InvolvementDefaultsDrawer` → заголовок «Вовлечённость и нормированные работы»; раздел «Сотрудники»: таблица (Сотрудник, С квартала, Вовлечённость, Нормированные работы — «по правилам роли» / «нет» / «Сопровождение 5% · Орг. вопросы 10%»), добавление и правка в модальной форме, удаление. Расшифровка фазы (`PhaseCalcSection`) показывает источник «сотрудник».

## 5. Проверка

Пример: разработчик ERP (55% нормированных) получает вовлечённость 100% и «свои» нормированные 0% с IV кв. → его фаза разработки берёт 8 ч в день; в сценарии его «На бэклог» = вся норма; запас «Технических задач» роли = 10% нормы второго разработчика; остатки видов у него 0.
