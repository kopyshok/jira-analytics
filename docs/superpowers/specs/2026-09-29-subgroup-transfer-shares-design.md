# Перевод и деление сотрудника между группами команды — дизайн

Дата: 2026-09-29
Ветка: `feature/subgroup-shares`
Продолжение: [2026-08-31-team-subgroups-design.md](2026-08-31-team-subgroups-design.md),
[2026-09-01-scenario-subgroups-design.md](2026-09-01-scenario-subgroups-design.md)

## Задача

«Команда 1С (Бухгалтерия)» делится на четыре группы: Ломбард, Бухгалтерия, РФМ,
Налоговый мониторинг. Появились две потребности:

1. **Перевод.** Сотрудник переходит из группы в группу с определённой даты.
   Перевод должен влиять на ресурс групп в сценарии и учитываться в
   планировании.
2. **Деление.** Часть сотрудников работает сразу в нескольких группах.

Сейчас у сотрудника ровно одна группа, и дат у неё нет. Смена группы переносит
человека задним числом: вся его ёмкость за квартал уходит в новую группу, а
переток внутри команды за прошлые месяцы пересчитывается так, будто он всегда
был в новой группе. Деления нет совсем.

## Ключевые решения

### 1. Распределение по группам — история внутри участия в команде

У сотрудника в команде с делением появляется **распределение по группам**.
Это история записей:

- запись = дата начала + набор «группа — процент»;
- проценты целые, каждая доля больше нуля, в сумме 100;
- запись действует до даты начала следующей записи;
- дата любая, в том числе будущая (перевод можно запланировать заранее).

Обе потребности закрываются одним механизмом:

- **перевод** — новая запись «с 15.11 — РФМ 100%»;
- **деление** — запись «с 01.10 — Ломбард 60%, РФМ 40%»;
- переход от одного к другому — тоже новая запись.

Участие в команде (вход и выбытие) при этом не трогается. Перевод между
группами не выглядит как уход из команды и возвращение, поэтому даты вступления
в балансе часов, конфликт «вне команды» в плане и стол тимлида не страдают.

Нынешняя единственная группа каждого сотрудника переносится в первую запись
«100%», действующую с начала его участия. Прошлое не меняется.

Отвергнуто:
- перевод через существующий перевод между командами (закрыть участие, открыть
  новое): даёт ложные выходы и входы в команду и не решает деление;
- проценты без дат: переписывают прошлое.

### 2. Группа обязательна

В команде с делением у каждого активного сотрудника должно быть распределение
на все дни его участия. Сотрудник без него — **некорректная карточка**: РП
обязан проставить группу или сделать сотрудника неактивным.

- В «Ресурсах» и «Сценариях» — красная плашка «N сотрудников без группы» со
  ссылками на карточки.
- **Утверждение сценария заблокировано**, пока в квартале сценария есть
  активный сотрудник команды без группы хотя бы на один день участия.
- Строка «Без группы» в отчётах остаётся, чтобы суммы сходились с командой, но
  выделена как ошибка.
- Новый сотрудник из Jira сразу попадает в плашку.
- Перевод в команду с делением требует выбрать группу: без неё перевод не
  проходит.

### 3. Где правится

**Карточка сотрудника** в «Ресурсах», рядом с переводом между командами. Блок
«Группы»:

- текущее распределение и история записей;
- «Перевести в группу» — группа + дата;
- «Разделить между группами» — дата + проценты по группам;
- удаление ошибочной записи.

Колонка группы в списке сотрудников «Ресурсов» перестаёт быть выпадашкой для
всех. Сотруднику без группы выпадашка задаёт первую запись «100% с начала
участия». У остальных колонка показывает текущее распределение текстом
(«Ломбард 60% · РФМ 40%»), клик открывает карточку. Иначе один жест значил бы
две разные вещи: исправление ошибки и перевод с даты.

### 4. Сценарий — ресурс групп

- Ресурс группы собирается **по дням квартала**. Каждый день часы человека
  (после нормированных работ и личной вовлечённости — как сейчас) делятся по
  его доле в этот день. При переводе 15.11 часы до этой даты идут старой
  группе, после — новой.
- Брони других команд снимаются с групп человека по его доле в дни брони.
- «По сотрудникам»: общий сотрудник виден в секции каждой своей группы с
  пометкой «общий 60%» и ресурсом по доле. Нагрузка в секции — его идеи этой
  группы, поэтому перебор подсвечивается уже существующей полоской загрузки.
- Сотрудник, переведённый внутри квартала, виден в обеих группах со своими
  днями и пометкой «переведён с 15.11».
- Сумма по группам равна итогу команды — часы не удваиваются.
- Утверждение замораживает распределение за квартал. Перевод или смена долей
  после утверждения сценарий не меняют, а показывают плашку расхождения — как
  сейчас при смене состава команды. Переутвердить — решение РП.

### 5. Планирование

- **Доля — ориентир, не лимит.** Дневного потолка по группам нет, перегруз
  ловится по человеку в целом, как сейчас. Если по факту выходит далеко от
  доли, это видно в сценарии по полоске загрузки в секции группы.
- **Автоподбор исполнителя.** «Свой» для группы — все группы, где у человека
  есть доля в квартале плана, хоть один день. Ёмкость по группам при этом не
  режется: доля — ориентир для расчёта ресурса в сценарии, а не дневной лимит
  для автоподбора. Общий сотрудник — свой для всех своих групп. Переведённый
  внутри квартала — свой для **обеих** групп весь квартал, а не только до/после
  даты перевода. Метка «соседняя группа» на полоске плана показывает дни,
  когда он занят группой, в которой на этот день доли нет.
- **Задачи старой группы после перевода** остаются за человеком: он их
  доделывает. На полоске задачи — тихая метка «соседняя группа», без
  конфликта. Работа на соседнюю группу внутри команды — нормальная ситуация.

### 6. Группа задачи

Лесенка сохраняется: явно → от родителя → предположение по исполнителю.
Меняется только третья ступень:

- предположение берёт группу исполнителя **на дату**: у закрытой задачи — на
  дату закрытия, у открытой — на сегодня. Так факт закрытых задач не
  переезжает при переводе, а открытая работа идёт за человеком. «Закрытая»
  определяется по категории статуса (`done`), а не по конкретному статусу.
  Дата закрытия — дата резолюции, а если её нет — дата последней смены
  статуса;
- если исполнитель на эту дату поделён между группами, **предположения нет**:
  задача остаётся «Без группы», пока РП не проставит группу вручную в стопке
  разбора;
- предположения пересчитываются там же, где сейчас (синхронизация, правки),
  плюс при правке распределения. Запланированный на будущее перевод двигает
  открытые задачи при первом пересчёте после наступления даты.

Позиция пользователя: РП изначально размечает группы у всех задач явно.
Предположение — страховка, а не основной путь.

### 7. Факт и переток

- Факт — по группе задачи, без изменений.
- Переток считается по группе человека **на дату списания**. Прошлый переток
  при переводе не пересчитывается.
- Работа сотрудника в любой группе, где у него есть доля на эту дату, —
  **не переток**. Перетоком считается только работа вне его групп: «ушло» — из
  его групп по долям, «пришло» — в группу задачи.

### 8. Витрины «на человека»

Баланс часов, нормированные работы, KPI, стол тимлида при фильтре по группе:

- общий или переведённый сотрудник виден в каждой своей группе периода и
  учитывается там **целиком** — без деления по доле (решение пользователя
  29.09). Деление по проценту действует только в «Сценариях», где нужна сумма
  по группам, а не в витринах «на человека»;
- пометка «общий» показывается в «Сценариях» и в «Ресурсах»; в остальных
  витринах отдельной пометки нет;
- личные показатели (KPI, строка стола тимлида) не делятся.

Executive и ресурсное планирование фильтру группы по-прежнему не подчиняются.

### 9. Команды без деления

Никаких изменений. Тест регрессии команды без групп должен остаться зелёным.

## Не входит

- Дневной лимит часов по группам в планировании (решено: доля — ориентир).
- Деление долями между **командами** — отдельная тема, там действует правило
  «основная команда главнее».
- Экспорт истории распределения в xlsx.

## Критерии приёмки

1. Команда без групп ведёт себя идентично текущей версии.
2. Перевод 15.11: ресурс квартала до 15.11 — у старой группы, после — у новой;
   сумма по группам равна команде.
3. После перевода факт закрытых задач и прошлый переток не меняются.
4. Общий сотрудник 60/40: ресурс групп по долям, виден в секциях обеих групп,
   часы не удваиваются.
5. Работа общего сотрудника в своих группах — не переток; вне их — переток.
6. Автоподбор: переведённый — свой для новой группы после даты перевода, общий
   — свой для обеих групп.
7. Задачи старой группы после даты перевода остаются за человеком с меткой
   «соседняя группа».
8. Утверждение сценария заблокировано при активном сотруднике без группы;
   блокировка снимается после правки карточки или деактивации.
9. Смена распределения после утверждения — плашка расхождения, сценарий не
   меняется.
10. Задача общего сотрудника без явной группы — «Без группы».
11. Закрытая задача с угаданной группой остаётся в группе исполнителя на дату
    закрытия; открытая переезжает вместе с ним.
12. Перевод в команду с делением без выбора группы отклоняется.

## Техническое приложение

- **Хранение.** Новая таблица долей: сотрудник, команда, дата начала (пусто —
  «с начала участия»), группа, процент. Запись распределения — все строки с
  одинаковыми сотрудником, командой и датой начала. Уникальность —
  (сотрудник, команда, дата начала, группа). Инварианты (сумма 100, доли > 0,
  группы этой команды) проверяются в сервисе.
- **Миграция.** Нынешняя группа участия переносится в строку «100%, дата
  начала пусто». Колонка группы у участия удаляется **отдельной, более
  поздней миграцией** — только после того, как все чтения из списка ниже
  переключены на новый модуль. Так на время перехода колонка и таблица долей
  сосуществуют, а не обрываются в одной миграции. Batch mode для SQLite;
  прогнать на PostgreSQL до релиза.
- **Один модуль чтения.** По образцу `app/services/team_membership.py`: доли на
  дату, доли по дням периода, сотрудники группы за период. Прямое чтение
  группы сотрудника в расчётах — регресс. Сейчас группу сотрудника напрямую
  читают:
  - `resource_base_service._team_subgroups` — ресурс сценария по группам;
  - `capacity_service.team_role_capacity_by_subgroup` — ёмкость «Ресурсов» по
    группам; с решением «ёмкость по группам не режется» (§5, §8) этот расчёт
    мёртвый — не используется ни одним экраном, подлежит удалению вместе с
    переводом чтения на новый модуль, а не переносу на него;
  - `resource_planning_service._subgroup_context` и `_assign_employees` —
    автоподбор (ёмкость по группам вместо одной группы сотрудника);
  - `snapshot_writer` — заморозка при утверждении (формат снимка расширяется
    распределением; старые снимки читаются как «100%»);
  - `subgroup_filter` — фильтр витрин по группе (период вместо «сейчас»);
  - `subgroup_resolver` — третья ступень лесенки (дата закрытия или сегодня;
    поделённый — без предположения);
  - `subgroup_flow_service` — переток по дате списания;
  - `api/endpoints/planning.py` (помощник около строки 465) — группа сотрудника
    в выдаче сценария;
  - `team_registry_service` — приписка и удаление группы (удаление группы
    должно убирать её из долей; если запись после этого перестаёт давать
    100% — сотрудник попадает в плашку «без группы»).
- **API.** Чтение истории распределения, добавление записи (перевод / деление),
  удаление записи. Нынешняя операция приписки остаётся только для первой
  записи у сотрудника без группы. Перевод между командами принимает группу,
  если у целевой команды есть деление.
- **Блокировка утверждения** — проверка на сервере, не только кнопка в
  интерфейсе.
- **Интерфейс.** Блок «Группы» в карточке сотрудника, выбор группы в окне
  перевода между командами, текст распределения в колонке «Ресурсов», пометки
  «общий N%» / «переведён с …» в секциях сценария, метка «соседняя группа» на
  полоске плана, плашка «без группы» в «Ресурсах» и «Сценариях».
- **Справка.** Дополнить разделы «Ресурсы» и «Сценарии».
