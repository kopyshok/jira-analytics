# Группы внутри команды в разделе «Сценарии»

Дата: 2026-09-01
Ветка: `feature/team-subgroups`
Продолжение: [2026-08-31-team-subgroups-design.md](2026-08-31-team-subgroups-design.md)

## Зачем

В первом выпуске групп Сценарии получили только разрез ёмкости по группам в
верхней ленте. Планировщик команды с тремя группами видит один общий список идей
и один общий набор полосок ролей — понять, чем занята конкретная группа, нельзя.

Нужно: список идей и правый блок ресурса читаются по группам, а группу идеи
можно поправить прямо на месте — как исполнителя.

## Решения

### 1. Откуда берётся группа у идеи

Существующая лесенка резолвера, ничего нового:

1. проставлена на задаче вручную;
2. унаследована от ближайшего родителя;
3. предположение по исполнителю;
4. иначе — «Без группы».

Идея бэклога своего поля группы не заводит: группа выводится от задачи. Для идей
без задачи (ручной бэклог) работает пункт 3 — по исполнителю идеи.

### 2. Правка группы в строке сценария

Выпадашка рядом с исполнителем. Выбор пишет группу **на саму задачу** — та же
операция, что кнопка в стопке разбора (`PUT /issues/{id}/subgroup`). Новой записи
не заводим.

Следствия принимаются сознательно:

- потомки задачи наследуют группу;
- разбор, аналитика и прочие витрины видят ту же группу;
- пустое значение возвращает к предположению по исполнителю;
- строка сразу переезжает в другую секцию.

В утверждённом сценарии выпадашка заблокирована — как галочки включения.
Правка данных задачи из замороженного сценария ломала бы смысл заморозки.

Отвергнуто: собственное поле группы у распределения («переопределить только
внутри сценария»). Тогда витрины и сценарий расходятся, и расхождение нужно
объяснять пользователю в каждом отчёте.

### 3. Таблица идей — секции

Заголовок секции: название группы · число идей · часы по четырём ролям · всего
часов. Секция сворачивается, состояние свёрнутости живёт в браузере
пользователя.

Порядок секций — как в реестре команды. «Без группы» последней и только если в
ней есть идеи.

Перетаскивание строк (ручной приоритет) работает **внутри секции**. Бросок в
чужую секцию запрещён: группа меняется выпадашкой, а не перетаскиванием, иначе
один жест значит две разные вещи.

### 4. Правый блок ресурса

«Ресурс по ролям» и «По сотрудникам» режутся на секции по группам:

- внутри секции роли — свои полоски план / доступно и число людей этой группы;
- внутри секции сотрудники — только люди этой группы;
- секции сворачиваются;
- верхняя плашка «Ресурс команды · Q» остаётся общей: итог команды виден всегда.

Сотрудник, поделённый между группами, показывается в каждой своей группе с
существующей пометкой «общий». Часы не удваиваются — ёмкость по группам уже
считается на сервере (`available_by_subgroup_role`).

Полоска «Ресурс по группам · часы на бэклог» в верхней ленте и строка перетока
остаются без изменений: они отвечают на другой вопрос — сколько часов группа
отдаёт наружу.

### 5. Команды без групп

Признак деления выключен → ни секций, ни выпадашки, ни заголовков. Поведение
идентично текущему. Это же условие показа, что и в первом выпуске.

## Объём

Сервер:

- группа идеи в выдаче распределений сценария (идентификатор, название,
  источник — проставлена / унаследована / предположение);
- группа сотрудника в выдаче ресурсной базы;
- запись группы — переиспользуется существующая операция.

Интерфейс:

- секции с итогами в таблице идей + сворачивание;
- перетаскивание в границах секции;
- выпадашка группы в строке, заблокирована в утверждённом сценарии;
- секции по группам в карточках «Ресурс по ролям» и «По сотрудникам».

## Не входит

Экспорт в xlsx, сравнение сценариев, история ревизий — показывают команду
целиком, как и до правки.

## Тесты

- выдача распределений отдаёт группу и её источник для команды с группами;
- для команды без групп поле пустое, поведение прежнее;
- выдача ресурсной базы отдаёт группу сотрудника;
- правка группы в утверждённом сценарии отклоняется.
