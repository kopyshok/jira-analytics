# Сверка справочников сервиса с Jira — дизайн

Дата: 2026-10-21. Статус: согласован с владельцем.

## Зачем

После переезда на Jira DC часть значений Jira сменилась, а настройки сервиса ссылаются на них по имени
или номеру. Ничего не падает — фильтры просто перестают находить задачи. Найдено на выгрузке прода 21.10
(сравнение с облачной копией 01.10 по тем же 137 тыс. задач):

- резолюция `Done` → `Готово` (124 тыс.), `Duplicate` → `Дубликат`, новые `Won't Do`, `Declined`;
  KPI quality / cycle_time / deadlines / customer_score отбирают `resolution in ["Done"]` — пусто;
- статусы: `Отменено` → `Won't Do` (19 тыс.; у 13 тыс. из них резолюция `Готово`!), `К выполнению` →
  `Сделать`, `Бэклог` → `IDEA BACKLOG`; новые `Hold`, `APPROVED IDEA BACKLOG`. Группы стола тимлида их
  не знают; KPI regulations исключает `Backlog/Бэклог`; общее правило KPI «не считать выполнением» —
  только `Отменено`; автоархив синка срабатывает на `== "Отменено"`;
- план QA: вторым полем при переезде выбрано `QA spent (ч)` (customfield_10845) — факт вместо оценки;
  правильная пара облачному «Оценка QA 1С (ч)» — `Оценка QA (ч)` (customfield_11042), решение владельца;
- план ОПЭ: поля «Пусконаладочные (ОПЭ) (ч)» в DC нет (вопрос админу Jira, в сервисе делать нечего);
- спринты (241, в основном PMD 2025–26), релизы (86 версий), приоритеты (Low/High/Блокер → Medium)
  поменялись в самой Jira — только показать.

Попутно: сводка для руководителя и тематический отчёт считают выполненной задачу со статусом `done`
(по имени) — у нас статусы русские, сломано и до переезда.

## Решения владельца

- Сверять: статусы и резолюции (+ типы задач, приоритеты, проекты), поля Jira, значения полей,
  спринты и релизы.
- Найденное расхождение: показать + «Заменить на…» во всех настройках одним действием.
- Сравнивать с полными списками из Jira (не только с тем, что пришло в задачах).
- Один экран в администрировании (не предупреждения по экранам).
- Ежедневная автоматическая проверка + плашка администратору при новом расхождении.
- Команда переименована в Jira → «Заменить» переименовывает команду в сервисе везде.
- Срочные правки — сами при обновлении версии (часть 1), отдельным выпуском раньше частей 2–4.

## Часть 1. Срочная правка при обновлении версии

Миграция данных (самодостаточная, без импорта кода приложения, повторный запуск ничего не меняет,
меняет только там, где найдено старое значение — на других установках пустой проход):

1. `kpi_metrics.numerator_json / denominator_json`: в условиях `attr = resolution` значение `Done` →
   `Готово` (без дублей; `eq` — замена значения). В условиях `attr = status, op = not_in`, где есть
   `Backlog` или `Бэклог`, — добавить `IDEA BACKLOG`, `APPROVED IDEA BACKLOG`.
2. `app_settings.kpi_excluded_statuses`: если ключ есть и содержит `Отменено` без `Won't Do` —
   добавить `Won't Do`. Код: умолчание `["Отменено"]` → `["Отменено", "Won't Do"]`.
3. `app_settings.team_desk_config` (JSON): в каждый список (группы, очередь, в работе, скрытые), где
   есть исходный статус, добавить новый, если его нет:
   `Отменено` → `Won't Do`; `К выполнению` → `Сделать`; `Backlog` → `IDEA BACKLOG`,
   `APPROVED IDEA BACKLOG`; `Приостановлено` → `Hold`. Код: те же значения в умолчаниях
   `team_desk/config.py`.
4. `app_settings.jira_planned_qa_hours_field_id` (JSON-список): элемент с `customfield_10845`
   → `{"field_id": "customfield_11042", "kind": <прежний>, "name": "Оценка QA (ч)"}`. После обновления
   администратор один раз перезагружает задачи (Синхронизация → Дополнительно → Задачи) — в заметке
   «Что нового» и в инструкции к выпуску.
5. `kpi/seed.py` (новые установки): резолюция `Готово`, исключение бэклога с `IDEA BACKLOG`.

Код:
- автоархив синка: `issue.status in CANCEL_STATUSES` (общий список, уже содержит `Won't Do`) вместо
  `== "Отменено"`;
- пауза Cycle Time: `PAUSED_STATUSES = ("Приостановлено", "Hold")` — `Hold` трактуется как пауза
  (как в столе тимлида);
- сводка для руководителя и тематический отчёт: «выполнено» = категория статуса `done`, а не имя.

Проверка: тесты миграции на копии настроек прода (до/после, повторный прогон), прогон миграции на
копии выгрузки 21.10, KPI за Q3/Q4 до и после на копии — показать владельцу разницу.

## Часть 2. Экран «Сверка с Jira»

Настройки → Администрирование → «Сверка с Jira». Время последней проверки, «Проверить сейчас».

### Устройство

- **Справочники Jira** (`app/services/jira_reconcile/catalog.py`): статусы (с категорией), резолюции,
  типы задач, приоритеты, проекты, поля, варианты значений полей из настроек (команда, участвующие
  команды, подтип, тип затрат, окружение, направление, влияние, риск), версии проектов из scope,
  спринты досок проектов из scope. Новые методы клиента: `/resolution`, `/priority`,
  `/project/{key}/versions`, agile `/rest/agile/1.0/board?projectKeyOrId=`, `/board/{id}/sprint`
  (клиенту нужна вторая база путей, сейчас всё под `/rest/api/2`).
- **Реестр мест** (`usages.py`): каждое место настроек, где хранится значение Jira, — вид значения
  (статус, резолюция, тип, приоритет, проект, поле, вариант поля X, команда, спринт, релиз), понятная
  подпись и экран («KPI → Регламенты, условие», «Стол тимлида → группа „ожидание“»), чтение значений и
  замена старого на новое. Места: условия KPI, `kpi_excluded_statuses`, `team_desk_config`, правила
  иерархии, настройки полей `jira_*_field_id` (включая списки плановых часов), сохранённые отборы стола
  тимлида у пользователей (статусы, спринты, релизы), scope-проекты (только показ). Встроенные в код
  списки (статусы отмены, паузы) — только показ с пометкой «встроено — сообщите разработчику».
- **Отчёт** (`report.py`): по каждому значению из реестра — где используется, есть ли в Jira, сколько
  задач с ним в базе; подсказка замены (совпадение без учёта регистра, пробелов и латиницы-двойника, затем
  по числу задач); обратный список — статусы Jira из задач, не разложенные по группам стола. Поля: роль,
  выбранное поле, есть ли в Jira, тип, заполнено у задач, перечитанных за 30 дней. Спринты/релизы:
  значения из задач, которых нет в Jira, и число задач — только показ.
- **Замена** (`replace.py`): старое → новое для одного вида значения во всех заменяемых местах одной
  транзакцией; результат — сколько где заменено; без дублей в списках. Предпросмотр — те же счётчики без
  записи. Для команды — часть 3.

### Экран

Четыре раздела-вкладки. Строка: значение, где используется (раскрывается), в Jira (есть / нет), задач в
сервисе, действие. «Заменить на…» — выбор из полного списка Jira, подсказка первой → окно подтверждения
(что и где поменяется) → замена. Поля: «Сменить поле» — выбор из полей Jira (как в «Полях Jira»).

## Часть 3. Переименование команды

`team_rename.py`: старое имя → новое во всех местах, где имя команды — ключ: реестр команд, участие и
группы сотрудников, `employees.team`, сценарии, бэклог, блоки графика, вовлечённость, нормативы Cycle
Time, утверждения KPI, расписания и запуски синхронизации, переопределения видов работ, ресурсные планы,
отметки онбординга, задачи (`issues.team`, `participating_teams`), пользователи (`default_team`,
выбранные команды, отбор стола), `ui_teams_categories`, `ui_team_projects`. Если команда с новым именем уже
есть: пустую (без участников и данных — её мог завести синк) поглотить, с данными — отказ с объяснением.
Тест полноты: обход метаданных — любая строковая колонка с «team» в имени обязана быть в списке
переименования или в явном списке исключений.

## Часть 4. Ежедневная проверка и плашка

Фоновая задача раз в сутки (тот же планировщик, что у самопродления ключей): собрать отчёт, сохранить
сводку (`app_settings.jira_reconcile_last`: время, число расхождений, отпечаток набора расхождений).
Администратору — плашка «Есть расхождения с Jira: N» со ссылкой на экран, если отпечаток новый и не
скрыт; «Скрыть до новых расхождений» запоминает отпечаток. Сбой обращения к Jira — плашки нет, на экране
сверки текст ошибки.

## Не делаем

Предупреждения в каждом экране настроек; автозамену без подтверждения (кроме части 1); правку значений,
встроенных в код, через экран; исправление данных в самой Jira (приоритеты, спринты — отчёт админу Jira).

## Проверка

Тесты на каждую часть (TDD), тест полноты для реестра мест и переименования команды; прогон на копии
выгрузки прода 21.10; живая проверка экрана на стенде; перед выпуском — Postgres и проверка
безопасности.
