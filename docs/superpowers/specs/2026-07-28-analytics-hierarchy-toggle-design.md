# Аналитика: переключатель «Иерархия»

Дата: 2026-07-28

## Задача

В иерархическом отчёте Аналитики нижний уровень — плоский список задач внутри категории.
Нужен переключатель «Иерархия»: задачи показываются деревом до самого верхнего родителя,
как в разделе «Категории задач». По умолчанию выключен.

## Решения (согласованы с PM)

1. **Дерево строится внутри категории.** Группировка Команда → Роль → Сотрудник → Вид работ →
   Категория сохраняется. Меняется только последний уровень.
2. **Родитель показывает сумму ветки.** Строка родителя = сумма часов всех задач под ним
   внутри этой группы (включая его собственные списания).
3. **Поднимаемся до самого верха** — до задачи без родителя.
4. **Экспорт XLSX повторяет дерево.**
5. **Родитель из чужой команды/категории** попадает в дерево контекстной строкой. Цепочку
   не обрываем.

## Поведение

### Выключен (по умолчанию)
Как сейчас: под категорией плоский список задач, сортировка по убыванию часов.

### Включён
Под категорией — дерево. Для каждой задачи с часами достраивается цепочка родителей до
корня; одинаковые родители склеиваются в один узел. Сортировка на каждом уровне — по
убыванию часов ветки.

Три вида строк:

| Вид | Когда | Что показывает |
|---|---|---|
| Обычная задача | у задачи есть часы и нет детей в этой группе | свои часы |
| Родитель | у узла есть дети в этой группе | сумму часов всей ветки |
| «Собственные списания» | у родителя есть и свои ворклоги | свои часы родителя отдельной подстрокой |

Родители без собственных часов — контекстные строки (приглушённый стиль), они существуют
только чтобы показать «откуда задача».

Строка «собственные списания» нужна, чтобы часы, списанные прямо на эпик (встречи, анализ),
не растворялись в сумме ветки и оставались кликабельными для просмотра ворклогов.

### Числа
Ворклоги / Задач / % в группе у родителя считаются по всей ветке. Итоги команды, роли,
сотрудника, вида работ, категории **не меняются** — те же часы, другая раскладка.

### Экспорт
Строки идут в том же порядке, что на экране. Ключ задачи сдвигается отступом по уровню
вложенности, добавляется колонка «Уровень», ставится группировка строк Excel (лист
сворачивается/разворачивается). Плоский режим экспорта остаётся при выключенном переключателе.

## Устройство

**Бэкенд.** Отчёт получает флаг `hierarchy`. Когда включён, после сборки бакетов список
задач каждой категории пересобирается в дерево:

1. Один проход walk-up по `parent_id` собирает цепочки предков для всех задач отчёта
   (батчами, с защитой от циклов) и их метаданные.
2. Внутри каждой категории строится дерево, узлы получают totals по поддереву.
3. Схема ответа: у узла задачи появляются `children: list[AnalyticsIssueNode]` и
   `row_kind: 'issue' | 'context' | 'own'`. При выключенном флаге `children` пуст,
   `row_kind='issue'` — форма ответа обратно совместима.

**Фронтенд.** Переключатель «Иерархия» в шапке рядом с «Ворклоги», состояние локальное
(при перезагрузке страницы снова выключен), пробрасывается в запрос отчёта и в ссылку
экспорта. Построение строк таблицы рекурсивное; контекстные строки приглушены, строка
«собственные списания» без ключа-ссылки.

**Экспорт.** Рекурсивный обход `children` вместо плоского цикла, `outlineLevel` по глубине.

## Границы

- Состояние переключателя не сохраняется между сессиями.
- «Развернуть всё» не добавляется (на большом стеке тормозит, как и в «Категориях задач»).
- Уровни группировки выше категории не меняются.

## Проверка

- Тест: задача с двухуровневой цепочкой родителей → родитель показывает сумму, контекстные
  строки помечены, итоги категории не изменились.
- Тест: родитель со своими ворклогами → появляется строка «собственные списания», сумма
  ветки включает её ровно один раз.
- Ручная проверка: выключенный переключатель даёт ровно тот же отчёт, что до правки.
