# Счётчики статусов в разрезе разработчиков — стол тимлида

Дата: 2026-08-11
Раздел: «Рабочий стол тимлида» (`/team-desk`)

## Задача

Тимлид хочет видеть, сколько задач у каждого разработчика стоит в конкретном
статусе — в первую очередь «Ожидает помещения», но список статусов должен
настраиваться: статусная модель Jira меняется, и второй интересный статус
появится без правки кода.

Сейчас плитка разработчика показывает только разбивку по группам статусов
(«у него» / «ждут не его» / «не начаты»). Внутри группы «у него» три статуса —
«В РАБОТЕ», «КОД-РЕВЬЮ» и «Ожидает помещения» — и они не различимы.

## Что считаем

По каждому разработчику — разбивка его задач по статусам. Состав задач ровно
тот же, что даёт цифру «N задач всего»: только самостоятельные задачи
(подзадача — декомпозиция родителя, её нельзя считать вторым разом), скрытые
статусы отброшены, режим среза и переключатель «выполненные подзадачи» действуют
так же.

**Инвариант:** сумма счётчиков статусов равна «N задач всего». Расхождений,
которые пришлось бы объяснять в справке, нет.

Сервер отдаёт **полную** разбивку по всем статусам, что встретились у человека.
Какие показать — решает интерфейс. Значит, снятие или добавление галочки
мгновенно, без повторного запроса данных.

## Настройка

В шапке стола, рядом с выбором команд и людей, — поле «Счётчики статусов»:
множественный выбор. В списке — статусы, встречающиеся в текущем срезе, в том
же порядке, что и везде в разделе: сначала группа «у разработчика», затем «ждёт
не его», «не начаты», «закрыта», в конце статусы, не отнесённые ни к одной
группе. Ранее выбранные статусы остаются в списке, даже если задач в них сейчас
нет — иначе выбор молча сбрасывался бы.

Пусто = показываются все статусы среза. Польза сразу, настраивать не
обязательно.

Выбор личный: живёт в профиле рядом с остальной шапкой раздела (команды, люди,
режим среза, окно периода, оба переключателя). Два тимлида друг другу не мешают.

## Где видно

Порядок статусов одинаков во всех трёх раскладках.

**Светофор.** Отдельная строка значков между очередью работы и значками
замечаний, по значку на статус: цветная точка группы + название статуса +
число. Наведение — подсказка «Ожидает помещения · у разработчика».

**Ведомость.** Колонка на каждый выбранный статус, после «Замечаний»,
сортируемая, с итогом в нижней строке. Видно, у кого больше всех висит в
«Ожидает помещения».

**Проблемы вперёд.** Та же строка значков в строке разработчика — под именем,
рядом с «N задач · M у него».

Итог по всей команде в шапке раздела не делаем — не просили.

## Клик

Клик по значку статуса оставляет в списке задач только этого разработчика и
только задачи этого статуса; повторный клик по тому же значку снимает фильтр.
Работает так же, как клик по карточке разработчика сейчас.

Фильтр по статусу и фильтр по замечанию складываются: выбраны оба — остаются
задачи, попадающие под оба условия. Действующие фильтры перечислены подсказкой
в шапке карточки со списком задач, как сейчас для замечаний.

Родительская задача остаётся в списке, если под условие попадает её подзадача —
то же правило, что уже работает для замечаний, иначе подзадача осталась бы
без строки-родителя.

## Границы

- Новых настроек на стороне администратора нет: группы статусов, скрытые
  статусы и пороги остаются как есть.
- Счётчик по статусу не становится «замечанием»: подсветки, отметок
  «просмотрено» и порогов у него нет. Это факт, а не проблема.
- Экспорта и печати раздела нет — добавлять некуда.

## Проверка

Расчёт разбивки — чистая функция сводки, на неё тест: разбивка по статусам
сходится с «N задач всего», подзадачи в неё не идут, закрытые подзадачи,
добранные под родителями, тоже не идут.
