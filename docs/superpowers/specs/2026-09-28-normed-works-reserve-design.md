# Нормированные работы ↔ ресурсное планирование — дизайн

## 1. Зачем

Нормированные работы (проценты по ролям и видам работ в сценарии), вовлечённость и заблокированные периоды — три мерки, которые сейчас не сходятся. «Загрузка по дням» занижает загрузку: у Пряничникова (разработчик ERP, IV кв.) задачи ERP ≈176 ч + «Блок Компетенций» ≈180 ч + нормированные работы ≈230 ч = 586 ч при норме 511 ч (≈115%), а диаграмма показывает ≈80%.

Цель: нормированные работы — **запас времени на квартал** по видам работ; вовлечённость — **плотность работы над задачей**; заблокированный период и работа в других командах — **нормированные работы с датой**, которые расходуют запас. «Загрузка по дням» показывает честную загрузку.

## 2. Выпуски

1. **Заблокированные периоды** — вид работ, сотрудники, приоритет сотрудника над ролью, список показывает «кому», период основной команды закрывает день и для других команд.
2. **Запас нормированных работ в ресурсном плане** — расчёт запаса, «Загрузка по дням», сводка запаса, предупреждения, вид работ у задач других команд.
3. **Сценарий и факт** на той же модели — отдельная спека позже (вне этого документа).

Раскладка задач (сроки фаз) в выпусках 1–2 не меняется, кроме одного правила: период основной команды закрывает день человека и в планах других команд.

## 3. Решения пользователя (28.09)

| Вопрос | Решение |

| Запас на человека или на команду | Общий на роль в команде. Работа с датой списывается с того, кто её делает; остаток делится между людьми роли. |
| Как запас ложится на дни | В день с задачей — остаток дня после вовлечённости; остальное поровну на свободное время дней без задач. |
| Вид работ у работы в других командах | По умолчанию «Технические задачи». Основная команда может указать другой вид у конкретной задачи — у себя. |
| Сколько человека может занять другая команда | Как сейчас: в пределах вовлечённости дня. Нормированные работы размазываются по остальным дням. Итог 100%, кроме случая, когда задач больше нормы. |

| Показ запаса | Сводка над «Загрузкой по дням» + подсказки у имени + предупреждения плана. |

## 4. Выпуск 1 — заблокированные периоды

### 4.1 Поля периода

- **Вид работ** — из справочника видов работ (только виды, которые уменьшают запас на проекты; «Прочие / Чужие» не предлагается). Обязателен при создании и изменении.
- **Кому:** ничего не выбрано — вся команда; одна или несколько ролей; конкретные сотрудники (из состава команды). Роли и сотрудники в одном периоде — объединение, как сейчас.
- Даты, причина — как сейчас.

Существующие периоды: причина «Закрытие месяца» (без учёта регистра и пробелов по краям) → вид «Сопровождение и консультация». Остальные — без вида. Период без вида закрывает день, запас не расходует; в списке помечен «укажите вид работ».

### 4.2 Список периодов

Колонки: даты, **Кому** (названия ролей, имена сотрудников или «вся команда»), **Вид работ**, причина. Период можно изменить (те же поля, что при создании) и удалить.

### 4.3 Кого закрывает период

Период команды X закрывает день человека, если в этот день:
- человек состоит в X (основная она у него или нет) — в планах X;
- X — его основная команда — в планах **любой** команды.

Привлечённого в план X (в X не состоит) периоды X не закрывают. Периоды без команды — для всех, как сейчас.

### 4.4 Приоритет

Уровни: вся команда < роль < сотрудник. Для человека, команды периода, месяца и вида работ действуют только периоды самого точного уровня, который у него есть в этом месяце. Пример: у аналитиков закрытие 05–07.10, Иванову задан 08–09.10 того же вида → у Иванова в октябре закрыты только 08–09.10; в ноябре снова действует период роли. Периоды без вида образуют свою группу «без вида». Периоды разных команд друг друга не перекрывают.

### 4.5 Устаревание планов других команд

Изменение периодов основной команды меняет доступность её людей в планах других команд. Такие планы помечаются устаревшими тем же механизмом, что изменения чужих планов («Планы других команд изменились — нажмите «Распределить»»), с названием основной команды в списке.

## 5. Выпуск 2 — запас нормированных работ

### 5.1 Откуда проценты

Опорный сценарий команды на квартал: утверждённый (самый свежий по изменению), иначе самый свежий черновик. Правила по роли заменяют правила «для всех ролей» (как в «Базовых ресурсах»). Учитываются только виды работ, которые уменьшают запас на проекты. Нет правил — у команды нет запаса, нормированные работы не показываются.

### 5.2 Запас

- **Норма дня** человека — часы производственного календаря минус отсутствия. Заблокированные периоды норму не уменьшают — они сами нормированная работа.
- **Люди запаса команды T** — те, у кого T основная; в запас идут только дни, когда T у человека основная.
- **Запас вида w для роли r** = Σ по людям роли r (норма их дней в T × процент w для r).

### 5.3 Расход с датой

- **Заблокированный период** команды T с видом w — весь день человека (его норма дня) в виде w. Только периоды основной команды и только в дни, когда она основная.
- **Работа в опорных планах других команд** (включая хвосты прошлого квартала, попавшие в квартал) — часы брони в дни, когда T основная. Вид — указанный командой T для этой задачи, иначе «Технические задачи».

### 5.4 Остаток и доля человека

- Остаток вида w роли r = max(0, запас − расход с датой).
- Остаток делится между людьми роли пропорционально их норме в T (при полном квартале без отпусков — поровну).
- **Нормированные работы человека** = его заблокированные дни + его доля остатков по всем видам. Работа в других командах в них не входит — она отдельный слой «другие команды», но расходует запас своего вида.
- Цифры человека не зависят от того, в плане какой команды на него смотрят.

### 5.5 По дням (для показа)

Для человека в окне квартала:
1. **Заблокированный день** — вся норма дня; вид и причина периода.
2. **День с задачей** (этого плана или брони другой команды, у фазы задана вовлечённость) — остаток дня после наименьшей вовлечённости фаз дня (при 90% — 10% нормы дня), как сейчас у «прочих работ», не больше свободного. Берётся из доли остатка человека, пока она не кончится.
3. **Остаток доли** — на свободное время дней пропорционально свободным часам дня.
4. Не поместилось — **не размещено** (перегруз квартала). По дням не рисуется.

Свободное время дня = норма − задачи плана − брони других команд − нормированные работы.

### 5.6 Процент у имени

`(задачи плана + другие команды + нормированные работы, включая неразмещённые) / норма квартала`. Подсказка: задачи плана, другие команды, нормированные работы по видам, «не вмещается на N ч».

### 5.7 Сводка запаса (над «Загрузкой по дням»)

Для команды плана, если у неё есть запас. **Пересмотрено 28.09 (вечер) по отзыву пользователя:**

- Блок при открытии плана всегда свёрнут в строку-заголовок «Нормированные работы — запас квартала» с отметкой «⚠ N перерасходов» (или «перерасхода нет»); разворачивается щелчком.
- Развёрнутый — **одна таблица** на все роли (колонки выровнены): подзаголовок роли, под ним строки видов работ. Показываются **только виды, у которых есть расход с датой** (заблокированные периоды или работа в других командах); виды без расхода не показываются совсем.
- Колонки: **Вид работ**, **Заложено**, **Занято** (полоска «занято из заложенного» + часы; под ней мелко источник: «заблокировано», «другие команды · N задач» или оба), **Осталось** (перерасход — красным «−78 ч»).
- Строка, где есть работа в других командах, раскрывается списком задач других команд этой роли: задача, команда, часы, **вид работ** (выбор; по умолчанию «Технические задачи»). Выбор сохраняется для пары «команда плана + задача» и сразу пересчитывает запас.
- Расхода нет ни у одной роли — вместо таблицы строка «Заблокированных периодов и работы в других командах нет — запас не расходуется».

### 5.8 Предупреждения плана

Живые (не хранятся, считаются при чтении диаграммы), только для команды плана:
- **Перерасход запаса:** «Разработчики · Технические задачи: заложено 102 ч, другие команды заняли 180 ч» (и/или «заблокировано N ч»).
- **Квартал не вмещается:** «Пряничников: не вмещается 75 ч нормированных работ» — у людей запаса команды плана.

### 5.9 Что не меняется

- Раскладка фаз: основная команда планирует как сейчас; другие команды берут человека в пределах вовлечённости дня, как сейчас (доля по справочнику вовлечённости в дни без задач основной команды — остаётся в планировщике).
- Отметки пересечений с другими командами — как сейчас.
- «Базовые ресурсы», «На бэклог», виджет «Нормированные работы» — выпуск 3.

### 5.10 Пример для проверки

Команда ERP, два разработчика по 511 ч, правила разработчика: орг. вопросы 10, сопровождение 15, минорные 20, технические задачи 10.
- Запас «Технические задачи» = 10% × 1022 = 102,2 ч. Пряничников в «Блоке» 180 ч → перерасход 77,8 ч, остаток 0.
- Пряничников: задачи ERP 176 + другие команды 180 + нормированные 230 (51,1 + 76,65 + 102,2) ≈ 586 ч → ≈115%, не размещено ≈75 ч.
- Шутов: «Технических задач» 0, нормированные ≈230 ч.

## 6. Реализация (для исполнителей)

### 6.1 Данные (одна миграция Alembic, batch mode)

- `scheduled_blocks.work_type_id` — `String(36)`, FK `mandatory_work_types.id`, nullable. Заполнение в Python (SQLite `lower()` не знает кириллицу): `reason.strip().lower() == 'закрытие месяца'` → id вида `support_consult`; чтение и запись через `sa.table`, без vendor-SQL.
- Новая таблица `team_work_type_overrides`: `id`, `team String(200)`, `backlog_item_id` FK `backlog_items.id` ondelete CASCADE, `work_type_id` FK `mandatory_work_types.id`, timestamps; unique (`team`, `backlog_item_id`).

### 6.2 Периоды — `app/services/scheduled_blocks.py` (новый)

`resolve_blocked_days(db, employees, start, end, plan_team) -> {employee_id: {date: BlockHit}}`, `BlockHit(block_id, team, work_type_id, reason)`. Реализует 4.3 и 4.4: членство и основная команда по дням из `team_membership.membership_rows`; роль сотрудника — `Employee.role` против `roles.code` периода. Все места, где сейчас грузятся периоды и вызывается `build_availability(..., blocks)` (`compute_schedule`, `explain_assignment`, расшифровка конфликта, выравниватель), переходят на резолвер. `build_availability` принимает готовые заблокированные дни вместо списка периодов (или резолвер вызывается внутри — на усмотрение исполнителя, но одним путём).

Отпечаток плана (`cto.fingerprint` / `stale_teams`) включает заблокированные дни чужих основных команд людей плана: ключ — имя команды, в хэш добавляются ячейки (сотрудник, день, «блок»).

API `/scheduled-blocks`: `work_type_id` в создании (обязателен), изменении и ответе; в ответе — `role_labels`, `employee_names`, `work_type_label` для списка.

### 6.3 Запас — `app/services/normed_reserve.py` (новый, только чтение)

## 7. Известные ограничения

- Периоды неосновной команды на показ «Загрузки по дням» не влияют (закрывают день только в её планах, как сейчас).
- В плане неосновной команды расход запаса основной считается по опорным планам, а задачи — по открытому плану; для неопорного плана цифры могут немного расходиться.
- Остаток вида делится между людьми роли пропорционально норме, без учёта их свободного времени.
