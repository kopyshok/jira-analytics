# Видео-инструкции по кейсам — дизайн (пилот)

Дата: 2026-09-29. Ветка: `feature/help-videos` (от `feature/onboarding-first-steps`, экспериментальная).

Цель пилота: два коротких ролика — «Внести отпуск» и «Отнести задачу к категории» — снятые роботом на
обезличенной копии рабочей базы, и их показ в справке и в «Первых шагах». По итогам PM решает, снимать ли остальные
(черновой список — 12 кейсов, см. разговор 2026-09-28).

## Решения PM

- Ролики снимает робот (Playwright), а не человек; при изменении интерфейса пересъёмка одной командой.
- Данные — **обезличенная копия рабочей базы** (вариант A): реальные объёмы, вымышленные имена.
- Реальные данные без обезличивания недопустимы: сервис может передаваться другим компаниям по договору.

## 1. Обезличенная демо-база — `scripts/demo_db/`

Локальный инструмент, в приложение не входит. Вход — локальная база (копия бэкапа продакшна), выход —
`data/demo.db` (папка `data/` в `.gitignore`, база никогда не коммитится).

`py -3.10 scripts/demo_db/build_demo_db.py --source data/jira_analytics.db --out data/demo.db`:
1. Консистентная копия исходной базы (sqlite backup API, исходник открыт только на чтение).
2. Обезличивание (`anonymize.py`), по отражённой схеме — все текстовые колонки всех таблиц, включая неизвестные моделям.
3. Проверка утечек (`leak_check.py`) — при находках выход с ошибкой, база удаляется.
4. Демо-пользователь `demo@example.com` / `demo12345`, роль «руководитель», команда — демо-команда; окно «Что нового»
   и автооткрытие «Первых шагов» у него отмечены как просмотренные (не перекрывают кадр).

### Правила обезличивания
Словарь соответствий «настоящее → вымышленное», детерминированный (один и тот же исходник → одно значение во всех
таблицах и внутри JSON-строк):
- **Люди**: ФИО из сотрудников, пользователей, задач (исполнитель, автор, разработчик), снимков сценариев, утверждений
  KPI → вымышленные русские ФИО (фамилия + имя из списков). E-mail → `userN@example.com`. Идентификаторы учёток Jira →
  `acc-N`. Аватары → пусто.
- **Команды** (все места, где хранится имя команды, включая JSON-списки) → «Команда Альфа», «Команда Бета», …;
  команда с лучше всего заполненной настройкой (по умолчанию «Команда 1С (ERP - Товарный учет)») → «Команда Альфа».
  Группы внутри команд → «Группа 1», …
- **Проекты Jira**: ключ → `PRA`, `PRB`, …; ключи задач `КЛЮЧ-123` → `PRA-123` везде (задачи, связи, области загрузки,
  правила иерархии, переопределения категорий); название проекта → «Проект А», …
- **Заказчики** → «Заказчик 1», …
- **Названия задач** → правдоподобные вымышленные («Доработка отчёта по остаткам», «Настройка обмена с банком», …),
  детерминированно по задаче; названия инициатив в бэклоге и снимках сценариев — как у связанной задачи.
- **Спринты/релизы** → «Спринт N» / «Релиз N».
- **Свободный текст** (описания, цели, влияние, риски, окружение, комментарии, комментарии ворклогов, заметки и
  комментарии планирования, тексты конфликтов, замечаний стола тимлида) → пусто (или нейтральная заглушка там, где пусто
  нельзя).
- **Удаляются целиком**: кэш Confluence, обратная связь, ИИ-саммари проектов и снимки ИИ-отчётов, ИИ-классификации,
  события и статистика использования, история синхронизаций (тексты ошибок), рабочие столы (токены).
- **Настройки**: секреты (токены, пароли, ключи ИИ, учётные данные Jira/Confluence) → пусто; адрес Jira →
  `https://jira.example.com`. Пароли всех пользователей → хэш демо-пароля.
- **Не трогаются** справочники без персональных данных: категории, роли, причины отсутствий, виды нормированных
  работ, метрики KPI, статусы/типы/приоритеты, производственный календарь, заметки «Что нового».

### Проверка утечек
Список исходных чувствительных строк (все исходные ФИО и их фамилии длиной ≥ 5 символов, e-mail, имена команд и групп,
ключи и названия проектов, заказчики, домен Jira) ищется во всех текстовых колонках демо-базы без учёта регистра; плюс
шаблоны: e-mail не на `example.com`, `atlassian.net`. Любая находка — ошибка с перечнем «таблица.колонка: фрагмент».

## 2. Съёмка — `frontend/help-videos/`

- Отдельная конфигурация Playwright `frontend/playwright.videos.config.ts` (не входит в E2E и CI).
  Перед съёмкой — свежая копия `data/demo.db` → `data/demo_run.db` (каждый ролик меняет данные).
  Серверы на своих портах (8012/5176). Окно 1440×900, видео того же размера.
- Режиссёр `frontend/help-videos/director.ts` — слой поверх страницы, попадает в кадр:
  - нарисованный курсор, плавно подъезжает к элементу перед кликом;
  - подсветка элемента (рамка);
  - подпись внизу экрана (крупно, на тёмной плашке), держится не меньше ~2 с;
  - паузы между шагами, чтобы зритель успевал.
- Сценарии `frontend/help-videos/<id>.video.ts`. Пилот: `absence-add` (Ресурсы → Отсутствия → «добавить» у сотрудника →
  даты и причина → сохранить → отпуск на карте), `categorize-issue` (Категории задач → «К разбору» → выбрать категорию у
  задачи → сохранить/подтвердить → задача ушла из очереди).
- Результат: `frontend/public/help-videos/<id>.webm` + кадр-обложка `<id>.jpg`; коммитятся в репозиторий (попадают в сборку
  как статические файлы). Команда: `npm run videos` (в `frontend/package.json`).
- Перед публикацией ролики просматриваются глазами (проверка на реальные данные в кадре).

## 3. Показ

- Реестр `frontend/src/help-videos/videos.ts`: id → название, файл, обложка.
- `VideoModal`: окно почти на весь экран, видео по кругу, без звука, с кнопками управления.
- Справка: ссылка вида `[Внести отпуск](video:absence-add)` в markdown рендерится карточкой «▶ Внести отпуск» с обложкой;
  клик — `VideoModal`. Раздел «Видео» в `docs/help/capacity.md` и `docs/help/categories.md`.
- «Первые шаги»: у шага «Отсутствия» и «Категоризация задач» кнопка «Видео».
- Экскурсии: не в пилоте (добавить после решения PM).

## Проверка

- pytest для обезличивания на маленькой синтетической базе: одно исходное имя → одно вымышленное во всех таблицах и в
  JSON; ключи задач пересчитаны; свободный текст пуст; секреты пусты; проверка утечек ловит подложенную утечку.
- Сборка демо-базы из локальной базы проходит проверку утечек.
- `npm run videos` снимает оба ролика; кадры просмотрены.
- Фронт: lint, build, e2e-спека панели «Первые шаги» проходит.
