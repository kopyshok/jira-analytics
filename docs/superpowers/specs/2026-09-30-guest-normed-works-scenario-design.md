# Нормированные работы основной команды в сценарии неосновной — дизайн

Дата: 2026-09-30. Повод: ручная проверка перед v1.12, пункт T08-04. Часть «выпуска 3» из
[2026-09-28-normed-works-reserve-design.md](2026-09-28-normed-works-reserve-design.md) (§5.9):
только «На бэклог» сценария для общих сотрудников. Виджет факта «Нормированные работы» и ворклоги
на чужих задачах — не здесь.

## 1. Проблема

Пряничников Алексей: основная команда «ERP — Товарный учёт», вторая — «Блок Компетенций». IV кв. 2026, 511 ч.

| | Часы |
|---|---|
| Задачи ERP в опорном плане ERP | 148,8 |
| Нормированные работы ERP (разработчик, 55%) | 281 |
| из них «Технические задачи» (10%) | 51,1 |
| Сценарий «Блока Компетенций», «На бэклог» сейчас | **362,2** = 511 − 148,8 |

Сценарий неосновной команды вычитает только брони основной, а нормированные работы основной — нет.
Правила самой неосновной команды к нему применяются (сейчас у «Блока» их нет — 0).

## 2. Решения пользователя (30.09)

| Вопрос | Решение |
|---|---|
| Как считать | Из запаса основной команды, как в ресурсном плане: квартальный запас раскладывается по дням так же, как в «Загрузке по дням». |
| Работа в других командах | По решению 28.09 она списывается в «Технические задачи» основной команды. Значит, остаток этого вида — время, которое может взять неосновная команда; из «На бэклог» он не вычитается. |
| Нормы неосновной команды к общему сотруднику | Не применяются. У человека нормированные работы только основной команды — цифры не зависят от того, в какой команде на него смотрят. |
| Показ | Отдельной строкой под таблицей ресурса, рядом с «Занято в планах других команд», с именами в подсказке. |

Ожидаемо для Пряничникова: 511 − 148,8 − (281 − 51,1) ≈ **132 ч**.

## 3. Правило

**Гость сценария** — сотрудник, который в квартале состоит в команде сценария, но она у него не основная
(`cross_team_occupancy.guest_ids`). Для остальных сотрудников ничего не меняется.

Для гостя в сценарии команды X:

1. Правила нормированных работ сценария X и его личные проценты день **не режут** (доля дня на проекты = 1).
2. **Нормированные работы основной команды** — из её запаса (`normed_reserve.team_reserve` по основной
   команде квартала; основная менялась — `merge_person`): заблокированные дни её периодов + доля остатков
   по видам. Личные проценты сотрудника уже учтены в запасе основной.
3. Из доли остатков убирается вид работы в других командах (`CROSS_TEAM_WORK_TYPE_CODE`,
   «Технические задачи»): это время доступно неосновным командам.
4. Раскладка по дням — `normed_reserve.place_person`, как в «Загрузке по дням»: ёмкость — календарь минус
   отсутствия в дни участия в X; свои задачи — брони основной команды (и другие вычитаемые брони);
   доля дня вне задачи — по вовлечённости броней (`cto.other_work_share`); заблокированные дни — периоды
   основной команды (`scheduled_blocks.resolve_blocked_days` без команды плана).
5. Часы дня для X = max(0, норма дня − брони − нормированные работы основной в этот день).
   Не поместившееся в квартал («не размещено») часы X больше не уменьшает — их и так 0.

Брони неосновных третьих команд вычитаются, как сейчас; они же расходуют «Технические задачи» основной,
поэтому двойного вычета нет.

## 4. Где считается

- Новая функция в `app/services/normed_reserve.py`: `guest_normed_by_day(db, team, year, quarter, guests,
  capacity, bookings) -> {сотрудник: {день: часы}}` — шаги 2–4. Один вызов на сценарий; запас каждой
  основной команды считается один раз.
- `ResourceBaseService.compute` (посуточная база, «По сотрудникам») и `compute_summary` («На бэклог» по
  ролям и группам) берут результат одной и той же функции и прибавляют его к броням дня гостя; у гостя
  `_pool_share` = 1. Так база по дням и сводка не расходятся.
- Сводка: новое поле `primary_normed_by_role` (роль → часы) и список гостей с часами для подсказки.

## 5. Показ

Под таблицей ресурса сценария, рядом со строкой «Занято в планах других команд этого квартала…»:

> Нормированные работы основной команды у общих сотрудников: 230 ч. Эти часы уже вычтены из «На бэклог».

Подсказка на числе — имена и часы («Пряничников Алексей — ERP — Товарный учёт, 230 ч»). Нет гостей —
строки нет.

## 6. Что не меняется

- Сценарий основной команды — без изменений.
- Планировщик: неосновная команда по-прежнему берёт человека в пределах вовлечённости дня. Если план
  возьмёт больше, чем «На бэклог» сценария, «Загрузка по дням» покажет перерасход «Технических задач»
  (выпуск 2).
- Команда без запаса (нет правил нормированных работ) — у её гостей в чужих сценариях вычитаются только брони.

## 7. Тесты

- Гость: «На бэклог» = норма − брони основной − (нормированные основной − «Технические задачи»); цифра
  Пряничникова на копии рабочей базы ≈ 132 ч.
- Правила неосновной команды к гостю не применяются; к своим сотрудникам — применяются, как раньше.
- Заблокированный период основной команды уменьшает часы гостя в сценарии неосновной.
- Посуточная база и сводка дают одинаковый итог по гостю.
- Сценарий основной команды не меняется; команда без запаса — гость теряет только брони.
