# Фиксация вовлечённости в фазе, отказ от вовлечённости из Jira

Дата: 2026-09-30. Продолжение исправления «правка справочника доходит до фаз» (88251cb9).

## Зачем

Вовлечённость в Jira ведётся плохо, у эпиков её нет. Планируем по данным самого
сервиса: справочник команды по ролям, личная настройка сотрудника и — для
отдельных задач — процент, зафиксированный прямо в фазе ресурсного плана.

## Правило

Процент фазы, по старшинству:

1. зафиксированный в фазе;
2. личная настройка сотрудника на квартал;
3. справочник команды по роли на квартал;
4. нигде не задан — 100%.

Раньше личная настройка была главнее процента задачи — теперь фиксация главнее.
Решение пользователя: фиксация — самое точное указание.

Фиксация принадлежит задаче и её фазе (Анализ / Разработка / Тестирование / ОПЭ):
действует во всех частях фазы и во всех планах, где задача есть.

## Боковая панель фазы

Строка «Вовлечённость»: поле процента, галочка «Зафиксировано», кнопка «Сохранить».

- Галочка снята — поле только для чтения, показывает действующий процент, подпись
  источника: «из справочника команды», «личная настройка сотрудника»,
  «не задана — 100%».
- Галочку поставили — поле доступно, в нём текущий процент; «Сохранить» фиксирует
  и пересчитывает план.
- Галочку сняли на зафиксированной фазе — фиксация снимается сразу, план
  пересчитывается, фаза берёт процент по правилу выше.
- Допустимые значения — 0..100%, как сейчас.

## Jira

- Синхронизация больше не читает поля вовлечённости; четыре строки «Вовлечённость …»
  убираются из настроек полей Jira.
- Сохранённые значения вовлечённости из Jira у задач Jira удаляются из базы вместе
  с колонками.
- Длительности фаз из Jira не меняются.

## Бэклог → «Параметры планирования»

Блок «Вовлечённость» убирается. Длительности и «сколько человек параллельно»
остаются. Фиксировать процент — только в фазе.

## Переход на проде

Одна миграция (iv01 — ещё не выпущена, переписывается):

- снимает процент вовлечённости у всех задач бэклога — все фазы начинают брать
  личную настройку или справочник; нужные фиксации ставятся заново;
- удаляет колонки вовлечённости у задач Jira.

Команды без справочника после выпуска получат 100% в фазах — им завести справочник.

## Что остаётся без изменений

- Правка справочника помечает планы команды «Требуется пересчёт» (88251cb9).
- Прочие нормированные работы в днях без фаз — по личной настройке / справочнику.
- Утверждение сценария в задачи ничего не пишет.

## Технически

- `effective_for_phase`: порядок «своё значение задачи → личная → справочник».
  Источник в расчёте фазы: `task` (= зафиксировано) → `employee` → `team`.
- `PUT …/assignments/{id}/involvement`: `involvement_pct` может быть `null` — снять
  фиксацию; 1..100 — зафиксировать.
- Синхронизация: убрать чтение `jira_involvement_*_field_id` и копирование в задачу
  бэклога; модель `Issue` теряет `involvement_*`; ответ бэклога теряет
  `involvement_*_jira`; правка задачи бэклога теряет `involvement_*`.
- Фронт: `InvolvementEditor` в `AssignmentSidebar`; блок вовлечённости в
  `BacklogPlanningParamsModal`; строки в `JiraFieldsCard`; типы.
- Справка: `docs/help/resource-planning.md` (порядок источников),
  `docs/help/planning.md` (панель вовлечённости), справка по настройкам Jira.

## Проверки

- Порядок источников: фиксация бьёт личную и справочник; без фиксации — личная; без
  неё — справочник.
- Снятие фиксации через API возвращает процент справочника и пересчитывает план.
- Синхронизация с заполненным полем вовлечённости в Jira процент задачи не трогает.
- Миграция: у задач проценты сняты, колонки удалены; цепочка миграций с нуля на
  SQLite и Postgres.
- Полный прогон тестов на SQLite и Postgres, сборка фронта.
